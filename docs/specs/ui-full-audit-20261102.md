# 全界面优化规格与八类实测（2026-11-02）

权威工作项：https://github.com/DaNN-55/loop-control/issues/196 （ready-for-agent）。

## Problem Statement

Owner 已逐项接受本次界面盘点的 01–76 项优化。当前问题集中在离开与刷新造成上下文或草稿丢失、状态和文案不准确、查看态仍呈现默认配置、搜索和素材选择不便、声音默认值保存范围不一致，以及媒体查看和轮询资源开销。盘点依据包含现场观察与源码推断；接受改进方向不等于所有推断均已通过真实场景复现。

## Solution

先冻结本规格及原编号映射，再复用既有隔离正式页面、Owner HTTP、真实 PostgreSQL、持久 Worker、真实 OpenChatCut SDK 和实际文件边界完成 T01–T08。测试期间只增加规格、计划、验证脚本和证据，不实施本规格的产品修改。实测结果区分产品缺陷、验证脚本漂移、无法复现和覆盖限制；新增项使用 N01 起的新编号补入同一规格，再统一实施已确认范围。

21 的补充要求：把「已应用」状态放在通用规则标题同行行尾，系列规则同理，状态信息包含当前版本。
41 的补充要求：批量文件处理中可增加占位加载动画，保持真实内容布局，保留逐文件结果和减少动态效果偏好。
44 的原修复方向由音效入口调整讨论替代：推荐实际选音效放在剪辑台，前置只记录可选「音效意图」，不自动选服务或发起检索／生成。T02 已发现内置音效会阻塞主应用保存；先打通保存、重开和交付，再考虑移除前置音效生成／检索及默认连接配置。第一版意图采用每镜头可选短文本，不强制扩充脚本。入口删减和新增内容仍待 Owner 确认；不删除音乐、原片声音、历史音效及其采用、混音、导出能力。

## Implementation Decisions

- 保留现有蓝灰视觉、四步制作、Owner 权限、候选明确采用、已完成／归档只读以及原生工程拥有实际时间线的职责。
- 导航、离开保护与非敏感操作草稿通过已有应用导航和表单边界统一；秘密输入不进入持久草稿。
- 创作基线、物理收纳、版本化连接、制作选择和执行快照继续采用既有领域含义。命名变化不改写历史对象或搬迁文件。
- 规则应用状态与版本置于通用规则／系列标题行尾；与内容分区和编辑动作协同，不新增重复状态卡片。
- 使用已注册能力约束和服务端真实校验信息；不为前端便利复制第二套执行权限或费用权威。
- 候选预览可以自动选中唯一项，采用、生成与保存仍保持明确动作；生成确认、未知提交阻断和原任务恢复不被省略。
- 声音意图是创作描述，声音素材、采用和时间线配置由现有制作与原生工程边界拥有。内置音效库的下载、许可、离线可用性、镜头定位和保存重开需先确认。
- 列表、媒体预览、空状态、错误和加载以真实读写结果表达。占位只在真实等待时出现，不伪装进度或业务成功。
- 测试先在独立源码快照与空基线数据库进行；日常运行只读，不重启日常服务、不修改其生产单、配置、目录、凭据或既有工程。
- 当前阶段没有确认数据库迁移或新增生产依赖；如实现必须扩展持久契约，先用最小前向变更明确兼容与恢复语义。
- T01–T08 完成前禁止开始 U01–U76 的产品实现。用户对 U44 的疑问及实测后新增范围需要清楚保留决策状态，不能当成已经批准的删除。

## Testing Decisions

主要验收边界采用现有正式页面 → Owner HTTP → 隔离 PostgreSQL／持久 Worker → 真实原生工程与实际媒体文件。供应商传输与秘密存储使用合成受控替代；不触碰真实 Keychain、不调用付费 Provider。以可见行为、HTTP 结果、任务数量、工程持久结果和文件身份互相印证，不用 mock 替代本次关键原生／数据库边界。

沿用现有故事 E2E、真实浏览器夹具、进程故障／重启夹具、原生文档保存重开和工作区调用确认等先例。尽量在这一条最高层边界集中覆盖；仅为难以从页面准确观察的文件或权限结果增加现有 HTTP／数据库证据。
