# 当前制作链全面替换实施规范

状态：用户于 2026-11-13 批准实施。完整依据：[全面替换建议](../plans/production-workflow-replacement-20261113.md)。本规范将原方案转为验收清单，不缩小范围。

## 目标与边界

当前业务、当前 SQL 接口和界面采用一致的制作概念；真正无用入口退役；旧工程通过当前程序接入，原始历史、冻结输入、草稿、音轨、审批和文件可恢复。保留现有 PostgreSQL／Owner 事务／原生工程／Worker 体系，分批局部重构，不整体重写或引入第二套数据系统。

不提交、不推送，不调用视频 API、不发起真实付费生成；日常重启、部署和采集启用仍按原方案单独授权。实现可在隔离环境完整验证和演练，不以擅自修改日常环境作为实施手段。保留本轮起点所有无关改动。

## 共通保护

Owner、跨账号／跨生产单、RLS／ACL、attempt／lease、冻结输入、文件指纹、确切导出、明确费用确认、结果未知和历史恢复保护必须保持。统计新增事件不得包含正文、路径或秘密；默认关闭、不补造历史、不将预留或应用上报金额当真实付款；统计失败不能授权重复外发。

已由 185 清理的旧生成脚本链不重复实现；已有旧建单核查用于定位和设计，实施后的新代码仍需重新验证。旧包原样执行与彻底删除其签名不能同时成立，按原方案落实版本支持门槛和当前恢复器；原历史包不改写。
