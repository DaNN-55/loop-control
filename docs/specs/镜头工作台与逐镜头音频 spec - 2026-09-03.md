# 镜头工作台与逐镜头音频 Spec

## Problem Statement

1. 自动 TTS 已按 storyboard shot 创建任务，但生成入口和配置仍隐藏在全局蓝图及后台编排中。
2. 上传阶段要求 Owner 预先选择整期使用 TTS 或保留原声，粒度过粗，也早于实际镜头判断。
3. 镜头准备页面主要预览原片；真实裁剪发生得太晚，Owner 审核的并不是 Studio 最终收到的片段。
4. 音轨预览与对应镜头分离，无法直接判断口播和画面的适配度。
5. 已有 shot 只能更换素材，缺少“补充原片”和“新增或拆分镜头”的明确路径。
6. 分镜审核、镜头冻结、预渲染成员审核之间存在重复信息和重复确认。
7. 当前页面一次展开所有 shot，纵向信息过长，关键状态和下一步不突出。

## Solution

Owner 应能按镜头完成画面和声音准备：选择或补充原片，生成并预览裁剪片段，决定该镜头使用 TTS、原声或无口播，按需修改口播内容、声音和语速，手动生成或重新生成音频，并在同步预览后确认镜头。

Studio 只接收已经确认的镜头视频、音频和字幕文本，负责组合、字幕样式、转场、音量与整体节奏，不再承担原始素材挑选、基础裁剪或口播生产。

分镜审核负责结构决策，镜头工作台负责逐镜头媒体准备，Studio 负责后期合成，整体成片审核负责最终质量检查。现有状态机继续复用，但删除重复的人工冻结审核体验。

## User Stories

1. As an Owner, I want 上传阶段只负责导入和标注素材, so that 我不需要在看到具体镜头前决定整期声音策略。
2. As an Owner, I want 在分镜审核中只确认镜头结构、顺序、类型、基准口播和目标时长, so that 结构决策不会与媒体制作混在一起。
3. As an Owner, I want 分镜批准后进入统一的镜头工作台, so that 我可以在同一处完成每个镜头的画面、声音、字幕和确认。
4. As an Owner, I want 默认只展开当前待处理镜头, so that 页面不会被全部镜头的长表单淹没。
5. As an Owner, I want 在折叠卡片上看到镜头类型、时长、画面、音频和确认状态, so that 我能快速判断下一步。
6. As an Owner, I want 确认当前镜头后自动打开下一个未确认镜头, so that 连续处理时不需要反复寻找位置。
7. As an Owner, I want 可以跳过缺少素材的镜头继续处理后续镜头, so that 单个阻塞不会中断整期准备工作。
8. As an Owner, I want 每个镜头的主播放器只显示真实裁剪产物, so that 我审核的就是 Studio 将收到的画面。
9. As an Owner, I want 在镜头内查看源素材并设置入点和出点, so that 我可以优化当前片段而不离开工作台。
10. As an Owner, I want 修改裁剪参数后手动触发生成, so that 未完成的参数编辑不会产生无效后台任务。
11. As an Owner, I want 新裁剪失败时继续保留上一版可用片段, so that 返工不会破坏已经可用的结果。
12. As an Owner, I want 在当前镜头内更换或补充原片, so that 找不到合适长度时仍有明确的补充路径。
13. As an Owner, I want 为每个镜头独立选择 TTS、保留原声或无口播, so that 声音策略能匹配具体画面。
14. As an Owner, I want TTS 默认继承已批准口播和蓝图声音设置, so that 常规镜头不需要重复配置。
15. As an Owner, I want 在生成前修改口播内容、声音和语速, so that 我可以先优化表达再产生费用。
16. As an Owner, I want 只有点击“生成此镜头口播”才调用 TTS, so that 草稿编辑不会自动触发外部服务。
17. As an Owner, I want 逐镜头试听已生成口播, so that 我能独立判断每段声音是否合适。
18. As an Owner, I want 修改配置后手动重新生成口播, so that 我能迭代单个镜头而不重做整条视频。
19. As an Owner, I want 新口播生成失败时保留上一版音频, so that 调整失败不会丢失可用版本。
20. As an Owner, I want 原声模式使用与准备视频相同裁剪范围的音轨, so that 画面和声音天然对齐。
21. As an Owner, I want 无口播模式明确记录静音决定, so that Studio 不会误以为音频缺失。
22. As an Owner, I want TTS 字幕逐字采用最终口播内容, so that 配音与字幕不会出现文案分叉。
23. As an Owner, I want 原声或无口播镜头可以编辑或关闭字幕, so that 非 TTS 镜头仍有合适的文字表达。
24. As an Owner, I want 同步预览当前裁剪视频和当前采用音轨, so that 我能在进入 Studio 前判断适配度。
25. As an Owner, I want 看到音频实际时长、镜头目标时长和差值建议, so that 我能决定调整语速、文案或裁剪。
26. As an Owner, I want 对轻微时长差异作出明确接受, so that 警告能被审计但不会永久阻塞制作。
27. As an Owner, I want 每个镜头独立确认, so that 完成进度和待处理问题清晰可见。
28. As an Owner, I want 修改已确认镜头时只撤销该镜头的确认, so that 其他已完成镜头不会被无谓重置。
29. As an Owner, I want 在镜头后新增镜头或返回结构调整, so that 素材不足时可以正式修改分镜结构。
30. As an Owner, I want 新增、删除、拆分、合并、重排或修改目标时长时创建新分镜修订, so that 结构变化有清晰的审核边界。
31. As an Owner, I want 新分镜修订复用输入指纹未变化的镜头产物, so that 局部结构调整不需要整期重做。
32. As an Owner, I want 在后台任务运行时持续看到过渡反馈和当前状态, so that 我能确认 Worker 仍在工作。
33. As an Owner, I want 单个镜头失败时看到失败步骤和安全重试入口, so that 我可以局部恢复而不是重启整期生产。
34. As an Owner, I want 只有所有必需镜头确认后才能进入 Studio, so that Studio 不会收到未完成输入。
35. As an Owner, I want Studio 默认工程只引用已确认的准备视频、音频和字幕, so that 后期合成使用的都是审核过的版本。
36. As an Owner, I want Studio 只负责组合、字幕样式、转场、音量和整体节奏, so that 基础裁剪与口播返工始终回到对应镜头。
37. As an Owner, I want 整体成片审核聚焦最终画面、声音、字幕、安全区和技术质量, so that 末端审核不再重复逐镜头制作。
38. As an Owner, I want 旧 Episode 继续可读取和完成, so that 新流程不会破坏正在进行或已经冻结的生产单。

## Implementation Decisions

### 调整后的流程

```text
分镜审核
确认镜头结构、顺序、口播基准文案和目标时长
        ↓
镜头工作台
逐镜头完成裁剪、音频模式、TTS/原声、字幕文本、同步预览和确认
        ↓
Studio
使用已确认镜头完成组合、字幕样式、转场、音量与整体节奏
        ↓
整体成片审核
检查最终画面、声音、字幕、安全区和技术 QC
```

数据库状态机可以继续复用现有阶段，但用户可见职责调整为：

| 现有阶段 | 用户可见职责 |
| --- | --- |
| `storyboard_review` | 分镜审核，只处理结构、顺序、基准文案、镜头类型和目标时长 |
| `storyboard_approved` | 镜头工作台，产出并确认逐镜头视频、音频和字幕输入 |
| `production_ready` | 后台创建不可变的预渲染快照，不再提供一套重复的逐项人工审核页面 |
| `render_ready` | Studio 待合成；根据已确认镜头建立默认工程，等待 Owner 提交合成版本 |
| `qc_review` | 整体成片审核，不再返回这里处理基础裁剪或 TTS 内容 |

### 阶段职责

#### 分镜审核

分镜审核只决定：

- shot 的数量、顺序和类型；
- 每个 shot 的基准口播文案；
- 每个 shot 的目标时长；
- 画面意图、制作要求和目标规格；
- 哪些镜头预期使用 TTS、原声或无口播。

该阶段不选择具体原片，不生成 TTS，不填写裁剪入点或出点，也不审核最终媒体文件。

#### 镜头工作台

镜头工作台是 Studio 前唯一的媒体准备和逐镜头确认界面。每个 shot 必须得到以下结果：

- 一段已经实际生成且可播放的准备视频；
- 一个明确的音频模式；
- TTS 模式下一个已经生成且可试听的旁白版本；
- 原声模式下一个与准备视频裁剪范围一致的原声音轨；
- 无口播模式下明确的静音决定；
- 一份将交给 Studio 的字幕文本和显示开关；
- Owner 对当前视频、音频和字幕组合的确认。

原片仍可在“源素材”区域查看，但不能作为镜头的主预览或确认对象。

#### Studio

Studio 只允许修改：

- 镜头组合和轨道位置；
- 字幕样式、安全区和动画；
- 转场；
- 音量、淡入淡出和混音；
- 不改变镜头结构的整体节奏微调。

Studio 不负责：

- 从原片中寻找内容；
- 生成基础裁剪片段；
- 修改 TTS 文案、声音或语速；
- 生成或重新生成 TTS；
- 新增、删除或拆分 storyboard shot。

若 Studio 中发现上述问题，应返回对应 shot 的镜头工作台；若涉及镜头数量、顺序或目标时长，则进入新的分镜修订。

### 镜头工作台布局

#### 页面总览

页面顶部显示紧凑进度条，而不是展开全部材料清单：

- 已确认镜头数，例如 `3 / 9`；
- 正在生成数；
- 待补素材数；
- 待处理的当前镜头；
- “进入 Studio”按钮，仅在全部必需镜头确认后启用。

所有 shot 以折叠卡片排列，默认只展开当前待处理镜头。确认当前镜头后自动展开下一个未确认镜头；Owner 可以跳过并处理后面的镜头。

折叠状态只显示：

- shot ID、类型和目标时长；
- 画面状态；
- 音频模式及音频状态；
- 当前确认状态；
- 需要处理的一个主要问题。

#### 展开的 shot 卡片

展开后使用以下布局：

```text
┌──────────────────────────────────────────────┐
│ shot-002 · A-roll · 4.4 秒       待确认      │
│ 基准文案摘要                                 │
├──────────────────────┬───────────────────────┤
│ 最终镜头预览         │ 口播与字幕             │
│ 已裁剪视频播放器     │ 音频模式               │
│ 当前片段范围与时长   │ 口播内容               │
│                      │ 声音 / 语速            │
│ [优化裁剪]           │ [生成/重新生成口播]    │
│ [更换/补充原片]      │ 口播播放器与时长反馈   │
├──────────────────────┴───────────────────────┤
│ [画面＋声音同步预览] [确认此镜头]             │
│ [在此镜头后新增] [返回分镜结构调整]           │
└──────────────────────────────────────────────┘
```

窄宽度下左右区域改为上下排列，不横向压缩播放器和表单。

#### 画面区域

画面区域包含：

- 准备视频播放器，始终播放实际裁剪产物；
- 当前原片名称；
- 入点、出点、实际片段时长和目标时长；
- 时长差异提示；
- “生成片段”或“重新生成片段”按钮；
- “更换原片”按钮；
- “补充原片”按钮，在当前 shot 内完成上传并自动标记用途；
- 折叠的“查看源素材”区域，用于辅助重新选择入点和出点。

保存入点和出点本身不代表片段已经完成。Owner 显式点击生成后，Worker 才执行裁剪；裁剪成功并产生带哈希的产物后，播放器才切换到新片段。生成失败时继续保留上一版可用片段。

### 逐镜头音频

#### 删除上传阶段的整期声音选择

上传阶段删除“TTS 替代原声 / 保留上传视频原声”设置。上传只负责导入和标注材料用途，不提前决定整期声音策略。

新 Episode 的声音策略由每个 shot 独立决定。旧 Episode 已冻结的 `audio_source_mode` 继续用于兼容历史任务，但不在新界面显示，也不改写历史结果。

#### 每个 shot 的音频模式

每个 shot 必须选择一种模式：

| 模式 | 行为 |
| --- | --- |
| TTS 口播 | 使用该 shot 的最终口播内容、声音和语速生成独立音频 |
| 保留原声 | 从该 shot 的准备视频对应时间范围生成独立原声音轨，不创建 TTS 任务 |
| 无口播 | 不创建旁白或原声音轨；背景音乐和音效仍可在 Studio 使用 |

分镜可以提供建议模式，但 Owner 在镜头工作台中拥有最终决定权。

#### TTS 编辑与手动生成

TTS 模式显示：

- 口播内容，默认取已批准分镜的基准文案；
- 声音，默认继承 Episode 冻结蓝图，例如“咆哮小哥”；
- 语速，默认继承 Episode 冻结蓝图，例如 `1.35`；
- “恢复分镜文案”和“恢复蓝图声音设置”；
- “生成此镜头口播”按钮；
- 已生成后显示“重新生成口播”按钮。

任何文案、声音或语速修改只形成待生成草稿，不自动调用外部 TTS。只有 Owner 点击生成按钮才创建新的该 shot TTS 任务。

重新生成时：

- 上一版成功音频继续作为当前可试听版本；
- 新任务成功后才切换当前版本；
- 失败只在该 shot 显示原因和重试入口；
- 旧任务、音频和配置快照继续保留审计，但不占据主界面。

#### 字幕规则

- TTS 口播：字幕默认开启，逐字使用最终口播内容；修改口播后必须重新生成 TTS，字幕同步使用新内容。
- 保留原声：字幕默认使用已批准分镜文案，Owner 可以编辑或关闭。
- 无口播：字幕默认使用已批准分镜文案，Owner 可以编辑或关闭。
- Studio 可以修改字幕样式和动画，但不修改字幕正文。

#### 适配反馈

TTS 成功后显示：

- 音频实际时长；
- 视频片段目标时长；
- 两者相差的秒数；
- 建议操作，例如调整语速、缩短文案、重新裁剪或拆分镜头。

Owner 可以点击“画面＋声音同步预览”，以静音方式播放准备视频，同时从零点播放当前口播或原声音轨。该预览使用 Studio 将收到的当前版本，不使用原片或待生成草稿。

时长不一致时允许继续编辑；确认镜头前必须明确处理警告。系统不因轻微时长差异永久阻塞 Owner，但需要二次确认“仍按当前版本确认”。

### 镜头操作与结构修订

#### 补充原片

“补充原片”只向当前 Episode 导入一份新的原始材料，并自动带入当前 shot 所需的 A-roll 或 B-roll 用途。它不改变分镜结构、目标时长或 shot ID。

上传完成后，新材料立即出现在当前 shot 的原片选择列表中，但仍需设置裁剪范围并手动生成准备片段。

#### 新增、拆分或删除镜头

每个 shot 提供“在此镜头后新增”和“返回分镜结构调整”入口。

以下操作属于分镜结构变化：

- 新增 shot；
- 删除 shot；
- 拆分一个 shot；
- 合并多个 shot；
- 改变顺序；
- 改变目标时长；
- 改变 A-roll / B-roll 类型。

结构变化必须创建新的 storyboard 修订并重新进入分镜审核，不能在 Studio 中直接生效。系统为新增镜头生成稳定 ID；未变化且输入指纹一致的 shot 可以沿用已准备的画面和音频，受影响的 shot 回到待准备状态。

### 镜头确认与顺序引导

每个 shot 独立经过以下用户可见状态：

```text
待准备
→ 画面生成中 / 音频生成中
→ 可预览
→ 待确认
→ 已确认
```

状态可以并行：Owner 可以跳过缺素材的 shot，先处理其他镜头。确认一个镜头后，页面自动展开下一个未确认镜头，但不强制锁定后续镜头。

确认要求：

- 准备视频存在且哈希校验通过；
- 音频模式已选择；
- TTS 模式存在成功的当前音频版本；
- 原声模式存在与准备片段对应的当前音轨；
- 字幕正文和开关已确定；
- 未处理的时长差异警告为零，或 Owner 已明确接受当前差异。

修改已确认镜头的原片、裁剪范围、音频模式、口播内容、声音、语速或字幕正文时，只将该 shot 退回待确认；其他 shot 的产物不删除。全部镜头再次确认前，不能进入 Studio。

### 后台任务与产物边界

实现优先复用现有 `tasks`、`artifacts`、`audio_tracks`、审核包和审计事件，不为同一事实建立第二套媒体系统。

需要支持的逐镜头任务结果：

- 准备视频：由原片、入点和出点生成的不可变视频产物；
- TTS 音频：由最终口播内容、声音和语速生成的不可变音频产物；
- 原声音轨：从准备片段对应范围提取的不可变音频产物；
- 镜头选择：指向当前采用的视频、音频和字幕修订；
- Owner 确认：记录当前采用版本、时长警告处理结果、理由和时间。

外部 TTS、视频裁剪和原声提取都必须由显式按钮或合法的后续状态动作触发。重复点击需具备幂等保护；新的成功修订替代当前采用版本时，不删除历史任务和产物。

预渲染快照只引用已确认镜头的当前产物。Studio 工程不得直接引用原片、待生成草稿、失败任务产物或未确认修订。

### 失败与返工

- 单个 shot 生成失败不能把其他 shot 标为失败。
- 失败卡片显示失败步骤、可否安全重试和重试按钮。
- 重新裁剪不自动重新生成 TTS；重新生成 TTS 不自动重新裁剪视频。
- 切换到保留原声或无口播时，不再要求该 shot 的 TTS 任务完成。
- 从保留原声切回 TTS 时，已有原声音轨保留历史，但不再作为当前选择。
- Studio 或整体成片审核发现基础素材问题时，返回对应 shot 的镜头工作台。
- 只有结构、顺序、类型或目标时长变化才返回分镜审核。

### 验收标准

1. 新 Episode 的上传阶段不显示整期 TTS / 原声选择。
2. 每个 shot 均显示独立音频模式，且可以分别选择 TTS、原声或无口播。
3. TTS 模式可以逐镜头编辑文案、声音和语速，并且只有点击生成按钮才创建任务。
4. TTS 成功后可以试听，修改配置后可以手动重新生成，重新生成失败不丢失上一版音频。
5. 每个 shot 的主视频播放器只显示已经实际裁剪的准备视频。
6. 裁剪参数改变后，旧片段继续可见，直到新片段生成成功。
7. 同步预览播放当前准备视频和当前采用音轨，并显示两者时长差异。
8. 字幕正文遵守本规格的三种音频模式规则。
9. 确认当前 shot 后自动展开下一个未确认 shot，同时允许 Owner 跳过处理顺序。
10. 修改已确认 shot 时，只撤销该 shot 的确认，不删除其他镜头的工作。
11. “补充原片”可以在当前 shot 内上传并选择素材，无需返回顶部材料区。
12. “新增、删除、拆分、合并、重排或修改目标时长”创建新的 storyboard 修订。
13. 未变化且输入指纹一致的 shot 可以沿用已经确认的准备产物。
14. 全部必需 shot 未确认时不能进入 Studio。
15. Studio 首次打开时只引用已确认的准备视频、当前音频和字幕正文。
16. `production_ready` 不再展示与镜头工作台重复的逐成员人工审核页面。
17. 单个生成任务运行时显示持续反馈，成功、失败和可重试状态可见。
18. 旧 Episode 仍能读取和完成，不因移除新界面的整期声音选择而失效。

## Testing Decisions

已确认以下三个最高价值自动化测试接缝，实施时优先复用仓库现有测试模式，不为本功能另建测试框架：

1. Episode 详情组件测试：覆盖上传阶段整期声音设置删除、镜头工作台折叠与展开、逐镜头裁剪和音频控制、手动生成、旧版本保留、同步预览、顺序引导、跳过，以及全部确认前的 Studio 门禁。
2. Supabase RPC 与状态迁移测试：覆盖 Owner 权限、Episode 阶段、shot 归属、逐镜头修订和确认、幂等、当前修订切换、结构修订后的产物复用，以及旧 Episode 兼容。
3. Worker 契约测试：使用代表性视频验证真实裁剪的入点、时长、音视频流和哈希，验证逐镜头 TTS、对应区间原声、失败时保留上一版，以及 Studio 快照只接收当前已确认输入。

必须再完成一条真实端到端验收路径：在同一个 Episode 中准备并确认一个 TTS 镜头、一个保留原声镜头和一个无口播镜头，然后打开 Studio，确认默认工程仅引用这三个镜头当前已确认的准备视频、音频模式和字幕正文，不引用原片、草稿、失败任务产物或未确认修订。

真实验收还应使用豆包语音连接验证逐镜头声音和语速已传入 Provider，并以任务实际返回的音频时长产生适配反馈；再执行一次新增或拆分镜头，确认未变化镜头能够沿用，受影响镜头回到待准备。

自动化断言聚焦用户可见行为、持久化状态和 Worker 输入输出契约，不绑定 CSS 选择器、内部辅助函数名称或具体组件拆分方式。

## Out of Scope

- 自动替 Owner 选择最佳画面内容。
- 自动改写口播文案或未经确认自动调整语速。
- 自动调用付费 TTS。
- 在 Studio 内实现新的非线性剪辑器。
- 删除历史任务、失败产物或旧音频修订。
- 改变 Owner 的审批权限边界。
- 在本规格中实现自动发布。
