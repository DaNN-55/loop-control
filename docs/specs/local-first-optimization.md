## Problem Statement

Owner 准备正式使用多账号内容生产平台，希望生产单操作及时、任务可靠推进、运行结构简洁，并能够将业务数据和调度留在本机。当前远端数据访问、较长的兜底派发间隔、反复启动与编译、多入口执行和重复读取/渲染共同增加等待；备份范围和过期任务回收路径还存在需要复现与修复的问题。

Owner 需要持续使用当前版本，因此全部优化必须发生在独立工作树与独立运行环境。仅隔离 Git 文件不足以保护共享数据库、端口、秘密、媒体及系统资源。完成优化后，也必须由 Owner 决定合并和生产切换。

现有历史计时只提供分析线索，不能推导整单加速比例或承诺可同时生产多少条视频。

## Solution

当前按“隔离及基线 → 恢复能力 → 调度与提速 → 数据本地化”实施A–D。E（页面和流程精简）及F（总体发布验收与切换）搁置，A–D全部完成后再讨论。每张票保留必要的阶段验证。

推荐以本地 PostgreSQL、本地应用服务、统一常驻调度器和本地秘密存储承接业务，保留现有 Episode 快照、连接版本、审核、任务和发布包语义。对用户而言，任务提交后及时排队与领取，异常有明确处理动作，页面只加载所需数据，能够在断网时管理本地业务数据。

在线模型、图片、TTS 和素材服务继续按所选执行路径使用；全部替换为离线生成属于独立可选范围。A–D推荐技术方向与测试边界已认可，具体架构契约在A阶段记录；功能精简尚未批准。

## Implementation Decisions

以下 A–D 范围和测试边界已获认可，已按票单完成主体实现及上述受限验收。调度及迁移契约以 Accepted 的 [ADR-0008](../adr/0008-local-execution-and-migration-contract.md)为准；本轮仅接续 TTS 限制修复、状态同步和隔离全链路验证，不部署到生产或迁移生产数据。E/F 相关条目继续作为搁置记录；重大边界变更仍先记录架构决定。

1. 保留生产版本，全部修改和验证位于优化工作树；运行配置、数据库、资产、端口、秘密与状态目录也必须隔离。检查生产已有改动并保留，不自动清理。
2. 沿用单一 Owner、多内容账号的领域模型，不扩大为多人协作或公网 SaaS。
3. 推荐本地 PostgreSQL 承接已有事务、约束及可复用函数；初期保留领域语义，不同步重写全部业务逻辑。SQLite 和完整自托管 Supabase 作为比较选项，不并行构建多套数据方案。
4. 历史 SQL 中的 Auth、角色、Vault 等平台依赖需要显式适配。独立测试数据库不等于直接对纯 PostgreSQL 运行全部旧迁移。迁移路径先在空库与导入库验证，历史迁移不改写。
5. 备份覆盖完整业务实体、版本、审核、任务及引用；明确一致性边界、秘密恢复和媒体范围。健康检查只报告状态，备份为独立操作，不把 best-effort JSON 等同于完整备份。
6. 任务领取先处理过期租约，再原子核算容量与领取。活跃心跳保持租约；重试保留尝试记录；结果回写验证任务与尝试身份，拒绝旧结果覆盖。
7. 所有即时与定时入口统一进入持久队列，常驻调度器持续消费；执行过程不占据唤醒请求。Worker 消费冻结任务输入，完成后再驱动满足依赖的下一步。
8. 同时管理全机执行槽位和 Provider/Adapter/连接资源组上限；保持有效容量取保守最小值的原则。公平轮转不同 Episode；网络失败退避；满载时明确排队。
9. 编译放在部署/启动准备或代码变更阶段；调度热路径只运行已准备产物。用户动作即时唤醒，五秒扫描用于兜底并防重入。
10. 五秒领取目标适用于调度器健康、前置满足、数据库可用且槽位空闲的任务；以原子领取成功计时，模型执行与满载排队另计。五秒扫描不能自动当作五秒响应的证据。
11. 统一业务查询与命令通过本地应用服务；前端不继续保留绕过该边界的第二条业务写入路径。内部模块不为测试新增重复 API。
12. 聚合生产单所需读取，按页面加载并使用服务端分页；优先更新变化的任务和状态；状态推送或轮询的具体机制在接口方案中确定，不能先引入多套机制。
13. 审核视频与最终交付复用基于冻结工程、素材、音轨、字幕、导出设置及输出完整性的指纹。来源或参数变化、产物丢失/损坏均重新生成；保留审核证据与发布包校验。
14. 本地身份替代远端 Auth，应用服务继续验证 Owner 与账号权限；仅监听本机不等于取消身份、请求来源与文件边界校验。
15. 推荐 macOS Keychain 保存外部连接秘密；业务库保留连接版本及不透明引用。明确数据库备份与 Keychain/重新录入的恢复关系，轮换与撤销不得静默替换既有 Episode 的连接。
16. 常驻调度器接管提醒、健康与备份后，移除新版本 n8n 运行依赖；本地业务访问接管完成后移除 Supabase 运行依赖。旧生产服务继续保留至明确切换。
17. 通知按新事件和消费位置去重；健康、备份与提醒分别显示结果；每日任务显式使用上海时区。过渡期 n8n 改造可与替代实现合并，避免无用的中间建设。
18. 页面方向为生产工作台、系列筛选、待审核和异常视图；技术详情保留在按需区域，字段标签、错误、关键状态与无障碍信息保留。
19. 审核关卡增删和 Adapter 移除先提供引用及影响清单。只执行 Owner 明确认可的条目；旧快照、旧产物和连接历史保持可解释。
20. 外部发布、指标采集及复盘学习已不属于当前主流程，不重建这些已删除功能；平台终点仍为发布包校验后的生产完成。
21. 实施按下表分阶段推进；顺序体现依赖，不承诺未经基线支撑的工期或加速比例。

测试边界已获Owner认可；A–D各票执行必要检查，F搁置不代表跳过这些检查：

1. 主要验收入口沿用本机控制面 HTTP 边界，并在本地化后贯穿本地应用服务。以 Owner 操作、可查询状态和产物为断言，不以调用内部函数次数或源码文本为主要结论。
2. 延用当前控制面依赖注入、派发、目录与连接路由测试先例；扩大高层行为覆盖，不为每个内部模块增加公开测试入口。
3. 数据库锁、竞争领取、全机/资源容量、租约、连接归属和旧尝试结果隔离必须在独立真实数据库验证。沿用已有 Worker 运行约束、连接权限与任务契约的 SQL 测试方式；模拟成功不能证明并发安全。
4. 先按现有链路复现“仅有过期运行任务”和“过期任务占满同组容量”，再修复并重跑；补验活跃续租、重复唤醒、进程重启与结果迟到。未复现的表现明确标注证据缺口。
5. 调度器行为测试沿用现有并发、存量任务和空闲场景，增加持续消费、公平性、退避和重启语义。模拟执行器用于快速覆盖队列，不据此宣称真实生成效率。
6. 启停与目录隔离沿用现有生命周期验收，检查新环境启停不会操作生产服务；无优化环境配置时拒绝误连生产数据库或媒体。
7. 备份在空白数据库实际恢复，核对实体数量、引用、快照、审批与任务记录；验证秘密恢复说明及选定媒体样本的内容指纹，单纯生成备份文件不算通过。
8. 真实媒体边界沿用 OpenChatCut 渲染与集成测试，检查尺寸、时长、音频、文件完整性及发布包。相同输入复用，关键输入变化与损坏产物不复用。
9. 本地化验收覆盖 Owner 会话、账号越界访问、连接轮换/撤销、秘密不回显、冻结快照及 Worker回写；断网验证本地数据操作，把在线生成阻塞单独报告。
10. UI 变更实际打开验证常用流程、空输入、重复提交、刷新和必要的窄屏布局；数据隔离和执行状态不能仅依赖截图判断。
11. 使用固定代表样本记录页面请求数、载荷、p50/p95、排队/执行/总耗时及CPU、内存、磁盘和空闲开销；样本不足时提供原始计时并注明限制。
12. 五秒指标同时给出满足条件的样本、满载排队样本和异常样本。真实压力验证之后才能确定稳定生产单并发容量，不预先把批次默认容量视为整机吞吐。
13. 每阶段执行与改动相称的类型检查、单元/集成测试及真实验证；记录实际执行与未执行项。通过后仅因新改动、新失败或未解疑点追加检查。

## Out of Scope

- 本轮 TTS 限制修复、规格/票单同步与隔离视频全流程验证之外的功能扩展；4 家豁免 Provider 的修复、凭据变更及新增请求。
- 在生产目录直接优化、停止原服务、写入生产数据库或覆盖生产媒体。
- 未经最终授权合并、推送、部署、切换或清理旧生产版本。
- 本轮默认实现完全离线的模型、TTS、图片与在线素材替代。
- 迁移为多人协作或公网服务，以及新增Provider或自动故障转移。
- E阶段页面合并、审核关卡及Adapter删减，以及F阶段总体发布验收与切换；待A–D完成后再讨论。
- 自动删除历史迁移或必要审计数据。
- 未经同条件真实对照就承诺整体提速比例、工期或并发生产条数。
