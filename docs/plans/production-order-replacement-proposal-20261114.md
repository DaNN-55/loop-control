# 当前生产单与旧流程全面替换方案

日期：2026-11-14。状态：Proposed，仅供评估。本轮不实施清理或业务修改，不提交、不推送。依据本轮开始时的固定源码；测试期间主工作区另有并行 UI／组件库与依赖变动，最终整合态仍需复验。对应本轮隔离测试报告，不替代 `PLAN.md` 中其他实施任务的进度，也不宣布 ADR-0066 已完成。

## 结论与取舍

建议保留已经能够完成新单的制作基准、原生工程、候选采用、Worker、导出及交付内核，按边界逐步替换旧内容。无需重写整个项目，也不需要换数据库、编辑器或再建一套工作流框架。值得局部重写的是新旧来源决策及任务领取中交织的职责；单纯名称问题直接改名并同步调用者即可。

新生产单走通，只能证明这张新单可以独立制作，不能证明所有旧作品和旧调用者都能立即撤下。最终目标是：当前制作只使用当前模型；旧格式只在明确的历史读取、接入和恢复边界出现；已经退出消费的旧执行入口真正删除；历史原件继续可核验。

## 先处理会影响结果的问题

| 项目 | 大白话说明与当前依据 | 建议怎样改 | 不改的影响与投入 |
| --- | --- | --- | --- |
| 正式导出的编辑辅助背景 | 本轮实际成片抽帧确认 contain 留白带棋盘格；SDK 的非透明根背景直接使用该网格，不能仅看导出和 SHA 成功 | 在渲染边界明确区分编辑预览辅助背景与正式输出底色、透明策略；验证 contain 留白、旋转和分屏空位。保留当前裁切与构图 | 留白可能把编辑网格带入正式成片。属于 SDK 局部修复，独立于 SQL 退役，不需重写编辑器 |
| 历史接入的完整性 | 保存计划、未确认草稿、混合确认、HTML／JSON 和已保存原生工程不是同一种来源。当前已增加明确来源、原声、封面、设置和区间承接，不能再把这些一概列为没有实现 | 先完成每种来源的正向与拒绝矩阵，再撤旧入口；实际原生人工编辑优先，冻结来源仅证明出处，不重套旧字幕可见性、音量或裁切 | 未完整验证前删旧链，可能让个别原作品失去无损接续方式。这是行为及恢复验收，工作量中到高 |
| 声音表达与角色名称 | 当前已经区分原声输入、准备项和实际已采用主声；部分类型和界面仍沿用「口播」概念。名字不一定说明声音丢失 | 页面统一表达主声音：口播／原片声音／无主声；明确输入、候选、已采用和静音。由原生工程决定实际声音，保留独立音轨 ID、文件 SHA 与区间 | 主要是使用和维护时误读。不能再以旧报告中的原声缺失现象直接断言当前仍失败；需要按最终页面验收，局部调整即可 |
| 当前工具借用旧计划模块 | 图片生成、Pexels 与调用确认从 `scriptProductionStore.ts` 取 `productionHash`，实际算法是已有 `canonicalFingerprint` | 让当前调用直接依赖已有规范哈希工具；冻结前后结果逐字节相同，再处理旧 Store。无需新增哈希库 | 一删旧模块就可能误伤当前生成或授权确认。低投入、值得先做的依赖整理，不能改变授权哈希 |

本轮还定位了一处测试等待缺陷：原声用例双击后立即用默认 1 秒轮询等待准备项；实际同一次 HTTP 命令约 1.68 秒返回。私有副本改为等待准确命令回执后，原有去重、Worker、采用、原生保存、事件和零旧草稿检查全部通过。建议随后修正测试的完成条件，不改产品或放宽断言；原 33 项批次的失败仍保留。

## 之前八类内容，现在如何安排

第 1 类旧生成脚本审核链已经退役，不重复安排。其余七类以本轮有效目录和调用链为准；历史文档里的「现在应保留」不能理解为永久保留。

| 原类别 | 尚存内容及当前用途 | 问题本质 | 完全替换的方法与保留条件 | 不改的实际影响 |
| --- | --- | --- | --- | --- |
| 2：初始化与继承 | 五个函数仍挂在旧审批／镜头草稿表，负责建草稿、复用音轨和继承混音、构图、裁切 | 动作藏在数据库触发器里，与旧业务模型耦合 | 当前接入器先无损承接必需的来源和设置。所有当前写入退出旧审批／草稿之后，再以新迁移撤下纯旧动作；引用锁、冻结保护另行保留 | 增加隐式动作和排错成本；直接删可能漏掉旧作品设置，并无已证明的明显提速收益 |
| 3：旧任务完成组包 | `create_visual_review_package()`、`create_storyboard_review_package()` 仍挂任务完成触发器 | 文件／冻结结果保护和旧审核包业务混在一起 | 将 attempt、lease、冻结输入、真实文件与结果校验保留在共享回执边界；旧结果由版本化解码器解释，自动组包动作最后撤下 | 维护链更长。误删则可能失去结果核验或原审核证据；不能用「旧任务不能再领取」替代迟到回执验证 |
| 4：七个退役拒绝入口 | 旧规划、旧旁白、旧配置与连接修复签名明确拒绝执行；当前源码和有效函数体未发现精确调用 | 旧版本的兼容门牌，不是七套还在运行的制作能力 | 明确最终执行协议、核对旧进程已退出、更新启动探测后，按准确签名 `DROP ... RESTRICT` 删除，并清理当前声明。原运行包继续归档 | 主要是兼容维护成本。当前入口拒绝原包不代表已经终止所有旧进程，不能由本轮隔离测试替日常切换作担保 |
| 5：空扫描器与旧预检 | `script_production_scopes()` 返回空；`record_episode_worker_preflight()` 仍可写旧预检时间 | 一个阻止旧自动发现，一个保留旧记录合同，用途不同 | 分别退出扫描器与预检消费者后删除。当前实际目录、连接、文件、运行版本和资源检查继续生效 | 多维护两个合同。把空扫描改成真扫描会恢复旧自动行为；按名字批删 preflight 则可能误伤当前保护 |
| 6：旧 v2 手动制作组 | 六个手动命令、旧计划 GET 路由仍存在；当前来源枚举还借用旧计划读取 | 两套业务并存，值得整体退出，而不是只改名字 | 完成统一来源接入与恢复；旧计划改为明确历史只读接口；先拆工具依赖，再整组撤旧写命令、路由和无用写入方法 | 当前不自动续跑，但要维护两套设置、绑定、渲染和交付规则。直接删 Store 会伤及当前历史来源选择 |
| 7：旧 Studio 与共享 Worker | 两个旧渲染编排仍有有效 SQL 调用；当前领取经过 `claim_input_task → claim_input_task_pre_lease → claim_next_worker_task_legacy`；旁白包装仍有拒绝职责 | 旧业务、现行共享逻辑和历史命名混在一起 | 旧渲染随接入替代而退役。共享领取按资格、恢复、公平、容量、资源锁、原子建 run 与 lease 整理为少量清楚的事务实现，再改名；拒绝职责随旧合同退出 | 盲删会影响当前任务领取或保护。只给旧实现再套新名字不会减少层次，也没有已证明的性能收益 |
| 8：历史与版本化格式 | 原脚本、草稿、音轨、审批、SHA、任务、锁和归档 SQL 仍是恢复依据；当前类型仍有两代身份分支 | 证据必须保留，协议边界可以变清楚 | 旧格式集中解码，当前内部逐步只接收严格当前模型；完整备份、逐项恢复及不同来源 Owner 的矩阵闭环后，再处理无消费者的当前列／类型 | 保留原件不会自动恢复旧执行。分支散落会增加维护成本；删历史或改冻结字节会破坏恢复。已修复的旧主脚本关联问题不重复列为待修 |

## 旧名字能替换到什么程度

| 范围 | 如何替换 | 需要避免的做法 |
| --- | --- | --- |
| 当前通用执行模块 | 将 `codexRunner`、`runCodexWorker`、`CodexWorkerDependencies` 等统一为体现媒体任务职责的名称；同步静态导入、CLI、构建清单与测试 | 只改页面文字；或因为名称含 Codex 就删掉当前执行器 |
| 当前 SQL 内部实现 | 收敛职责后，为领取、预留和回执使用明确名称；一次同步调用者、权限、启动探测与测试 | 新名字永久套旧名字，旧包装一层不少；使用 `CASCADE` 掩盖未清理依赖 |
| 当前模型与类型 | 当前工作区要求真实 `preparationRevisionId`；旧审核包 ID 在历史来源类型中表达；当前任务与旧任务用版本边界区分 | 全文把旧审核 ID 改名成新基准 ID；通过类型断言或伪造空值绕过真实迁移 |
| 页面与素材显示名 | 使用「镜头」「主声音」「口播」「配乐」「原保存计划」等用途名；人工名称优先 | 随显示改名重建文件、clip、音轨或采用身份 |
| 人工登记与生成任务名称 | 本轮两条人工音轨登记在任务表中仍叫 `generate_narration`，但 attempt=0、没有外发与费用预留。当前视图按已有来源和 mode 表达人工登记／本地处理／外部生成；如进一步改任务枚举，应纳入新执行协议，保留原值解码 | 仅看任务类型就计作供应商调用，或将原历史枚举批量改写 |
| 旧 JSON 字段和枚举 | 新协议停止写旧概念，旧解码器认识原来的 `storyboard/v1`、A-roll／B-roll 等原值 | 改写历史任务、冻结 JSON、原工程和已应用迁移，让旧证据看起来像新生成 |
| `Episode`／`episodes` | 仍是当前生产单实体，不属于无用旧流程。页面可统一称生产单；若坚持改内部名，最后独立规划 SQL、外键、RLS、API、类型和恢复迁移 | 将实体名称统一与旧执行退役捆绑，一次扩大改动面；它主要改善一致性，没有已证明的制作收益 |
| SQL clean 基线与生成类型 | 最终有效 schema、前向升级、新库和恢复结果一致后，再生成下一代基线和当前接口类型 | 改写旧 ledger 或删掉用于核验旧备份的归档迁移 |

可以做到当前代码与页面完全使用当前名称。历史原件中的旧字段、协议号和文件名保留在历史边界；这不妨碍当前流程完成替换。验收目标不是整个仓库搜索旧单词零命中。

## 哪些需要重写，哪些直接删除或改名

- **局部重写**：来源接入的分支协调、共享 SQL 领取／回执／预留中交织的职责。保留已验证算法与事务保护，不换整套基础设施。
- **有条件删除**：退出消费后的旧写命令、旧业务触发器与渲染编排、七个拒绝签名、空扫描和旧预检合同；具体以依赖及恢复验收为准。
- **直接整理依赖或改名**：哈希工具导出、通用 Worker 名称、当前界面与类型术语。同步构建和调用合同，不增永久兼容壳。
- **必须保留**：Owner／RLS／ACL、attempt／lease、公平与容量、真实文件／输入／导出 SHA、费用确认和未知不重发；原历史数据与冻结文件。

## 埋点如何收尾

本轮可与制作链联验，代码已经位于同一源码，无需合并另一工作树。继续使用已有采集体系，不另建一套。

需要分清：准备不等于采用；声音使用不与候选采用相加为总数；本机导出不伪装成 Worker 队列；阶段事实不与阶段证据重复相加；费用预留／估算／应用上报不等于供应商实付；CPU／内存是主机观察，不是单任务独占消耗。未知数据保持 null，关闭期间不补造。

后续优先补最终来源／恢复路径的事件对账及运行包一致性。长期与跨进程采样、真实 Provider／账单仍需独立验收；视频分支在本轮禁用范围内不测试。只读统计 API／Dashboard 可作为后续可用性功能，不是删除旧流程的前置理由。图片重试的 `input_changed` 若需准确分类，应增加不含授权身份的语义指纹，不能拿授权哈希变化推断内容变化。

日常部署、重启、Owner 采集开关及资源采样配置另行授权。本轮隔离启用不改变日常开关，也不代表最终日常运行包已经更新。

## 推荐实施顺序与验收

1. **保结果正确**：独立处理正式输出底色；完成当前声音名称和来源状态的最后页面验收。先修真实可见问题。
2. **完成历史接入**：覆盖保存计划、未确认／确认／混合草稿、HTML／JSON、保存原生工程，保留原裁切、字幕、音轨、设置和封面；完成整库＋文件、逐项及不同来源 Owner 恢复。
3. **拆当前依赖**：让通用工具脱离旧 Store；将只读历史计划与当前执行明确分开；严格当前模型不再依赖旧审核 ID 回退。
4. **退出旧执行消费者**：定义最终执行协议，核对应用／Worker／编辑器进程及启动探测。保留归档运行包，停止支持原程序继续执行。隔离门槛成功不等于完成日常停旧。
5. **批次退役旧业务**：先关旧写命令，再按实际依赖拆触发器与旧编排，删除无消费者的拒绝／空查询／预检。使用前向迁移、准确签名和 `RESTRICT`。
6. **整理共享职责和命名**：将资格、锁、容量、run、lease、结果与费用边界保留到明确实现，移除不再需要的包装；最后统一当前名称、类型与有效 SQL 基线。
7. **最终整体验收再切换日常**：跑完整默认回归、真实 UI 与原生保存、导出／交付、前向升级和恢复、埋点对账；汇总通过与未覆盖项，再按另行授权部署和启用。

每批验收同时包括正向制作，错误 Owner／SHA／lease／过期输入拒绝，重复与中断恢复，旧数据和文件逐字段／字节保持，以及新库、升级和恢复的 schema 对账。不能靠放宽保护使测试通过。切换后已有新写入时，不能把旧备份覆盖回去称作无损回滚。

完成条件：当前制作无旧业务写入、当前调用无退役入口、旧消费者有明确退役门槛、共享保护可独立验证、历史原证据可恢复、当前名称统一、最终有效 schema 与升级／恢复一致。达到这些条件后再宣布全面替换完成。
