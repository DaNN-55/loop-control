# 当前制作与旧流程全面替换方案：196 副本评估

日期：2026-11-14。状态：Proposed，本轮仅测试与建议，不执行改造。依据[本轮新生产单与埋点报告](../verification/production-replacement-assessment-196-20261114/REPORT.md)、固定源码／有效 SQL、现有 ADR-0066／0068／0069。沿用已确定的 PostgreSQL、Owner 事务、原生工程和 Worker；不新增另一套制作系统。

## 结论与清理范围

建议局部替换、逐步收口，不整体重写。现有内核已能让新单不经过旧审核包／草稿／审批而完成图片制作、保存、导出和交付。重写这些已验证能力会重新承担文件身份、支付确认、请求未知、原生编辑与恢复的成本，当前证据没有支持这项代价。

值得改的部分是：正式输出底色、旧作品接入缺口、两套执行入口、隐藏触发动作、重复包装与分散历史回退，以及当前名称／类型不一致。它们不是同一种问题，不能用全局替换名字一次解决。

“完全清理”应定义为：当前操作只有一套制作模型；旧执行入口退出；必要的旧资料由版本化适配器读取／接入／恢复；当前名称表达实际职责。原历史、冻结输入、草稿、音轨、审批、原包字节、已应用迁移与备份中的旧名字继续保留。全文零命中不是完成标准。

## 先处理真实功能与覆盖缺口

| 问题 | 大白话：原因是什么 | 怎么改 | 不改的实际影响 |
| --- | --- | --- | --- |
| 棋盘格进入正式 MP4 | 编辑器用来提示透明区域的装饰底，被当作正式画面输出；是 SDK 输出问题 | 在渲染边界明确区分预览网格、不透明背景与透明输出。普通 MP4 使用明确底色；验证 contain、透明 PNG、横竖比例、位移和多镜 | 文件、SHA 和交付都成功，画面仍可能不符合预期。优先修；不能仅强制裁满掩盖 |
| 原计划设置尚未完整落到当前制作 | 旧记录留着原值，但有的只保存为来源证据，尚未转成当前可编辑／采用参数；是映射缺口 | 建逐字段清单：时长／画幅／布局、字幕模式／空间／样式、口播增益、音乐／音效增益、闪避、时间偏移、封面。区分已映射、只保留证据、不支持并明确提示；通过当前输入／混音操作接入，采用仍需明确操作 | 不能把“原值没丢”说成“新工程已经按原样设置”。例如原配乐应很轻，接入后直接采用当前默认音量，听感可能不同；本轮未为全部字段做行为复现 |
| 旧手工绑定未形成成品的接入 | 老用户可能已挑视频、口播和混音，却尚无 SDK 工程／HTML 产物；当前接续主要要求已有原生或产物，计划导入也不等于接入草稿的实际采用 | 从原镜头草稿、选择／确认和冻结来源读取已选素材；核对原镜头、文件、时间窗、字幕、混音／构图，显式生成当前工程。保留未采用候选，歧义／失效项列出，不能自动生成或猜测 | 现在就删旧手动入口，会让一部分未完成旧作品失去继续操作的路径；是删除前阻塞项 |
| 接入 UI 缺口 | 后端已有原计划只读／接入命令，页面尚未提供这条完整选择流程；是产品入口问题 | 展示原计划及核验状态、源版本和待接入内容；Owner 明确选择。已有当前编辑继续原工程，源脚本变更显示差异，不覆盖、不套新默认、不消费原授权 | API 能做不等于日常用户能可靠完成迁移，容易误选来源或误以为参考已采用 |
| 大工程与复杂声音边界 | 真实文件核验／观察仍有开销，部分 SDK 声音结构无法可靠解释 | 测大文件、多来源、多别名和超时；必要时做以不可变身份为依据的缓存或两阶段观察。复杂变速／嵌套按实际模型逐项支持，不支持继续 unknown | 多来源保存开销上限未证明；复杂声音统计不完整。不得跳过实际 SHA 或伪造事件换取更快保存 |

旧计划只读“不再因现脚本变 v3 而看不到原计划”、首条显式接入、当前工程不覆盖、原生文件仍在而 SQL 行缺失时拒绝重建、受控同账号复制及未知任务保持，均已有实现且本轮重验通过，不安排为从零开发。

## 原来八类的当前处置

第 1 类旧生成脚本链已经退役，不重复列清理任务。其余类别如下；原历史关联恢复缺陷已有修复，也不重复称为现存缺陷。

| 原类别 | 当前用途／问题类型 | 建议及删除条件 | 不改／误删的影响 |
| --- | --- | --- | --- |
| 2. 批准后建草稿、历史复用、继承混音／构图 | 四个实际挂载触发器仍执行旧业务动作；主要是结构问题 | 将旧作品接入所需能力集中到明确的同事务操作；核对草稿、音轨、镜头、构图／混音及恢复承接，再随旧批准路径退出移除触发器及函数 | 不改需维护隐式动作；误删可能导致旧作品缺素材继承。不能凭前端零调用判断无用 |
| 3. 旧任务完成后组审核包 | 两个挂载函数同时承担原结果核验和旧证据投影；结构与保护混在一起 | 分开租约／attempt／冻结文件回执验证和旧审核包投影；明确在途、迟到、未知与已验证结果的恢复规则后，退出纯旧组包 | 不改保持第二套投影；误删会丢证据或放松错误结果拒绝。不能靠重发供应商恢复 |
| 4. 七个退役拒绝 SQL | 保留明确“已退役”响应的旧签名；是兼容成本 | 已有运行协议门槛，仍需核对最终包／实际旧消费者退出和有效依赖；之后用前向迁移、准确签名、RESTRICT 删除，同步类型与探测 | 不改不会自动恢复旧制作，只增加维护；先删可能打断旧消费者启动。缺函数不等于受控退役已完成 |
| 5. 空扫描器、旧预检 | 前者使旧自动发现持续为空；后者核对 Owner 并登记预检。不是同一种职责 | 当前精确名字扫描未见执行消费者，列优先退役候选；随旧扫描／Runner 退出删除。当前连接、文件及运行能力预检继续保留 | 不改主要是兼容量；不能把空扫描改回真实扫描，也不能按 preflight 单词批删 |
| 6. v2 手动命令和旧查询 | 当前仍存在第二套配置／绑定／渲染／交付；计划只读与首链接入已补，完整接入未结束 | 完成上表剩余映射、旧人工绑定及 UI／恢复矩阵；只读查询迁到历史边界，整组关闭旧手动写入口 | 长期两套规则容易串用；现在删会遗漏尚未接入的旧作品 |
| 7. Studio／媒体与共享 Worker | 有些是真旧业务，有些是当前实际共享能力，`legacy`、`codexRunner` 名称不能表达现职责 | 逐层列保护矩阵，合并重复包装；通用执行器按媒体任务职责命名，旧 Studio／QC 操作随能力迁入退役 | 只改名不会简化职责或保证提速；盲删会影响当前任务领取、回执、容量、公平和预留 |
| 8. 历史、冻结及格式回退 | 原资料有恢复价值；当前核心仍分散理解两代字段，是边界问题 | 版本化解码器核对身份、Owner、文件和原引用，输出严格当前模型；整库／逐项恢复共用明确映射。旧审批关联、失效传播等保护找到承接后再收敛 | 原数据本身不可当垃圾删。不改主要增加理解／回退成本；误删会影响追溯与历史恢复 |

第 2 类为 `seed_shot_preparation_drafts_after_storyboard_approval`、`reuse_shot_preparation_history_after_storyboard_approval`、`copy_shot_audio_mix_to_revised_draft`、`copy_shot_composition_to_revised_draft`；第 3 类为 `create_storyboard_review_package`、`create_visual_review_package`，本轮有效库仍各挂一个触发器。

第 4 类七个函数为 `plan_input_tasks`、`queue_workspace_planning`、`replan_workspace_planning`、`save_planning_selection`、`generate_input_shot_tts`、`apply_episode_configuration_repair_v2`、`apply_external_connection_repair`；第 5 类为 `script_production_scopes()` 和 `record_episode_worker_preflight`。它们当前未发现精确名字消费者，但本轮没有完成动态 SQL、外部消费者和全部 `pg_depend` 退出审计，不能直接执行删除。

六个旧手动命令为 `configureScriptProduction`、`pauseScriptProduction`、`applyScriptSettings`、`bindScriptVideo`、`renderScriptReview`、`prepareScriptPublish`；旧计划查询为 `/api/local/script-production`。其他旧镜头制作、Studio 审核渲染、QC／发布家族仍需逐组做能力对应，不能只退役这六个就宣布全部退出。

## 旧名称可以替换到什么程度

| 范围 | 建议目标 | 改法与实际价值 |
| --- | --- | --- |
| 当前通用执行器／私有模块 | 例如 `mediaTaskRunner`、`runMediaTask`，名称说清做什么 | 重命名时同步导入、脚本、CLI、构建清单、prepared manifest、测试和当前文档。保留任务 ID、文件身份和旧包字节；降低误读，不承诺提速 |
| 共享 SQL 函数 | 按资格、领取、租约、回执、费用预留／拒绝命名 | 先厘清并收敛实际包装。`claim_input_task → claim_input_task_pre_lease → claim_next_worker_task_legacy` 本轮仍实际连接，不能只替换后缀；避免再叠一串“新名字包装旧名字” |
| 当前工作区身份与类型 | 当前读写必须有制作基准，旧审核包只作为明确的历史来源 | 当前 `preparationRevisionId` 仍可选，部分核心还有 `preparation_revision_id ?? storyboard_package_id`。完成旧数据转换与恢复后收紧真实合同、消除核心分散回退，不能只用断言压掉错误 |
| 用户看到的名称 | 镜头、口播、候选、已采用、配乐、工程版本 | 界面不暴露内部 `workspace-*` ID；原生素材默认显示名用可读称呼，用户手工名称优先。不以改名重建 clip／音轨 ID，也不把草稿当已使用 |
| 旧输入／任务／备份协议 | 仅在版本化历史类型和适配器中保留旧字段 | 原字段拼写是旧文件协议的一部分；从当前核心退出即可，不能全局替换原快照导致 SHA 或恢复协议变化 |
| `Episode`／`episodes` | 当前领域仍代表生产单，本身并非退役流程 | 若明确要求内部也变成 `ProductionOrder`／`production_orders`，另做跨 SQL、外键、RLS、API、类型和恢复的版本迁移。收益主要是术语一致，成本较大，不宜夹进常规无用代码清理 |
| SQL 基线／生成类型 | 最终有效 schema 和当前接口，历史声明单列 | 前向迁移最终验收后生成新 clean 基线与类型；保留已应用迁移、ledger 和归档。新建与升级的权限／行为／恢复必须一致 |

上述目标名称是建议，不是本轮新增公开协议。不要机械替换底层仍在使用的 Provider 能力名称；例如当前视频能力仍可用，不因旧 HTTP 命令同名而删除，虽然本轮未调用视频 API。

## 埋点还需要补什么

本轮可以与生产测试同步完成主要对账，无须为“尚未合并”另等一轮。38 项相关集成及 37 项定向检查通过；逐单阶段、声音、导出、交付与真实文件一致。具体通过与未测范围见报告。

后续仍需：

1. **把统计提供给用户查看。** 增加受 Owner 约束的只读查询／展示，按生产单、日期和覆盖区间解释事实。候选采用、声音实例、制作里程碑、数据库阶段和 Worker 执行是不同指标，费用预留／上报不能展示成供应商扣款。
2. **覆盖缺口保持诚实。** GPU、首样本 CPU、复杂原生声音、启用前历史保持未知；图像重试不可用授权指纹变化判断内容变化。跨停用区间不补造。
3. **最终版本做一次启用前验收。** 代码／迁移／运行包对齐，隔离开启采集和资源开关，验证长期采样、空闲停止、重启、重复保存／回执、失败和未知结果不重发。真实 Provider 的扣费与产出如需验证，另明确授权；本轮受控响应不能代替。

日常启用、必要服务更新／重启是部署动作，不由此次评估自动执行。

## 建议按这个顺序实施

1. **修成片底色。** 工作量集中在 SDK 输出边界，独立于 SQL；以真实导出／抽帧验收，不仅看导出状态。
2. **补齐旧作品接入。** 完成原设置逐字段映射、无成品手工绑定、UI 来源选择；不覆盖当前编辑，不自动恢复旧预算／连接授权或重发未知请求。验证新旧作品、选中／未选、源脚本差异、原源离线及真实完整／逐项恢复。
3. **收紧当前协议与历史边界。** 当前类型必须独立身份；旧格式集中解码。执行协议随破坏性合同变化提升，实际切换时核对旧进程和消费者退出；23 原包保留证据，不把原样执行作为永久要求。
4. **先退役无消费者入口，再拆旧业务链。** 优先七拒绝 SQL、空扫描／旧预检及已迁出手动命令；随后旧批准／组包、Studio／QC 家族。每批准签名、有效依赖、保护承接和恢复证据齐备后 RESTRICT 删除，不用 CASCADE 掩盖未知依赖。
5. **收敛共享保护，统一当前名称。** 对 Owner／RLS／ACL、容量／公平、历史／回收站、lease／attempt、冻结输入、实际文件／准确导出、费用确认和未知结果逐项做允许／拒绝等价验证，再改职责名。结构与机械改名分批，便于发现行为变化。
6. **生成最终基线和总验收。** 新建、升级、注入回滚、完整备份与逐项恢复一致；默认完整套件一次，真实宽窄 UI、新单到交付、旧工程接入、故障／崩溃／恢复及独立审查。最后按部署授权处理日常包和采集。

每一批必须能单独审阅和回退；原数据和原包不清除，回退有新增写入时不能简单覆盖旧备份。中间阶段不保留无期限的两套执行，也不以某一条绿色新单代替整个替换完成。

完成后可以清掉的是无用执行代码、重复编排、旧兼容入口和当前核心的过时命名；必须留下的是保护职责以及可解释、可恢复的历史。当前尚未全面清理完毕，但没有必要重建现有制作内核。本轮仅交付上述方案，不实施修改、不提交、不推送。
