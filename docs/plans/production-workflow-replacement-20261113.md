# 当前制作链与旧流程全面替换建议

日期：2026-11-13。状态：待评审方案，未实施。依据：当前工作区隔离副本、新生产单实际制作与交付、同单埋点对账，以及日常有效 SQL 的只读清单。关联验证见 [生产单与埋点验收](../verification/isolated-production-and-legacy-review-20261113/REPORT.md)。

## 结论与目标

建议在现有四步制作上分批替换，保留已经验证的制作内核，针对旧业务模型和兼容层做局部重构。没有证据支持把整个项目推倒重写。新单已经可以完成图片、人工音轨、字幕、原生编辑、导出和技术交付；但本轮发现共用人工音频路径时交付说明错选音轨，尚不能判定业务交付全部正确。剩余成本主要来自当前功能借用旧数据结构、旧包兼容、逐层包装的 SQL 和名称与实际职责不一致。

目标应是「当前执行链、对外当前接口和用户界面只使用一套清晰概念；历史证据可原样读取并通过当前程序恢复」。这不要求继续运行所有旧二进制，也不要求抹掉备份、冻结快照和历史迁移中的旧字符串。历史恢复与旧程序继续执行是两件事，必须分别验收。

此前八类的第 1 类已由 185 完成退役，本方案不重复安排清理。此前独立核查的 `public.create_episode(uuid,uuid,uuid,text,boolean)` 仍存在，当前新建走目录意图协议，本方案将它单列为可先实施的删除项。

## 本轮新生产单说明了什么

新建三镜头、约 9 秒生产单，使用本地测试图片、人工音轨、配乐和独立字幕；另执行受控图片、受控口播各一次，验证明确确认、请求、候选和统计链。没有外部付费请求，没有视频 API 请求。生成内容是测试图形和音调，不能用于判断模型画面、中文语音或艺术质量。

这条链没有创建审批行，但仍创建了 `storyboard_review` 审核包、3 条 `shot_preparation_drafts`，并使用 `audio_tracks`、`tasks` 和 `production_workspaces`。因此，数据库对象名字旧，不代表当前已不用。若要彻底换掉旧模型，必须先替换当前写入者、读取者和恢复映射。

数据库阶段实际只经历 `waiting_input → script_approved → production_completed`。分镜台、剪辑、导出等实际工作包含在 `script_approved` 期间。当前阶段埋点忠实记录了数据库变化，却不能直接提供四步各自的耗时。

## 命名建议及边界

以下是候选名称，需要随最终接口设计确认，不是本轮已接受或已执行的重命名。当前术语表中的 Owner、内容账号、生产单、制作选择、执行快照和制作工作区继续沿用。

| 旧名称或概念 | 当前语义与建议名称 | 迁移方式 |
| --- | --- | --- |
| `claim_next_worker_task_legacy`、`*_pre_lease` | `claim_eligible_task`、`attach_task_lease` 或合并后的明确领取事务 | 保持当前容量锁、回收站／历史栅栏、轮转公平、资源约束、attempt／lease；同步 SQL 调用及 ACL，后删旧层 |
| `reserve_workspace_narration_submission_legacy` | `reject_unsupported_narration_submission` | 名字表达拒绝；保持租约检查和 `0A000`，不改为成功或静默跳过 |
| `orchestrate_review_render_tasks`、`orchestrate_final_render_tasks` | 历史工程适配器内的 `queue_review_render`、`queue_final_render` | 先核对当前 Studio 与旧包调用；仍支持旧签名期间保留桥接 |
| `codexRunner.ts`／`runCodexWorker` | `mediaTaskRunner.ts`／`runMediaTask` | 全部当前静态导入、prepared manifest、CLI 与测试一起更新；历史包字节不改 |
| 当前准备基准中的 `storyboard_review`、强制 `shotType:'b_roll'` | 版本化制作基准、镜头、画面方式 | 新格式不带已退役分类；旧 `storyboard/v1` 解码器继续理解原字段 |
| `storyboard_package_id`、`review_package_id` | 当前模型中使用独立的 `preparation_revision_id` 等明确外键 | 不是列名替换：迁移来源、稳定镜头 ID、音轨绑定、恢复映射和校验合同 |
| 原生素材 `workspace-narration-shot-shot-01` | 页面显示「镜头 01 口播」 | ID 不动，显示名可改；已有手工名称优先保留，不搬文件 |
| `episodes`／`Episode` | 这是生产单的现行领域实体，不因英文名看着旧就自动改 | 若另行统一为 `production_orders`，单列跨 SQL／API／类型／恢复的迁移，不和删除兼容入口捆绑 |

「完全替换旧命名」可以做到当前可执行路径和当前接口不再暴露旧概念。若同时要求继续执行所有原运行包，它们原先调用的旧名字就仍须有兼容承接。建议目标是升级当前执行环境、保存历史包作恢复证据，并用当前恢复器读取旧资料；达到验收条件后撤下旧执行合同。不能同时保证旧程序原样执行、又保证它依赖的签名彻底不存在。

## 推荐实施顺序

### 第一批：先处理确实影响恢复的缺陷，删除已证实无依赖入口

1. 先修本轮交付 metadata 错选音轨：共用文件、不同音轨／文案、再次采用、原生剪辑与同路径歧义要有失败断言；技术校验和业务内容校验分别对账。
2. 单独修复历史主脚本关联投影，覆盖父记录先后顺序、当前已有脚本、跨 Owner／跨单引用、冲突、重复投影和事务回滚；原始证据不可改写。
3. 单独退役旧 `create_episode` 及陈旧类型。未来迁移编号实施时重新分配，不预占并行任务编号。
4. 列出所有原包及支持状态、旧接口消费者、活跃／未知请求；形成可机器核对的支持清单。

这批无需重写制作内核。这些功能变化应分别验证和交付，不能把上轮核查通过当作未来版本永远无漂移。

### 第二批：把当前制作模型从旧审核模型中分出来

1. 建明确的制作基准版本和镜头身份；冻结主脚本、素材、布局及来源。
2. 当前准备、候选、音轨和字幕读取统一指向新基准；迁移当前已存在的作品时做稳定 ID 对账，不覆盖人工编辑。
3. 提供旧工程接入／历史恢复适配器，保留原包、草稿、音轨、审计、审批、哈希与原路径；不能默认重新生成或重新计费。
4. 新增脚本版本，支持纯静态制作，明确拒绝错误的结构化输入，保留旧版解码。
5. 同步定义制作里程碑和统计范围；不能把 UI 切换标签当实际阶段变化。

这批是局部核心重构，收益比大规模改名高，也需要最完整的历史、原生编辑和交付验收。

### 第三批：迁移旧手动业务，关闭旧执行包

1. 用实际旧计划、旧 HTML 和原 OpenChatCut 工程逐个验证当前接入；没有完整转接能力前保留旧手动入口。
2. 处理仍在途、结果未知和可恢复的旧请求：保留原请求，只读核对；不能为了收尾自动重发。
3. 最低版本检查先落地，旧包在启动前获得明确退役提示；升级日常包需另行授权、核对编辑器和活动任务。
4. 停止支持原执行包后，统一移除旧 v2 命令、旧拒绝 RPC、空扫描器、无调用的预检；保留归档证据。

这是移除兼容空壳的前提。仅在测试副本里把 23 个包删掉，不能证明用户实际不再需要它们。

### 第四批：收敛 SQL 包装、重命名和生成新基线

1. 从有效 SQL 函数逐条提取保护清单，对当前允许／拒绝结果做对比；先整理当前领取、媒体选择、提交回执等链。
2. 分模块收敛 `*_before_*`、`*_pre_*` 与 `*_legacy`；明确职责后再重命名；不要把所有流程装进一个大函数。
3. 当前类型按有效接口生成，历史类型留在版本化解码器；加入当前执行目录禁用退役入口的扫描检查。
4. 前向迁移、旧源升级、全新建库、完整备份恢复、逐项历史投影均通过后，再产出 clean baseline。保留历史迁移和 ledger 一致性。
5. 最后统一用户显示名与术语，保留所有冻结快照、已采用来源与可下载历史文件。

不要在尚有行为变化时先做全仓库全文替换；那会让代码审查无法区分改名与真实语义变化。

## 每批都要保持的验收条件

- 当前新单完成：正文、静态／已有素材、口播及混音、字幕、原生保存重开、精确导出确认、交付包 SHA 与下载对账。
- 旧单接入：人工编辑、镜头身份、原音轨、未采用候选、已拒绝候选、冻结来源和旧渲染结果保持；原包是否可执行按支持清单分别断言。
- 恢复：完整 SQL、非空历史逐项投影、媒体离线／重挂、故障与 SIGKILL 边界；不以原文件还在代替关联正确。
- 权限和费用：Owner／跨账号／跨单、RLS／ACL、租约、结果未知、明确确认、重复操作、冻结输入、内容变化后旧确认失效；不得放宽。
- 埋点：按真实提交与使用事实对账；重复保存和重开不多算；停用不记录、启用不补造；统计失败不能授权重复请求；新旧质量和事件版本不混算。
- SQL：显式签名删除，额外依赖阻止、失败回滚和幂等；原行、序列、权限及非目标函数保持；新旧基线收敛到同一有效 schema。

## 本轮没有做的事

没有实施上述重构、重命名或清理，没有新增／应用正式 SQL 迁移，没有修改日常采集、服务或历史数据，没有提交或推送。此次浏览器与制作使用自有隔离数据库、媒体卷、SDK 和源码副本；私有测试脚本不回迁产品目录。
