# 当前制作链全面收口方案（193 核查更新）

日期：2026-11-14。状态：Proposed，本轮仅测试和记录，没有执行下述清理、重命名或产品修复。依据 [最新生产与埋点报告](../verification/production-replacement-assessment-193-20261114/REPORT.md)、ADR-0066／0068／0069；此前规范的未完成范围保持。

## 总体建议

保留现有 PostgreSQL、Owner 事务、原生工程及 Worker，按模块逐段替换。当前独立制作模型已能完成不写旧审核包的新单，交付身份、v3 默认入口和制作里程碑已有实现，推倒重写会重新承担权限、费用、文件与恢复的验证成本。

最终只保留一套当前制作命令和明确的历史适配边界。旧运行包不再永久拥有当前执行权，但原包、历史草稿／音轨、文件、冻结快照、版本迁移和 ledger 继续保存。当前显示名称、函数名、文件名可以逐步替换；历史协议字面量和证据不能通过全局替换改写。

## 埋点能否一起验收

可以。引用「埋店」代码已在当前工作区，本轮已与新单一起验证，无须先合并。8 个制作里程碑各一次、重开不重计、关闭不采集、未知结果不重发、Owner 隔离、失败回滚和非空恢复均有实际专项证据。

仍须补三层：

1. **完整素材／声音使用事实。** 主口播候选事件不能代表全部使用量。配乐、音效、原声、本地图片分别记录采用／替换／静音／撤回，依据有效时间线中的可听／可见内容、轨道、嵌套和来源身份；不能仅按素材 ID 前缀猜。
2. **本机导出活动和资源窗口。** 已有就绪／确认不等于开始／失败和耗时。同步导出在业务事务内持有工作区锁，不能简单另开有外键的活动事务，避免自锁等待；评估同进程活动注册或独立短事务协议后再实现。资源仍双开关，不能伪造 Worker attempt，也不能把主机 CPU 当单任务用量。
3. **只读展示与启用前验收。** 当前没有完整 Dashboard／统计 API。明确分母、停用缺口、未知费用和保留期后接只读展示；最终冻结代码后验收长期采样／重启连续性。日常开关和必要服务更新单独授权，不以本轮受控测试证明真实供应商实付或 GPU 指标。

本轮私有日期窗口错误已修正，产品指标仍按上海时区、结束日不包含在内；没有理由改统计合同迎合错误测试。

## 推荐顺序和完成标准

1. 先修真实成片背景，再单独修测试合同；复用本轮生产单，增加透明／留空／混合来源反例。
2. 完成当前必填身份、旧工程显式接入与全部恢复矩阵。已有独立制作、v3 和里程碑保留，不重写。
3. 对 23 个原包逐一定义允许执行、只读恢复、拒绝执行；现有 schema 186 清单不是 193 全包通过证明。未知／在途请求保留，不自动重发。
4. 门槛成立后成组删除旧手动命令、拒绝 SQL、空扫描／旧探测和纯旧触发写入，同步调用与类型；保留审批／回执所承担的有效校验。
5. 按职责整理共享保护与命名，再统一显示名和草稿语义；当前名称可以清理，原 ID、历史协议、备份和冻结证据不改字节。
6. 补声音使用／导出观测和只读统计；从最终有效 schema 更新类型与 clean 基线。验收新建库／前缀升级／失败回滚／角色权限／整库及逐项恢复、默认完整套件和实际 UI。

最后的「清理完成」应表示：当前链只有一套模型与执行入口，新单零旧审核／草稿／审批写入；旧包执行结果明确；旧作品可读且需要时可接入；共享保护逐项等价；当前用户界面与实现名不借旧流程表达。旧词仍存在于不可变证据和版本化历史解码属于有意保留，不应追求全文搜索零结果。

所有建议均未在本轮实施；没有清理历史资料、放宽保护、提交或推送。
