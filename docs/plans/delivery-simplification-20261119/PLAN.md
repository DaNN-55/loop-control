## 1. 目标与边界

让零基础用户看得懂下一步，并用最少的必要操作完成：

**分镜准备 ↔ 剪辑 → 生成成片 → 观看确认 → 下载视频。**

发布资料独立可选：AI 帮用户起草标题、简介、标签，用户可以修改并分别复制；封面按需选择。不要求先准备发布资料才能完成视频。

本方案包括完成语义、交付页面、发布资料持久化、AI 文案、封面选帧、已完成作品的生产单副本，以及旧人工问题功能的完整退役。沿用现有分镜台和剪辑台能力，不重做编辑器、素材生成、账号设置或外部发布。

测试单整体清理属于后续清理事项。本方案只删除本功能已确认退役的问题记录及关联入口、门槛和专项界面残留，不据此批量删除生产单、原素材、任务、备份或其他验证报告。

## 3. 页面与状态

### 主流程

1. 剪辑台保留普通“保存”和返回分镜台；“保存并前往交付”改为明确的“生成成片”。先保存当前工程，成功后进入检查页并生成该工程的视频。
2. 检查页突出实际视频播放器、一个当前状态和一个下一步主操作。未生成时显示“生成成片”；生成期间显示进度/运行状态；可确认时显示“确认并完成”；完成后显示“下载视频”。
3. “返回剪辑”无需记录问题。技术失败直接指出应返回剪辑、恢复文件还是重试；正常检查明细不占主要操作区。
4. 发布资料保持紧凑可见，不随视频确认状态锁住。没有文案时展示 AI 生成及自己填写入口；有文案时展示三个可编辑字段及分别复制按钮。补充要求可选。封面只先显示当前图片或“添加封面”。
5. “更多下载”容纳真实存在的附加输出，不显示尚不存在的封面或伪造空文件。工程下载仍清楚说明其原素材依赖。

### 状态解释

| 事实 | 主要呈现/动作 | 后台要求 |
| --- | --- | --- |
| 尚无当前成片 | 待生成 / 生成成片 | 查看不触发生成。 |
| 正在生成 | 正在生成成片 | 重复点击、刷新恢复同一操作，不额外渲染。 |
| 渲染或技术检查失败 | 具体失败原因 / 重试或返回修改 | 保留已有文件、检查证据与恢复依据。 |
| 当前视频通过技术检查，尚未人工确认 | 待确认 / 确认并完成 | 确认绑定实际 MP4、工程及内容身份。 |
| 人工确认后正在收尾 | 正在完成 | 自动校验/登记核心交付；不再增加人工按钮。 |
| 核心交付有效 | 已完成 / 下载视频 | 与封面、文案、AI 是否可用无关。 |
| 工程实际内容已更新 | 视频需重新生成 / 生成成片 | 不把旧视频当作当前输出，保留旧文件。 |
| 曾完成但文件当前缺失/损坏 | 文件不可用及具体恢复入口 | 区分完成历史与当前文件可用性，不永久卡在“需核验”。 |

后台仍可有渲染、检查、确认、排队、校验等阶段；界面精简不删除任务租约、失败恢复和审计事实。不能将任意一次历史成功等同于最新文件成功，也不能用最新失败抹掉仍可下载的历史文件。

## 4. 数据与实现约束

### 4.1 核心交付与可选发布资料分开

- 核心交付保留已确认视频、对应完整工程、检查证据和身份清单。封面/发布文案不属于完成门槛，不用虚假占位标题或空封面绕过旧校验。
- 为新核心交付定义版本明确的清单协议；现有 `publish-package/v2` 五类产物清单按原协议读取和校验。不能直接放宽旧协议，导致旧包缺文件也被判成功。
- 用户“确认并完成”触发人工确认及自动收尾。确认成功、打包失败时保留确认事实，重试仅继续原文件收尾；文件或工程身份改变后须重新生成并人工确认。Worker 不得代替用户确认。
- 发布资料独立保存，具有自己的修订号、归属和所依据的视频/工程身份；修改它不增加视频内容版本、不令视频过期、不改成片确认或生产完成状态。
- 已完成原单可修改发布资料，这是 Q10 已确认能力；它不属于 Q22 的视频编辑复制触发条件。旧包不可变，新下载包固定当前已保存的发布资料快照；包内视频身份仍指向原已确认视频。
- 所有包按真实存在产物构造。旧包、旧下载链接和旧文件保持可核对；新资料保存中或保存失败时不能声称新包已经包含该资料。

### 4.2 自动保存与 AI 文案

- 正式自动保存至少覆盖标题、简介、标签、补充要求、封面真实文件及选帧来源身份；本机草稿用于未完成写入的恢复，不能只记封面文件名后要求用户刷新重选。
- 发布资料以生产单/工作区为归属，不因新导出 ID 改变而清空。Owner 隔离、修订校验和旧响应防覆盖沿用现有可靠模式；保存失败就近显示，不能显示虚假的已保存。
- AI 增加专用文案合同/请求，不把脚本识别或拍法 Prompt 冒充发布文案能力。复用服务目录、连接校验、模型选择及请求恢复基础设施，不整体复用“已完成单不可写”的脚本命令。
- 发送前固定当前工程、实际使用片段/口播/字幕、账号/系列规则、当前文案、补充要求与所选模型。上下文由服务端核对，不信任客户端宣称的最终成片。
- 裁切、变速、静音或仅采用部分声音时，不把完整源口播当作完整成片台词；只能使用能证明保留的内容，未知内容标识为未知。没有字幕/口播时仍可基于实际画面安排起草，不额外调用视频理解或语音识别来补齐。
- AI 结果只更新发布资料，不改脚本、工程或确认事实。标题、简介、标签按现有有效长度/格式校验；输出格式错误保留旧文案并给出可操作错误。
- 仅新明确生成意图创建请求；重复点击、刷新、超时恢复读取原请求，未知结果不自动重发。不能因后台自动保存而触发模型。
- 成功替换前保留至少最近一次完整文案快照供撤回。进行中的结果若遇到用户新编辑、切生产单或视频基准变化，不静默覆盖新状态；使用修订校验保护，仍保持单套编辑界面。
- 复用最近明确选择模型的偏好；所选模型不可用时提示选择，不自动换供应商。无模型时手写、复制、视频完成和下载仍正常。

### 4.3 封面

- 已有图片选中后完成必要读取和验证即可使用，不再增加“使用已选封面”第二次采用操作。
- 成片选帧从实际视频解码指定帧，保存视频身份和时间位置，产出可持久化的真实图片；不以播放器截图或空文件代替。
- 上传保留真实图片、类型、大小及归属验证。已有封面来源失效时明确提示替换，不能因此阻止视频完成。
- 视频更新时保留已选封面及其旧来源事实，统一提示核对。取消选图/选帧不删除当前已保存封面。

### 4.4 已完成原单与新生产单副本

- 单纯打开、播放、选中片段或查看不创建正式生产单副本。可复用临时隔离工程承载编辑，但必须保证原单不被写入。
- 用户实际修改并首次明确保存时，以可恢复、幂等的流程建立新 Episode、新 workspace、新媒体归属/必要 ID 映射，再保存本次修改；成功后切入新生产单的正常剪辑会话。
- 副本继承原单适用的脚本和已确认制作依据、账号/系列创作基线、素材与采用关系、原生时间线/字幕/声音、可用制作选择，以及已保存发布资料。使用原单的创作基线，不悄悄替换为账号最新规则。
- 原生切镜、片段位置、裁切、音量、字幕正文/时序/样式以及绑定必须保持。重新映射生产单及文件身份；必要文件可用受支持的写时复制或流式复制，不允许可变写入穿透到原文件。
- 已采用素材无需重新生成；旧生成任务/请求仅作为来源证据，不复制为可执行任务，不重发付费请求，不复制秘密或自动继续授权。
- 不继承旧成片为新成片，不继承人工成片确认、已完成状态、交付回执或旧问题记录。副本脚本/素材依据可直接使用，无需强制重走前三步的确认。
- 副本停留剪辑台，可退回分镜台再返回，也可直接继续剪辑后主动生成成片。后续保存更新同一副本，不反复新建生产单。
- 首次保存遇到断网、重启或并发重试，只恢复同一创建操作，不产生多张副本。失败保留当前修改，不破坏原单；未完成复制有回执可恢复或清理，不将半成品列成可用生产单。
- 副本媒体引用具有自己的有效归属或受控生命周期保护；归档/回收原单不能使副本断链。命名默认可用“原名称（副本）”，仅为可撤销实现默认值，不新增命名弹窗。

### 4.5 删除范围与兼容

- 退役 `recordWorkspaceExportIssue` / `resolveWorkspaceExportIssue`、相应界面、状态/类型和读取字段，以及 `workspace_export_issues` 数据与有效 schema 依赖。旧客户端调用退役命令不得继续写入。
- 迁移前盘点并保留可恢复快照，明确待删行与依赖，再按依赖顺序移除。用户已确认删除，不用“保留只读”替代；本轮文档任务不执行删除。
- 同步处理 `workspace_delivery_current`、排队/完成校验、生产单删除函数、RLS/权限等实际依赖，不能只删 React 门槛。
- 移除 `CompletedQualityEvidence` / `completedReviewEvidence` 中本专项测试展示及调用。保留原验证报告；只清理因此确定失去用途的产品资源，不顺带删其他资料。
- 保留历史 ADR，实施时新增 ADR 标明替代范围；当前方案不把尚未实现的目标写成 `CONTEXT.md` 的现状。
