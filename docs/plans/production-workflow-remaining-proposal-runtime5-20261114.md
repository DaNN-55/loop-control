# 当前制作与旧流程全面收口方案

日期：2026-11-14。状态：Proposed，仅方案，未在本轮修改代码。依据[本轮实际生产与埋点结果](../verification/production-replacement-assessment-runtime5-20261114/REPORT.md)、当前源码、有效 SQL 及 ADR-0066／0068／0069。本文更新此前方案的剩余状态，不撤销或宣称完成既有实施规范。

## 结论：保留当前内核，逐段替换旧边界

无需整仓重写。当前新单已经不写旧审核包／镜头草稿／审批，v3、独立制作基准、精确交付来源、制作里程碑、声音使用、本机导出与资源观测均已有实现和专项证据。剩余工作主要是：修输出缺陷，把旧单和旧计划的必要能力接到当前工作区，退出第二套执行入口，收敛共享保护，再统一名称和生成当前基线。

「完全替换旧内容」应有明确范围：当前页面、模块和执行合同使用当前概念；旧资料通过版本化历史适配器读取／恢复。原草稿、音轨、审批、冻结输入、原包字节、已应用迁移和备份里的旧词继续保留。不能用全文零命中作为清理完成条件。

本轮本机导出并发、独立资源连接、满池采样、停用和跨覆盖期回归已通过，不再作为待修问题重复实施。短样例不是长期采样、重启或启用前验收。

## 此前八类现在怎样处理

| 原类别 | 现在用途与问题本质 | 建议改法与清理条件 | 保留理由／不改影响 |
| --- | --- | --- | --- |
| 1. 旧生成脚本链 | 已退役，不再是待清理工作 | 保持归档和退役栅栏，不重复处理 | 历史迁移文字不代表运行入口；改写原证据没有收益 |
| 2. 旧批准后初始化、复用及草稿继承 | approvals／draft 插入仍触发建草稿、继承混音和构图；是隐式业务结构，不只是命名 | 将必要历史转换集中为明确、同事务的接入操作；覆盖原镜头身份、草稿、音轨、混音和构图后，随旧批准执行退出删除触发器及函数 | 新单不用不能证明旧作品不用；误删会使旧编辑丢继承信息；长期保留则维护隐藏动作 |
| 3. 旧任务完成组包 | tasks 状态变化仍触发旧分镜／视觉包登记，同时承担原结果核验 | 拆开租约／attempt／冻结输入／文件回执校验与旧审核投影。为未知、在途、迟到和已验证结果规定承接路径，再删除纯旧组包动作 | 停新领取不等于旧请求已结束；误删可能丢证据或失去错误结果拒绝，禁止用重发恢复 |

| 5. 空扫描与旧预检 | 空扫描阻止自动续跑；旧预检验证 Owner 并登记时间，两者职责不同 | 随旧扫描／Runner 退役移除 `script_production_scopes()` 和 `record_episode_worker_preflight`；当前连接、文件、执行能力预检继续保留 | 本轮未发现当前源码消费者，已是优先候选；但还需最终启动／恢复／消费者退役验证。不能按 preflight 词批删 |
| 6. 旧 v2 手动命令及读取 | 仍有第二套配置、绑定、旧审核渲染／交付；属于重复业务模型 | 旧计划先按原保存快照只读；需要继续制作时显式迁入当前工作区，核验脚本／计划 SHA、已绑定素材及来源，不重新套当前默认值。迁入后使用当前操作，整组退役旧命令和旧查询 | 尚未完成，是重要阻塞项。只删 HTTP 分支会让未接入旧作品失去操作；保留两套则长期维护两套规则 |
| 7. 共享 Worker／SQL 包装及旧名 | 当前领取和回执仍经过旧命名函数，`codexRunner` 实际承载通用媒体执行；结构与命名混合 | 先列资格、容量、公平、回收站／历史、lease、attempt、冻结输入、费用及未知结果保护映射，再合并重复层；随后统一职责名称和所有消费者 | 不能直接删。只改名降低理解成本，不承诺提速；漏掉任一层可能放宽保护 |
| 8. 历史、冻结保护及分散回退 | 原资料仍有恢复价值；当前核心多处同时理解两代字段，属于边界问题 | 按版本集中解码和来源验证，输出严格当前类型；完整备份与逐项恢复共用明确映射，原记录／字节保持。审批关联、过期口播失效保护先找到承接，再收敛旧触发 | 历史资料本身不是无用内容。此前关联恢复已有阶段修复，不再当未修缺陷；最终新旧恢复总矩阵仍需验收 |

## 旧计划接入是当前缺口，不应以保留兼容替代完成

当前 `ScriptProductionStore.inspect()` 先解析现主脚本，只在 v2 时读取保存计划；若脚本已换 v3，之前保存的计划可能无法经该读取显示。该判断来自源码，不是本轮已做行为复现。接入前应针对「原计划、现脚本、现工作区」三者不一致补实际用例，不直接把旧计划按最新脚本重新计算。

建议读取按保存记录及其原脚本版本提供历史视图；接入命令要求明确选择和准确版本，保存原计划、原解析绑定及来源证据。有现工作区时先保留当前编辑，冲突不覆盖；跨单素材经当前核验导入并记录复用来源。旧连接、预算与整期授权只作为历史证据或预填，不得自动消费、生成或重新请求供应商。未采用候选、原音轨和未知请求仍保留。

原 HTML、原生 SQLite、旧排版子版本、逐项历史和完整备份有阶段验证记录，但「当前 v3 新单通过」不能替代「只保存旧计划、尚无当前工程」的迁移验收。

## 当前类型、名称和入口如何统一

| 范围 | 建议目标 | 实施方式与注意事项 |
| --- | --- | --- |
| 当前制作身份 | 当前接口必须有 `preparationRevisionId`；旧包字段只在历史适配器里解释 | 数据库内部记录已要求独立基准，但对外 `ProductionWorkspace` 字段仍可选，核心仍有 `preparation_revision_id ?? storyboard_package_id`。先证明旧数据转换，再移除当前核心回退，不只改类型断言 |
| 通用执行器 | 如 `mediaTaskRunner`／`runMediaTask`，名称表达真实职责 | 同步导入、CLI、构建清单、prepared manifest、测试与文档；旧包字节不改。`generateOfficialVideo` 等底层 Provider 能力当前仍使用，不能因为同名旧 HTTP 命令而删除 |
| 领取与预留 SQL | 用资格、领取、租约、预留／拒绝等实际职责命名 | 在事务边界内收敛，不复制保护，也不机械塞成一个巨大函数。当前 `claim_input_task → claim_input_task_pre_lease → claim_next_worker_task_legacy` 确有调用，须保持允许／拒绝结果等价 |
| 原生素材显示名 | 使用「镜头 01 口播」等可读名字，用户手工名称优先 | 显示名与机器身份分开；不重建 clip ID、音轨 ID、路径、SHA 或冻结请求 |
| 草稿、候选、采用 | 页面明确当前输入、可选结果和工程实际使用内容 | 保存草稿不自动换片；预览／交付以实际采用工程为准；拒绝后重开和改草稿后导出实看宽窄 UI |
| 历史格式 | 独立版本化载荷、解码器和适配器 | 不给旧快照补字段冒充新请求；未知版本、歧义、错误 Owner 或来源拒绝／只读；原资料保留 |
| 其他旧 HTTP 家族 | 逐组核查旧镜头制作、Studio 审核渲染、QC 和旧发布入口 | 与当前 workspace 命令比较真实用途，将原作品所需操作迁入后退役。复用的原生编辑、媒体执行、产物核验和恢复模块保留；不能由当前页面零调用直接判全部无用 |
| `Episode`／`episodes` | 可保留，这是现行生产单实体名 | 若目标要求内部也统一为 `ProductionOrder`／`production_orders`，单独做跨 SQL、FK、RLS、API、类型、历史映射与备份的版本迁移。它是术语成本，不是本轮缺陷根因，不建议夹在常规清理中 |
| 类型和 clean SQL | 当前接口只描述当前有效合同，历史接口单列 | 最终前向迁移通过后生成有效 schema、类型和新基线；原已应用 SQL、ledger 与归档保持。新建、升级、回滚、整库／逐项恢复必须一致 |

这些是建议目标名称，并非本轮已接受的新公开合同。当前领域术语继续以 `CONTEXT.md` 为准。

## 建议顺序与完成条件

1. **修正式输出。** 先处理棋盘格；在实际部署所用 SDK 版本上复现与验收。该问题独立于旧 SQL 清理。
2. **完成历史计划与工程接入。** 只读原计划、显式迁入、有当前编辑不覆盖、原文件与未知请求保持；收紧当前独立身份，并完成新旧恢复矩阵。
3. **完成旧执行退出。** 当前 v5 门槛已在源码及原包检查中验证，但最终候选包还需启动、Worker、恢复验证；日常旧进程退出和部署另按授权操作。后续破坏性合同变化须提升执行协议，不能永久允许早期过渡包。
4. **成组删除旧执行。** 优先七拒绝 SQL、空扫描／旧预检和已迁出的六命令；再处理旧审批、组包与 Studio／QC 链。每组列准签名、实际目录依赖及保护承接，使用 RESTRICT，不使用 CASCADE 绕过未知依赖。
5. **收敛共享保护并统一命名。** 逐项映射当前允许／拒绝场景，保留 Owner／ACL／RLS、容量／公平、lease／attempt、冻结输入、确切文件、费用和未知请求保护。行为与名称分批审查，不能靠放宽校验得到绿色。
6. **生成最终类型／基线并总验收。** 完整默认套件、真实宽窄 UI、新单端到端、旧格式与历史恢复、权限／故障／崩溃、运行版本门槛、有效 SQL 依赖对账。最后再做独立的采集启用前验收和必要长期采样；不要以本次 29 项代替全项目完成。

完成后的目标是一套当前制作模型和操作入口；旧作品可读、需要编辑时明确接入；原包保留为证据而不成为永久执行依赖；当前名称表达真实职责，旧资料仍可恢复。**当前尚未达到全面清理完成状态，但已无需重建现有制作内核。** 本轮不执行上述修改，不提交、不推送。
