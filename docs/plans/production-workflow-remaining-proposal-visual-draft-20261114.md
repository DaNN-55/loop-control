# 当前制作与旧流程的剩余替换方案

日期：2026-11-14。状态：Proposed，本轮只测试、核查和记录，没有实施以下改造。依据：[本轮隔离生产与埋点报告](../verification/production-replacement-visual-draft-assessment-20261114/REPORT.md)、固定当前源码、隔离有效 SQL 及 ADR-0066／0068／0069。本文更新剩余事项，不撤销其他实施任务，也不把专项测试通过视为完整目标完成。

## 建议结论

**保留现有内核，分批替换旧边界，不整体重写。**本轮新建生产单已经能避开旧审核包、旧草稿及旧审批，完成原生编辑、重开、实际导出和交付。Owner 事务、文件身份、执行快照、候选采用、Worker 租约、确切导出与恢复体系仍有实际价值。

还没有达到「旧执行链全部退出」：旧作品接入的界面与恢复矩阵尚未收尾，后端还接受第二套旧制作命令，数据库保留旧触发动作和执行合同，共享实现仍夹着历史术语。大量全文改名会掩盖这些边界，并不能完成业务替换。

目标应当是：当前操作和执行只依赖一套当前模型；旧来源只经过明确版本的读取、接入和恢复适配；不再支持执行的旧入口被准确退役；当前函数、类型和显示名表达实际职责。历史原文、旧包、SHA 输入、音轨、草稿和归档迁移继续保留。

## 埋点怎样继续

这次已经能和制作同单测试，不需要合并另一分支。新单的 8 个制作里程碑、两次口播采用、3 次声音使用、一次导出起止及真实 Worker 交付均能对账；重开不增计数。相关停用、不补造、Owner／lease、事务失败、未知请求不重发、质量冻结和资源边界另有隔离测试。

无需重做一套采集。后续补旧来源 UI／恢复、复杂声音与大工程场景，给现有只读汇总增加明确查询入口／Dashboard；最终代码、迁移和运行包一致后再做启用前验收。本轮没有测试真实供应商账单、视频生成／轮询／下载或长期运行重启。GPU 与供应商实付继续未知；主机 CPU 不是单任务消耗，阶段驻留包含等待。

棋盘格能得到 `delivery_completed`，说明这个事件目前证明通过了既定技术／来源校验，不能理解成视觉审美及所有业务内容已正确。应保留这个范围说明并补输出缺陷回归，不改名掩盖验收缺口。

## 推荐分批顺序和完成标准

1. **先修实际输出与选择显示。**棋盘格单独处理；候选初始区间、预览和采用摘要一致。以实际文件／真实帧及页面操作验证，不通过放宽保护解决。
2. **补齐旧作品接入。**完成来源 UI、剩余原设置和全来源完整备份＋文件／逐项／不同来源 Owner 恢复。已有编辑优先，待确认不伪造批准，未知不重发，原来源保持。
3. **退出旧执行消费者。**核对活动进程和任务，明确过渡运行包停止支持范围并提升执行合同。原包保留为证据；日常部署、重启另行授权。
4. **成组退役第二套业务。**删除无用旧写命令、拒绝 SQL、空扫描／预检和仅服务旧执行的编排。前向迁移精确 RESTRICT 删除；残留依赖使迁移失败，不能 CASCADE 扫掉保护。
5. **收敛公共保护与历史边界。**将回执验证和旧组包副作用分开，合并领取／预留真实职责，旧协议集中到适配器。用允许与拒绝的行为矩阵证明等价。
6. **统一当前命名、类型和基线。**在职责稳定后一次更新当前导入、API、CLI、manifest 和显示名；核心禁止重新引入已退役标识。用编译、schema 对比和调用清单持续检查，违规时回到对应适配边界修正。
7. **最终全量验收。**完整默认回归、相关集成、实际 UI、原生保存／输出、升级回滚和各种恢复、Owner／ACL／lease／费用／未知请求保护及最终埋点对账。每批先验收再推进，最后才安排日常切换。

这是局部重构、数据与协议迁移、最后统一命名的组合。能彻底退出的是无用执行入口、旧自动动作和重复业务；需要继续保留的是有用保护、稳定身份、原历史及其恢复能力。没有证据承诺这轮改名带来明显提速；收益主要是行为更一致、误用更少、后续维护更清楚。
