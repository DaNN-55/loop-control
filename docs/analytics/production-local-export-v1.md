# 本机导出生命周期与资源观察 v1

当前实施规范 C2，迁移 195；尚未应用日常或启用日常采集。保持 ADR-0069 里程碑、原 Worker 事件和费用语义。

## 实际导出事实

通过当前 Owner 命令校验工程、来源和文件后，在真正启动执行器前取得 PostgreSQL 开始时间。渲染及技术核验完成、当前导出结果登记后，在原业务事务中持久化 `local_export_started`／`local_export_finished`；纯前置拒绝为 `local_export_rejected`。开始事件的时间是实际执行边界，事件提交时间在结果之后；它不是可独立查询的实时进度，也不代表崩溃的执行一定有结束事实。

推迟写入避免渲染期间占用匿名日汇总行锁，从而阻塞同 Owner 的其他生产单。结果事务失败时不产生虚假的成功统计，原导出、内容指纹、文件和确认保护保持。

`local-export/v1` 只含关联 ID、版本、哈希、阶段、时间和固定结果原因，不含正文、路径或秘密。实际执行失败与前置拒绝分开，精确命令回执重放不增加事件。关闭期间不采集；完成时已停用的整次导出不产生生命周期事件。跨覆盖期或执行前尚未开启时，可以观察到当前覆盖内的结束，但开始未知、时长为 null，不补造开始或精确耗时。

## 当前应用实例的活动

每个 `LocalEpisodeCommands` 实例有独立活动计数，以认证 Owner 隔离。真实执行及核验期间递增，成功／失败均在 finally 释放；测试生产单排除。未启用采集时计数仅在内存中存在，不产生统计；以后启用可观察当时仍在执行的活动，但不补录此前资源或生命周期。

实例不同，即使恢复了相同 Owner UUID，活动也不混合。进程退出后活动自然消失，不能凭活动消失自动认定导出失败或重试。真实崩溃状态仍由现有业务恢复与文件证据判断。

## 资源样本

运行时仅在显式启用资源采样时建立独立数据库连接池，避免等待被导出占满的业务池；关闭先停止采样再释放该池。Owner 数据库开关仍独立检查，原 30 秒频率、CPU／内存数值校验、采样时间窗口、未知 GPU 和保留期不变。

`production_metric_resources` 仍是一份主机 CPU／内存样本。195 的 `production_metric_export_resources` 只对同 Owner／同时间样本注记当前应用实例的 `active_exports`；沿原资源记录删除，不关联被业务事务锁住的工作区或生产单。新窄写入函数复用原严格写入合同，不扩大原函数字段白名单；重复样本必须同时保持资源内容和导出数量一致。Worker 的队列、运行和资源等待不增加本机导出数量，CPU 日汇总不重复写。

汇总 `maximumLocalExports` 和 `localExportCountKnownSamples` 仅来自真实注记；旧样本缺注记表示 unknown，不补为零。`localExportAttribution` 是 `current_application_instance`，CPU／内存仍是主机观察，二者均不是单任务消耗。多个应用实例不能直接相加主机资源样本。

主机时间允许略领先数据库；只读统计快照排除其观察时刻之后的样本，不能把暂未进入窗口的样本当丢失。测试按实际已存样本的数据库时间边界等待，不放宽数量断言。

启用采集时，原覆盖观察对正在被业务事务锁住的生产单／排队任务使用受控的 `SKIP LOCKED` 读取，避免统计外键等待反过来阻塞导出。只跳过统计起点观察，不改变业务锁、Owner、领取、租约或执行资格；跳过的对象没有虚构的初始锚点，后续真实事实按新覆盖期续记。其他未锁对象仍按原合同观察，原函数权限不变。
