## 事实与汇总

- `177-production-metrics-collection.sql` 新增 Owner 隔离的统计表、默认关闭开关、覆盖周期、最小触发器和维护函数。普通应用只有按 Owner 隔离的只读表权限；私有追加函数不向 Owner／Worker 开放。Worker 写入保留当前 task／attempt／lease 校验。
- `productionMetricWrites.ts` 在真实保存后的工程使用变化记录采用和撤回；音频以实际可听主声路由判断，保留的静音旧轨不算采用。原候选首次决定表与业务判断继续保留。候选事件不记录口播正文或路径。
- Provider HTTP 观测只记录操作类型、独立请求标识、状态码和时间。创建、查询原任务、下载分别计数；已记录 HTTP 响应不代表已生成可用文件。视频远程任务登记与图片／口播已验证产物回执分开记录。
- `readProductionMetricsV2` 在一个 Owner 只读、可重复读事务中组合 A/B 与 C，保留原 `readProductionMetrics` 返回语义。没有安装 C 时 collected 为 null，不要求调用不存在的 SQL 函数。未新增 Dashboard 或统计页面路由。
- C 明细与匿名日汇总分别输出。匿名日汇总包含已永久删除生产单的历史计数，不能与 A/B 的保留对象指标相加。明细过期、停用或启用前不提供伪造的精确分位数。阶段驻留包含 Owner 等待；可领取后的排队时间同时包含容量与调度等待，不能当成人工耗时或纯容量等待。
- CPU／内存是主机观测，不是单任务用量；跨进程重启的缺口由样本时间和覆盖范围判断，模块内 gap_seconds 不声称精确跨重启持久化。资源日汇总保留已知样本数、和、峰值及缺口，缺测不补零。

## 跳过的语义冲突

图片候选现有 input_fingerprint 包含 authorizationHash 和 retryOfTaskId。授权身份变化也会改变指纹，不能据此证明图片提示或素材发生变化。

处理建议：本阶段图片 input_changed 保持 null，只记录明确的重试关系和原任务客观状态。未来若需要细分图片重试原因，可另行增加不含授权身份的语义输入指纹，并保持旧请求快照不变。

实际影响：本轮不能自动区分图片的同输入恢复与输入变化重试；请求数、估算、费用预留、采用记录和当前图片制作功能仍可使用。不把该缺口补为 false，也不把所有图片重试算作质量返工。

原编号冲突按本轮授权处理：主工作区175／176保持，C顺延为 `177-production-metrics-collection.sql`，ADR顺延为0057。完成最新并行基线与非空176→177隔离升级验收后回迁代码，不应用日常。原独立C验收材料保留为历史；最新回迁证据见下方报告。
