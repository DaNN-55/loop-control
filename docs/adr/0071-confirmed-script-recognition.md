# ADR-0071：确认识别结果作为制作依据

状态：Accepted。2026-11-17，用户纠正此前的“修改脚本建议”设计，并明确允许整部视频仅一个镜头。本决定取代 ADR-0070 的建议采用流程，沿用其独立连接、密钥和持久回执边界。

后续：同日确认的极简脚本工作区与一次审批产品流程见 ADR-0072。本记录的旧无损识别合同和回执保留，不再作为当前脚本页面的交互要求。

用户关心可确认的镜头与字幕，不必先把原稿改为固定模板。本地可识别的输入继续走原规则；本地诊断失败时，显式调用已验证的 GPT／DeepSeek 连接，直接返回标题、已有设置、镜头口播／字幕／画面意图和提醒。连续场景默认一镜到底，不按空行、字数或句号凑分镜；明确切镜／场景变化保留原顺序。没有的画面提示不编造，未指定画面来源为暂未选择，缺少信息不能可靠识别时说明原因。

镜头与字幕预览展示模型结构，用户先确认识别结果，再确认脚本或修订；原文在此之前不改变，不再展示修改建议或采用改稿按钮。识别绑定完整原文和脚本基准，改稿或换基准立即失效。浏览器刷新后需再次读取回执并核对，不能从浏览器缓存直接授予保存权限。

新合同 `script-recognition/v1` 使用 `/api/local/script-recognition` 的 `recognize` 动作，旧格式建议写入口返回 410，旧回执保持历史。Provider 仍固定官方 Responses URL；输出严格 JSON Schema、本地字段／内容值／口播顺序和制作合同校验，不执行模型指令，不自动发送重试或切换服务。原稿、模型、提示和用量按原回执持久化。

确认脚本调用 `confirmRecognizedScript`，仅提交生产单、当前基准、原稿、请求 ID 和修订原因。后台从同 Owner、同单、同基准、相同原文且完成的新合同回执读取结构，客户端不能提交任意分镜 JSON 冒充结果。完成同一次事务的脚本登记与确认关系，保存不可变的脚本 SHA／原稿 SHA 和模型请求引用。

为复用现有制作、字幕和工程流水线，确认结构由程序确定性转换为内部 v3 制作输入；它不作为给用户修改原文的建议。原始输入保留在模型请求中，迁移 208 的确认关系固定到实际主脚本版本，引用保护原稿回执不被单独删除。已有保存／启动分步恢复、Owner、CSRF、运行任务、归档、历史和回收站保护保持。

验收必须覆盖：本地路径、连续文本一个镜头、明确多镜头、无原文改写／遗漏／倒序、未确认不保存、改稿失效、伪造／跨 Owner／过期回执、真实数据库和文件的保存－启动－分镜台／字幕衔接，以及实际页面。不能以 mock 的模型效果冒充真实供应商结果。
