# ADR-0072：原文与拍法分开保存，脚本工作区一次审批

状态：Accepted。2026-11-17，用户确认完整页面原型和讨论方案后授权实现，要求分支验证通过后再迁移日常环境。本决定取代 ADR-0071 的“仅识别、先确认识别再确认脚本”产品流程；旧识别合同、回执与历史保持原语义。

## 用户流程

普通原文、含 Markdown 的非模板文字和有效 v3 脚本都能直接继续。有效模板沿用明确镜头与设置；其他原文视为一个完整片段，不按空行、字数或标点强拆。直接路径不调用模型；用途不明确时暂不启用口播和字幕，在后续制作方案说明安排，分镜台现有开关继续有效。

Owner 按需选择“优化拍法”，只提交一份推荐方案；默认保留原文事件、已有台词/字幕及顺序、明确制作设置和有效总时长，允许创作景别、运镜、衔接和镜头组合。独立的大胆改编入口与新请求模式已于 2026-11-18 按用户要求退役；既有改编记录保留读取、手动修订和采用。修改建议绑定上一请求身份，不能在无新授权时扩大为改编。

“采用并继续”是唯一的拍法审批动作。程序内部保存、转换、启动不额外要求格式确认。审批仅登记当前展示的方案，不自动调用图片、视频、口播或其他素材生成。

## 数据与执行合同

新合同为 `script-studio/v1`。旧 `script-recognition/v1` 的无损校验不放宽。新请求使用已验证的独立 GPT/DeepSeek 连接及固定官方 Responses 端点，结构化输出经本地校验；不执行模型指令，不调用工具，不自动重发未知请求或更换模型。

`/api/local/script-studio` 的 POST 固定原文、脚本基准、目标时长、优化/讨论模式、修改要求、上一请求、连接及模型。持久发送标记先于唯一网络发送；同一请求或未改变的输入恢复已完成/未知回执。回执写入失败后也不再发送。GET 只读取同 Owner、同生产单、同脚本版本的原文，验证实际脚本文件 SHA；已完成/归档可以查看，写入保持只读保护。

确认命令仅接受原文、基准、目标时长、选填备注与请求 ID，不接收客户端可信分镜 JSON。服务端从相同 Owner、生产单、原文、基准、时长的完成回执读取方案；直接路径由本地程序构造。修订原因自动记录，备注选填。保存、启动仍使用已有分步恢复机制。

迁移 209 增加不可变的 `script_studio_confirmations`，保存原文及 SHA、实际脚本 SHA、目标时长、批准方案和模型请求身份。原文与确定性 v3 制作脚本分开，读取原文不以内部模板替换用户输入；旧确认可经原识别回执恢复原稿。工程、媒体和旧版本不删除。

## 可执行约束

时长以输入目标优先，其次原文明确时长，最后本地预计值；模型请求与本地验证使用同一有效总时长。范围为 0.1–3600 秒，最多两位小数，镜头之和必须一致。此为逻辑镜头与剪辑时间，不代表某个供应商单次生成时长；不为适应供应商限制强制拆镜。原生工程按累计余数取整到帧，避免多个小数镜头分别四舍五入改变总时长。

已有非拍法设置缺失时确定性补回，反转时拒绝；逐镜字幕、口播启用设置保留。Owner 显式要求调整口播或字幕时才允许对应变化。运镜合入实际视频提示，支持的动画/转场字段进入既有制作设置；不把仅有展示文字当作落地。视频提示与运镜合计超过上限时拒绝，不静默截断。

批准方案的口播开关写入原生镜头的真实启用标记，字幕依既有合同首次组装；依据新方案重规划时也组装批准的字幕开关。后续人工开关不被读取或刷新重置。

每个启用口播的镜头都必须有明确口播正文，每个启用字幕的镜头必须有明确字幕或跟随的口播正文。预览与执行共用逐镜开关/字幕正文函数；不能把内部用于承载原稿的画面说明或标题当成未经审批的口播、字幕。普通文本中明确的字幕正文独立保留，关闭口播不丢失其字幕内容。

全新工程与保留的原生工程使用明确边界：已有原生编辑时不重新组装字幕，但根据新审批方案创建的 fresh project 不因旧 workspace 行曾被编辑而跳过组装。静态图片匹配、候选注册与采用支持同一 3600 秒逻辑镜头边界；视频供应商的单次生成限制保持原样。

## 边界

新建/修订原文和 AI 输入统一最多 20000 Unicode 字符；旧的更大脚本仍可查看。文件选择沿用 2 MB 的读取边界，实际提交另受原文字符上限约束。模型对故事语义、视觉创意和表达质量的判断仍需 Owner 审批；结构与文字/时长校验不能证明创意一定更好。本轮不新增全自动素材生成、公共部署或额外依赖。

## 脚本确认页内手动修订（2026-11-17）

单镜头文字编辑通过 `/api/local/script-studio` 的 `editShot` 创建新的 completed 回执，绑定 Owner、生产单、脚本基准、原文、目标时长及上一回执；只允许标题、画面、视频提示词、运镜、口播和字幕文字。服务端复用制作合同验证，禁止更改时长、开关、来源和制作设置；不覆盖原回执，不调用 Provider，不写入模型 usage。原文和已有确认仍保留，采用仍仅提交回执身份。

仅修改画面／运镜等拍法文字继续沿用普通优化约束；改写口播／字幕或在改编方案上修订时，明确保留手动内容变化及改编约束。继续优化始终携带当前回执，当前通过常驻聊天提出要求，费用说明按需显示；对话发送与采用为独立动作。页面提前读取连接目录并展示上次有效选择或唯一可用模型；多个可用模型且无有效选择时不得隐式使用列表首项。

## 常驻拍法对话（2026-11-18）

脚本确认采用正文／分镜／可收起的拍法助手三栏。上传、时长和历史位于顶部，采用和直接继续位于底部。模型选择与发送动作整合在聊天输入区；已有拍法后，提交新要求才生成新版。仅讨论使用独立的结构化回复合同，不产出可采用计划，也不触发素材制作；独立改编选项和二次确认已退役，新 `mode=adapt` 请求返回 410，不调用 Provider。

复用已有 `script_format_requests`，无新增数据表。每轮绑定上一完成回执，服务端恢复同 Owner、生产单、脚本基准、原文及目标时长的完整父链，自动带上最近的有效计划及按时间排序的交流。客户端不能上传可信聊天历史或分镜 JSON；刷新恢复只读，不调用 Provider。仅讨论和手动编辑也进入回执链，后续修改携带实际最新方案。正在处理或结果未知的请求只核对，不重发；失败保留本轮文字和旧方案。

历史用户要求同时进入模型上下文及本地口播／字幕等验证上下文，原文和时长硬约束不变。`turnInstruction` 保存本轮实际输入，`data.instruction` 固定本轮包含历史用户要求的验证依据；历史模型建议不扩大授权，过去的大胆改编不授予本轮改编权限。采用仍只读取完成且包含有效计划的同基准回执。

对话按脚本版本、原文和时长分开，改变这些输入会恢复对应上下文，不混用旧方案。采用产生新脚本版本后使用新上下文，旧回执保留。发送快照继续限制为 128 KiB，父链最多读取 256 个回执；超过边界拒绝，不静默丢弃早期要求。未发送的聊天文字使用现有本机草稿机制，与 Owner、生产单和脚本版本隔离。

## 聊天控件收敛与推理配置（2026-11-18）

拍法提醒并入顶部“拍法说明”，不在镜头列表底部重复。时长输入内部显示时钟、自动时长占位和秒单位，保留无障碍标签与校验；次要说明留在输入提示。聊天输入底栏统一为供应商图标／模型、推理强度、聊天设置和发送；设置内切换调整拍法／仅讨论，不自动提交。旧聊天草稿中的独立改编选择被丢弃，未发送文字与交流方式保留。

`reasoningEffort` 按所选模型原生合同验证，实际传入 Responses API，写入请求快照并参与去重。关闭沿用原先 `none` 行为；显式 `none` 规范化为缺省，复用既有默认请求身份。非默认推理值形成独立请求；处理中／未知结果继续只核对，不能通过改配置重复派发。配置按 Owner 与供应商／模型保存本机偏好，连接和模型切换不调用 Provider。

当前 OpenAI 固定模型原生档位为 none/low/medium/high/xhigh/max；DeepSeek 为 none/low/high/max，不展示兼容别名。开启推理的讨论回复预算为 16000 output tokens，关闭时仍为 3000；生成拍法保持 16000。没有真实供应商调用验收，外部模型支持以文档和供应商实际响应为准。[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[DeepSeek Responses API](https://api-docs.deepseek.com/api/create-response/)。

## 镜头删除与型号扩展（2026-11-18）

镜头操作使用“…”菜单。`deleteShot` 与手动文字修订同样绑定 Owner、生产单、脚本基准、原文、时长和上一回执，产生不可变新候选；至少保留一镜，不改原文或旧回执，不调用 Provider。剩余镜头按原时长比例分配固定总长到 0.01 秒，采用后才进入制作；逐镜开关与剩余文字保留。`modifiedShotIndexes` 作为回执元数据展示人工修改及删除后的时长变化，旧人工回执可由可信父链恢复；变化说明收进拍法说明。

GPT-5.6 的 Luna／Terra／Sol 及官方 gpt-5.6 别名、GPT-6.1 Sol／Terra、DeepSeek Flash／V4 Pro 共用已登记的 Responses 合同。新增迁移 210 扩展回执型号约束，旧数据及默认启用选择保留；新增型号由 Owner 在连接模型页启用。连接验证读取模型目录，任一已适配型号可完成只读资格验证。GPT-6.1 Sol 原生不支持 none，默认 low 并在去重前规范化；其他既有默认 none 请求身份不变。型号不因字符串前缀自动放行。

## 聊天呈现与配置反馈（2026-11-18）

用户消息为无标题的右侧绿色气泡；模型回复为灰色气泡，图标和名称读取该轮回执实际供应商／型号，不随当前选择变化。人工修改显示本地消息，不冒充模型回复。上下文说明统一放在使用帮助，不占聊天首屏；拍法说明默认短预览，完整摘要、原文安排和提醒按需展开，阻断性提醒默认可见。

推理强度用带标签的原生离散 range，只展示型号原生档位，中文 aria-valuetext 与当前等级同步；改变档位不发送。交流方式触发器同步切换图标、名称与占位说明。历史复用标准图标和可关闭的非模态弹层，版本／拍法／备注分组；还原需确认，取消后保留备注并返回历史。两种交流方式的模型调用、上下文、回执及采用合同不变。

## 粗稿中的逐字口播选段（2026-11-18）

原文没有明确口播／字幕字段时，Owner 在修改要求中明确口播安排，可从原文选择逐字连续的片段（如粗稿里引号内的台词）；其余原文继续由画面表达。未明确提出口播安排、改写或重排的选段仍拒绝，原有明确口播／字幕不可借此遗漏。默认优化不再提示已退役的独立改编入口。真实供应商输出与复现／复核证据见 `docs/verification/script-real-models-20261118/REPORT.md`。

## 修订模式与历史输入边界（2026-11-18）

当前方案校验及内容修订回执使用 `optimize`／`revision`，不再用旧独立改编名称描述人工操作。手动修改文字、删除镜头仍生成新的待采用回执，沿用原时长、原文和父链；只有存在内容变化时记录 `revision`，仅修改拍法且不改变原文内容仍可记录 `optimize`。模型请求仅允许 `optimize`／`discuss`，不能借 `revision` 申请内容改写。

旧 wire 值 `adapt` 和旧聊天草稿字段只在 `src/scriptStudioLegacy.ts` 集中识别：旧回执读取及采用时映射为当前 `revision`，旧草稿只恢复文字与交流方式，丢弃旧开关；旧独立改编新请求继续拒绝。历史数据库行、结果、请求ID、快照、去重版本与未知结果恢复合同不改写。旧按钮和说明的无调用翻译删除，历史模型回复与人工文字原样保留。

## 独立会话和参考附件（2026-11-18）

用户可在拍法助手输入框右上方通过虚线加号创建独立对话，编号单行显示约4格，滚轮横移和键盘可访问。新对话从同一原文、时长出发，不继承旧消息、用户要求、方案或附件，不自动发送；旧对话保留并可切回。迁移211新增空会话元数据表，旧未带会话ID的回执只读兼容为隐式会话；这取代上文早期实现“无新增数据表”的描述，不重写既有回执。显式会话必须延续可信最新完成父链，未知请求的防重边界覆盖同一原文/时长下全部会话。

附件按钮位于推理图标左侧，弹层只留一个紧凑上传槽；点击槽位调用系统文件选择，聊天及槽位均可拖入。支持PNG/JPEG/WebP、PDF、UTF-8 TXT/Markdown/CSV/JSON及普通DOCX。上传即通过已有Owner材料登记进入本期素材，移除待发引用不删除素材，发送才调用模型；同对话累计携带已发送附件，新对话不携带旧附件。

每轮最多4个、单个10 MiB，同对话最多16个/24 MiB；提取文本单份20000字符、累计40000字符。DOCX仅读取有界文字，不读取内嵌图片或执行链接/宏/实体；PDF由显式支持的OpenAI型号以input_file读取，DeepSeek不隐式调用另收费的文件解析端点。图片使用真正input_image，普通文本及DOCX作为标注为数据的文档内容。所选型号不支持时明确拒绝，草稿保留。

材料引用只保存修订ID、SHA、MIME、大小和名称。服务端发送前重新验证Owner、生产单、材料身份及真实文件；原文件内容只在派发期间读取，快照不保存base64或文档正文。专属上传标记在材料发布前应用附件校验，既有普通reference上传合同不变。附件、文档内容及图中文字不作为系统指令；与原文冲突时保留原文并提示Owner，不自行改写。

未发送文字和附件草稿按会话隔离；同一浏览器页内的非秘密提交标记用于刷新后确认已经完成的本轮，按可信新回执及不可变附件字段匹配才清理，避免重复发送或误删更新的草稿。未知结果仍只核对，不自动重发。人工编辑、删除镜头及采用继续沿用不可变回执合同。

## 自由交流与极简脚本入口（2026-11-18）

“仅讨论”改为“自由交流”，保留持久模式值discuss与既有草稿、回执、父链和跨模型上下文。自由交流可回答知识、技术、日常问题、分析附件或给创作/改写草稿，不要求关联视频拍法；原文、时长、当前计划和历史只是可用背景。旧回复的拍法专属角色说明不限制新自由交流。回复仍只返回文字，不登记可采用计划，不改原文、制作设置或工程，不声称已保存/采用。用户指定格式在reply内容里满足，外层JSON回复协议保留，避免DeepSeek在“只输出代码”时绕开解析合同。

自由交流实际输入标记mode=discuss，以script-studio-free-chat/v1区分新提示语义，回复JSON schema保持script_studio_discussion_v1。原script-studio-direction/v2生成合同、原文/时长校验和批准身份不变。旧同一请求ID仍恢复原回执；旧合同处理中/未知请求仍按原身份核对，不重发。新请求ID不复用旧窄角色的已完成讨论结果，旧数据不迁移、不改写。

上传脚本改为正文标题右侧的图标入口，原生文件选择、TXT/MD边界及拖入行为保留；桌面与粗指针布局沿现有容器规则适配。附件保留可见标题和关闭按钮，标题行与上传槽各占完整一行，右边界对齐；新开对话保持强色1px虚线，推理标题底部间距仅在自身弹层归零。
