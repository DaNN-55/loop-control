# ADR-0015：四步制作与嵌入式整期工程

- 状态：Accepted，分票实施中
- 日期：2026-10-29
- 依据：Owner 已确认 A 版及规格 #152；首票 #153。

## 决策

目标可见流程为脚本确认、素材准备与匹配、剪辑工作台、检查与交付。首次生成提前，剪辑中允许局部重生；OpenChatCut 统一拥有可编辑时间线，Loop Control 负责材料、任务、来源和生命周期。最终批准绑定实际交付文件。此决定逐步替代 ADR-0014 的六步界面和 ADR-0012 中受影响的人工关卡安排，不改变它们的归属、不可变历史、凭据或付费授权约束。

T01 仅在已有完整输入路径增加真实嵌入式 Studio。原六步导航、全部镜头准备门槛和既有独立入口暂保留；占位、生成前移和新交付顺序由后续子票接入，不能为开工程伪造确认。

嵌入适配由 Loop Control 持有，不改写第三方源码。宿主通过限定 origin、窗口、通道及 projectId 的消息协议请求选择和刷盘，编辑状态来自真实编辑器。保存须先等待编辑器持久化成功，再经 Owner/CSRF 本机命令验证当前来源、工程身份和预期工作文件指纹。旧窗口或失败刷盘不能报告宿主保存成功，也不能覆盖新的工作版本。Studio 自身保留原有浏览器工程所有权及冲突处理。

后台返回带 `lcBridge=1` 的真实适配运行时地址后才启用嵌入；后台尚未重启的兼容窗口沿用旧入口，避免热更新前端等待不存在的桥。

工作版本仍可编辑；冻结提交仍生成不可变版本。重新打开复用已有工程，不自动重建或覆盖人工编辑。四步默认切换在最后集成票完成，浏览原页面不自动改变业务状态。

## 验证

复用 Owner 原生 HTTP、PostgreSQL、真实 Studio project store 和本机媒体边界。隔离夹具测试打开、修改、保存、刷新、Studio 重启，以及失效指纹、错误身份、Owner/CSRF、迟到消息和保存失败。真实浏览器验证加载、镜头选择与状态回传；不以 iframe 出现、源码字符串或接口排队成功代表实际保存完成。
