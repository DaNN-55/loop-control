# Episode 采用归档与 Owner 永久删除两级清理

普通业务清理使用归档，避免误删生产历史和本地产物；只有 Owner 才能发起永久删除，并且必须二次确认、先展示将清理的本地路径，再删除 Episode 关联的任务、产物索引和审计记录。这保留了日常操作的可恢复性，同时为测试数据提供明确的彻底清理路径。

2026-10-27：Owner 明确要求已归档的普通生产单也可永久删除，取消仅限测试生产单的限制。归档仍保留全部数据；永久删除继续要求 Owner 权限、标题二次确认、路径与版本校验，并拒绝运行中任务、有效资产锁或并发任务操作。先暂存生产单目录，再删除关联数据库记录，提交后清理目录；文件清理未完成时保留重试入口。账号仍要求关联生产单数量归零后才可删除。该功能变更不自动删除现有账号、生产单或历史资料。

2026-10-27 补充：旧生产单缺少 `input_episodes` 管理标记时，也允许 Owner 在归档后清理，但不为此补标记或启用生产执行；明确标为只读历史的生产单继续受保护。打开确认框先读取服务端删除计划，展示部署映射后的实际目录；提交使用同一计划的路径、版本和确认文本，失败在框内显示。删除范围是关联业务记录及当前部署的 `episodes/<id>` 整个目录，账号目录其他内容、外部盘旧副本、原始素材与历史备份不自动删除。数据库已删除而文件清理未完成时，页面明确提示到系统维护重试。

2026-10-27 外部盘副本清理：后续永久删除包含当前生产单目录及当前部署映射中可确认的同一账号、同一生产单 ID 的旧副本目录。确认框列出完整清单，提交绑定目录清单、设备/目录身份与版本；目录变化或外部盘未挂载时拒绝继续。仅访问已登记媒体位置，不扫描磁盘；原始素材库、其他生产单和未列出的目录不动。所有目录先分别暂存，提交失败时恢复已移动目录，提交成功后逐个清理；全部完成后才确认文件清理完成。旧待清理回执继续按原确认范围处理，不追加外部副本。

2026-10-27 空目录与标题链接收尾：永久删除提交后，在每个已确认账号资产根内清理精确指向 `episodes/<id>` 且目标已不存在的「按标题浏览」符号链接，兼容相对和绝对目标；不按标题文字或名称片段匹配，也不跟随导航目录链接。已登记旧副本仅剩该生产单标题链接时，同样纳入本次删除计划。只用非递归空目录删除清理空的「按标题浏览」、`.deletion-staging` 和 `episodes` 容器，账号根目录保留；其他生产单、其他失效链接、素材库和历史资料不动。原路径被重新创建时保留并报告待清理；链接权限或边界检查失败沿用待清理回执，重试即使暂存内容已删除也继续收尾。数据库事务失败只恢复生产单目录，不提前删除标题链接。旧回执仍仅清理原账号位置，不追加外部盘范围。

2026-10-27 账号空目录收尾：账号永久删除数据库事务提交后，尝试清理该账号所有蓝图记录中的资产根及其已登记部署副本。只对提交时已确认为空、目录身份可核验且没有其他账号蓝图引用的位置保存计划；使用非递归 `rmdir`，任何文件（包括隐藏文件）、子目录或链接都使账号目录保留。不递归清空目录，不移除媒体根或账号父容器，不扫描未登记位置，不修改历史资料。全账号引用检查跨越调用者的账号可见性限制，只返回是否被引用，并在实际清理前重新检查。符号链接、目录替换、外部盘不可访问或权限不足时保留目录；同一请求重试仅尝试原计划中同一设备/节点的目录，不追加新位置。保留原公开布尔响应和旧幂等回执行为；本轮不追溯清理已删除账号，也不为非空目录安排后续自动删除。

2026-10-29 历史入口永久删除：Owner 明确要求历史清理预览可同时删除选中条目的真实生产单和独占媒体。新增专用 `planHistoryDeletion / deleteHistoryEpisode` 流程，不改变普通生产单“先归档再删除”的入口合同。历史入口先显示服务端核查的完整目录、独占内容库文件、留存记录及共用/依赖保留数量，必须勾选不可恢复说明并输入服务端要求的完整名称；最终请求绑定业务/历史版本、目录清单与文件身份。若仍有真实生产单，最终事务内完成归档及删除；历史只读执行栅栏不会被提前解除或转为可执行队列。运行任务、资产锁、并发操作、其他生产单的对象/路径引用或文件变化均拒绝删除。

历史记录和关联可删除部分在同一数据库事务中清理，保留共用及受保护内容；新增 Owner 范围的删除标记防止保留的依赖或后来导入的旧关联重新显示该条目。生产单目录沿用暂存、事务回滚恢复、提交后清理与回执重试；内容库文件检查摘要、设备/节点身份、数据库引用及留存文件中的间接引用，保留引用链闭包。提交后再检查新依赖，发现新引用则保留内容并登记为业务依赖。文件清理未完成时继续使用系统维护的原重试入口，不将数据库提交误报为全部文件删除完成。仅实现和隔离验收不构成删除真实条目的授权。

2026-10-31 新旧层级的精确文件清理：归档继续只改变可见性，不移动文件。永久删除沿登记的实际生产单位置盘点，以具体业务登记、冻结输入或已核验的 Host / SDK 协议证明文件归属，并绑定设备、inode、大小和 SHA256。目录名、已知子目录及旧迁移来源本身不授予删除权限。计划同时列出删除文件、保留项和原因；新增内容、文件替换或引用变化使原确认失效。手放、共享、硬链接、符号链接、未知原生项目与缺少证据的文件保留；保留文档引用的文件按引用闭包一并保留。

本轮取代上述 2026-10-27 的整目录、部署副本及全部历史蓝图空根清理规则：生产单默认只确认统一解析器给出的当前实际目录。迁移 / 恢复保留源不因 logical alias 获得删除权限；在线旧源整树保留，离线旧卷不阻断当前目录删除。账号空目录也只使用当前登记根，legacy 兼容仅解析当前蓝图指针；历史蓝图和 aliases 只参与引用保护，不授予文件系统删除范围。全局媒体根、平台根及未知父容器均不清理。

SQL115 的 `episode_deletion_intents` 在首次文件变更前独立提交原确认清单。`prepared` 表示未提交的删除，`committed` 表示业务删除与既有 command receipt 已原子提交，`completed` 表示清理完成，`rolled_back` 表示文件已安全恢复。暂存和回滚使用同目录的精确排他发布，目标被占用时不覆盖；重启识别同 inode 的 link / unlink 中断窗口。执行、恢复和重试只处理持久清单；完成清理仅逐文件 unlink，再按已确认身份尝试非递归 rmdir。旧回执没有逐文件授权时保留文件并显示待处理原因，不从整个目录推导新权限。现有恢复入口可恢复未提交的清单，恢复后仍须重新检查并确认删除。

普通删除沿用历史删除的跨 Owner 引用核查和确认事务库存锁；运行任务、资产锁、提交结果未知、活动原生进程和其他生产单的业务依赖继续阻止删除。删除前等待当前 Host 持有的真实原生进程关闭；重启后仍存活的外部 writer 不会通过删除进程回执被伪装成关闭。SQLite 只读查询仍会改写 SHM，因此原生盘点先流式复制稳定的 DB / WAL / SHM 到本次私有临时读副本，原生产树保持不变，临时文件只按创建句柄身份清理。

账号包含任意生产单时仍拒绝父删除，归档及已完成单也在此范围。未完成的创建或删除 intent 是占用中的存储操作。空父容器只从删除前的真实登记捕获，提交后再次检查引用、身份与空状态；未知内容保留。已完成的账号 / 容器创建 intent 和 command receipt 属于历史，删除账号不级联删除或重写这些记录；当前位置登记仍按既有 FK 处理。本轮不新增系列删除或级联能力。
