# ADR-0028：工程写入与完整状态读回分离

状态：Accepted。日期：2026-11-09。Owner 已批准第三项架构优化。

复用 `productionWorkspaceCommands.ts` 中已有的 `persistWorkspaceRevision`，作为持有 Owner 事务及工程行锁的内部写入入口。它维护不可变工程文件、revision／SHA 并发保护、版本登记及镜头输入同步，返回已保存的 `ProductionWorkspaceRecord`，不组装完整工作台状态。需要新工程 SHA 的调用使用该记录。

`updateWorkspaceProject` 保留写入并返回完整状态的现有接口。调用方实际使用其完整响应时沿用此入口；只需写入、随后还要更新证据或外层统一读回的调用，使用写入入口。字幕、候选采用、音频和口播仍按各自原有顺序登记证据，最后在同一 PoolClient、同一事务中读取返回状态，再由 Owner 命令边界提交。最终读回失败继续回滚数据库工程、版本、证据及命令回执。

素材池登记仅返回素材，不增加完整读回。打开或恢复 Studio 保留进入前的完整就绪检查，去掉保存后的中间读回；恢复字幕后才组装最终响应。原生保存继续同步字幕后读回一次。保留对外响应和错误语义，不新增缓存、数据模型、数据库迁移或通用持久化层。

沿用 ADR-0016、0019：原生工程是唯一编辑权威，文件访问仍经 EpisodeFileIO。数据库回滚可能留下未被引用的不可变文件，不把文件系统描述为数据库事务的一部分。通过真实 Owner HTTP、隔离 PostgreSQL 和受控 Worker 验证读回次数、最终返回内容、并发拒绝、回滚及原生保存／重开。
