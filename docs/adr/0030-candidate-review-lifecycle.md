# ADR-0030：候选核对生命周期统一

状态：Accepted。日期：2026-11-09。Owner 已批准第五项架构优化。

在现有 `useWorkspaceCandidateReview` module 内集中画面与口播候选核对的归属、请求序号、取消失效、确认锁和工程 SHA 校验。读取与发布继续使用 `useWorkspaceReading`，不复制其读取排序和卸载处理。界面负责选择与焦点，媒体 adapter 负责命令参数；不建立通用工作流框架。

核对归属于 episode、workspace、目标及影响采用结果的选项；口播沿用折叠／展开与模式的现有归属边界，关闭后再打开不恢复旧核对。切换后即使返回相同选项也不恢复旧核对。新准备覆盖旧请求，取消使尚未完成的准备失效，旧错误和收尾不得覆盖新请求。准备读取取得的新 SHA 可以建立本次基准；已有核对或准备命令执行期间收到外部工程变化时使核对失效。revision 单独变化不清除核对，确认仍重新读取并使用最新 revision；SHA 不匹配时禁止发出采用。

确认同步占用当前操作，避免重复点击重复发出采用。发出采用后的本地取消不能撤回服务端写入：同一仍存活归属可发布已完成的权威结果，但取消后不执行本次局部成功回调；采用自身产生的新 SHA 不使成功回调失效。切换归属或卸载后不向新界面发布旧操作的结果。

画面继续保留裁切、运动、时长和替换视频的参数。备用图片使用显式 `image-backup` 核对及 `retainWorkspaceImageCandidate`，不伪造 `adoptionId` 或影响。口播继续使用 `use-candidate`，恢复正文只在确认成功后执行；独立字幕、无候选人工回退保持原行为。沿用 inline／modal、Escape、焦点恢复及草稿交互。

后端候选命令、工程 CAS、事务锁、`adoptionId`、生成授权及付费调用均不变。测试通过真实 hook 与读取 module、两个 React 入口及隔离 Owner HTTP／PostgreSQL／浏览器验证，覆盖请求竞态与现有媒体语义。
