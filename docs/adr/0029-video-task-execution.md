# ADR-0029：视频任务恢复与下载协议集中管理

状态：Accepted。日期：2026-11-09。Owner 已批准第四项架构优化。

Wan 与 Official 视频入口共用内部 `videoTaskExecution` module，集中持久预留结果分流、供应商任务 ID 校验与登记前置、轮询、进度通知及受限下载。供应商 adapter 继续负责输入校验、凭据、endpoint、请求体、响应解释、下载域名、轮询间隔和错误文本；输入及凭据校验仍在预留前完成。

执行沿用既有预留及登记回调：旧预留无 ID 时停止，已有 ID 时仅查询原任务；新提交取得有效 ID 并等待登记成功后才能查询。提交、登记、查询、下载或进度写入失败均透传，不在共享 module 内重发生成、释放预留或另建任务。保留默认持续轮询、供应商间隔、`queued`／`processing`／`saving` 阶段及现有公共入口；旧类型保留兼容导出，`reserveWan` 等字段及 SQL 名称保持兼容。

共享下载继续使用传入的 `MediaFetcher`。供应商层保持逐跳 URL 校验、最多四次请求、每次 60 秒、100×1024² 字节上限、MP4 MIME 与空流检查及 reader 释放。在线网络 adapter 仍在更外层拒绝全部 3xx、严格检查声明长度和实际流量，并绑定原任务及相应授权。其缓冲与重建 Response 的行为保持原样，不将供应商层重定向能力描述为在线能力。

沿用 ADR-0021、0024、0025：冻结模型与输入、逐次授权、数据库账务与租约、submission 记录及固定运行版本继续由既有实现负责。ADR-0023 的本地产物发布未知恢复不纳入供应商生命周期。无数据库迁移、供应商扩展、队列或网络协议变更。

验证通过现有生成入口及受控 fetcher、真实网络 adapter 加受控 transport、Owner HTTP／隔离 PostgreSQL／受控 Worker／真实 MP4 三处 seam，检查失败中止、原 ID 恢复、POST 总数不增加、预留不重复和产物单次登记。等价重构先固定现有行为，不为制造失败修改业务预期。
