# ADR-0050：日常采用 clean-v2 并保留旧库

状态：Accepted。日期：2026-11-13。用户明确授权先采用 clean-v2 + 166–170，完整验证日常库后，再检查并清理不影响当前功能和历史恢复的旧预算、空操作审核触发器及剩余编排函数。

沿用 ADR-0045 的原生 PostgreSQL 17、ADR-0047 的不可变历史迁移与新代际、ADR-0048/0049 的旧执行入口退役。此次授权替代这些记录中「本轮不切换日常库」的执行限制，不改变历史原文。

采用控制器固定日常配置、原生集群、源库 OID、代码与 SQL 摘要、准备运行包及媒体/Keychain 引用。当前日常无账号、生产单和任务，因此一次性控制器主动限制为无生产内容的采用范围；有内容的其他实例不能直接复用该入口。

先在专属 VM 与 Mac 临时原生集群验证交换、中断恢复、切换前回退、重复执行拒绝以及真实控制器的回执发布边界。停本项目消费者后，完整导出所有业务和控制行，包括登录摘要、会话、ledger 与序列；私有材料仅存本机。独立候选先按原结构完整对账，再在事务中转换到 clean-v2 + 166–170。比较全部有效结构、角色和 ACL，仅接受批准的定义退役、两个历史表改名与只读收紧。

维护连接按 OID 和持久阶段日志冻结源/候选连接并交换名称；新库继续叫 loop_control，原库改名并禁止新连接。真实对账生成新的采用回执，部署仅更新回执路径及其媒体根别名。原媒体授权、原恢复回执、实际媒体、OpenChatCut 工程和 Keychain 不替换。

启动消费者前持久记录可能开始写入的边界。即使遗漏该标记，回退仍须对比目标的完整采用后快照；发现任何新行、控制记录、ledger、序列或结构变化即拒绝直接回旧库。启动后的故障优先在新代际修复并保留最新完整材料，不默默舍弃新数据。

旧库和原 Docker 回退库不删除，不启用周期备份，不进行真实付费生成。后续 SQL 清理只有在日常采用验收通过后才能开始；新增前向迁移，不改 166–170、旧基线或归档迁移。

验证记录见 `docs/verification/daily-clean-sql-20261113/REPORT.md`。实际状态以该记录和只读检查为准。
