# ADR-0014：六步制作流程与版本修订

- 状态：已接受
- 日期：2026-10-29
- 范围：本机 Owner 生产单

## 决策

可见流程为输入与脚本、视觉准备、分镜审核、逐镜头制作、合成与 QC、交付。逐镜头确认后直接进入合成与 QC，移除独立预渲染审核及本机逐成员批准入口。`production_ready`、`render_ready`、冻结成员和指纹仍是内部合成契约，不能删除或伪造人工批准。现有本机冻结包使用 `approval_mode: qc_only`；最终 QC 仍由 Owner 审批。

逐镜头操作采用 B 版摘要入口，复用真实的素材、声音、构图、预览与确认表单。未保存修改继续受保存围栏约束。预览弹窗受视口限制，长表单在内部滚动；小屏沿用单列布局。

已确认主脚本可以修订。Owner 显式确认新版本后，后端创建不可变材料快照与批准记录，保留旧版本；当前生产单返回 `waiting_input`，旧任务及审核包失效，原有自动继续授权暂停。重新开始及自动继续需按新脚本再次确认。此决定沿用 ADR-0012 的脚本指纹授权边界。

分镜新增、排序和删除统一使用已有结构修订任务，不直接改写已批准分镜或删除历史媒体。在分镜已批准至 QC 审核阶段可提出修订；后续合成与 QC 依据失效。最后一个镜头不能删除。

## 实现与边界

`LocalEpisodeCommands` 沿用会话、CSRF、Owner、命令幂等和生产单行锁。脚本修订携带预期主脚本 ID，并核验原文件指纹；迁移 `082-production-revisions.sql` 通过受限函数更新业务状态，`083-pending-structure-revision-fence.sql` 阻止结构修订排队期间抢跑旧媒体或合成。存在运行中任务、生产单已归档或已完成时拒绝脚本修订。结构修订沿用最新已批准分镜校验与现有操作验证器，不增加 Provider 调用。

不回写历史冻结快照，不自动执行实际用户脚本修订、分镜删除或付费生成。历史内部阶段仍可读，但不计入人工待审。

## 验证

组件测试覆盖六步导航、B 版入口、结构修订确认、脚本取消及失败时草稿保留。隔离 PostgreSQL/HTTP 验收覆盖 CSRF、跨 Owner、预期版本、幂等、运行中任务、旧材料保留、下游失效、授权暂停，以及删除末镜拒绝。列表集成测试检查人工待审与状态筛选一致。
