# ADR-0041：当前作品依赖与后台请求记录分离

状态：Accepted。日期：2026-11-11。Owner 认可 48 类流程建议并授权逐项实施；回执发送阶段分类重构暂缓，回收站继续隔离 Demo。

## 决定

原生工程继续拥有当前启用、采用、位置、声音和字幕状态。数据库中的任务、费用、提交、候选与发布回执保留历史事实。关闭提示不改变内容；明确关闭口播、配乐、音效，或删除目标才改变当前用途。重新开启只恢复已有内容/音量，不自动创建请求。

`workspaceExecutionProject` 从原生工程构建临时执行图，排除显式停用的音频节点。原始工程及素材库不删除，普通音量为零不等同舍弃内容。来源检查、导出渲染输入和最终时长检查使用同一执行图；实际已用文件、画面覆盖和启用字幕仍须通过检查。

目录在 Owner 只读事务中，对搜索/账号/系列范围内、仍有未结任务的活动工程读取经过指纹验证的原生文档，构建临时用途投影；不新增另一份可编辑内容状态。当前仍需且没有可用主声的口播、尚未填补的画面及当前交付失败才关联阻塞。历史、未采用、被替换/删除、关闭用途的记录保留为后台提醒；生产完成不因无关历史失败倒退。

目录不在每次读取时重新哈希整片视频或音频。列表状态反映已登记状态和当前用途，不是文件仍可导出的实时证明。采用、打开/保存工程、导出、确认和交付继续在其实际文件边界验证来源。工程文档/存储身份不可读取时明确报告，不用猜测的用途解除阻塞。

## 队列与并发

明确停用或删除用途后，受控 Owner 函数 `stop_workspace_queued_tasks` 仅将尚未开始的 `ready` 请求标为 `superseded` 并记录失效原因。冻结快照、原结果和历史关联不改写。运行中、已提交/已收到、已有费用预留、未知结果或产物待恢复的记录不在此处取消，继续提供核对/恢复入口。重新发起须走新的明确确认。

`persistWorkspaceRevision` 在同一事务中同步这个调度意图，覆盖网页开关、模式保存、镜头删除和原生保存。调用受 Owner、当前脚本/审核包、归档/历史/完成及作用域限制；不授予普通应用角色任意任务更新权限。

退避、自动尝试耗尽和输入失效由持久任务证据投影。自动尝试耗尽不等于撤销 Owner 再次明确确认的资格；已失效输入不能继续原请求。未知结果和 publication hold 保持原有限制，不因本轮展示改动增加重发资格。

旧 QC 合成/结构修订通过受控 `lock_owned_revision_tasks` 锁定当前任务并拒绝运行中冲突；合法修订仍冻结新依据，保留旧审核包和文件。新增锁由 SECURITY DEFINER 执行，不扩大 `loop_app` 的 UPDATE 权限。
