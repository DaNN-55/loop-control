# ADR-0065：退役旧生成脚本审核与批准落库链

状态：Accepted。日期：2026-11-13。

用户授权检查两个旧生成脚本函数及调用链，确认当前功能、23 个保存运行包及历史恢复不依赖后清理；不得删除历史数据、放宽保护、提交或推送。其他七类残留只分析，不顺带修改。

当前手工正文和 v2 脚本通过独立确认／准备路径进入制作。`draft_script` 不可由当前 Worker 新领取，也不在原生回执允许范围；46 个保存包 Worker 模块同样使用原生回执包装。16 个旧包的旧审核命令仅允许视觉／分镜阶段，其他包已拒绝旧审核；均不提供生成脚本批准。两个目标仅有各自挂载触发器依赖，无其他 SQL 调用者或精确原包引用。

但通用 `transition_episode` 仍保留旧脚本阶段。仅删批准触发器会使这条 SQL 转换可能成功却不再登记主脚本，因此必须在原权限、状态、产物检查后、任何写入前明确拒绝旧生成脚本阶段转换。保留当前手工脚本确认、旧视觉／分镜、QC 与交付转换，以及所有原有状态校验、Owner／会话、RLS、冻结／租约／费用和未知提交保护。不得通过删除校验来实现退役，也不新增前代包装函数。

185 仅以 CREATE OR REPLACE 在原通用函数中加入明确 0A000 拒绝，保持签名、Owner、ACL、原函数其余正文；显式拆除 `create_script_review_package_after_task_completion` 和 `materialize_approved_script_revision_after_approval`，再默认 RESTRICT 删除两个无参函数。无 CASCADE、数据 DML、历史 SQL 修改、授权或重新派单。

历史的脚本任务、原回执、产物、审核包、批准记录、原主脚本版本、Prompt 和实际文件必须保持。完整 pg_dump 的数据恢复先于触发器安装；现行历史投影使用独立受控的 replica 事务装载原记录，不重放业务审批事件。验收必须实际比较退役前后的完整恢复与历史投影，不能仅以文本判断。

完成隔离的非空恢复、额外依赖阻断、失败回滚／幂等、全部原行／其余目录 ACL 对账，真实当前与保存包合同及完整回归后，备份并恢复独占候选演练，复核日常无漂移再应用。采集保持关闭，不重启；报告 `docs/verification/generated-script-chain-retirement-20261113/REPORT.md`。
