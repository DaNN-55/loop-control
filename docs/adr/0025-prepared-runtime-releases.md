# ADR-0025：后台与 Worker 绑定已准备的运行版本

状态：接受。日期：2026-11-02。

## 背景

main 的真实 E2E 发现：日常服务每次调度都将开发源码与编译清单比较；并行修改共享源码或重新编译会阻断已有制作，还可能让旧后台启动新的 Worker 代码。产物完整性保护必须保留，不能简单跳过检查。

## 决策

`runtime:prepare` 在确认编译前后源码一致后，将后台与 Worker 编译产物发布为带内容指纹的独立版本。先完成独立目录及清单，再原子更新当前准备结果；准备失败保留上一份可用版本。

日常服务启动时选定一个运行版本；后台模块、Worker 子进程和健康检查均固定使用该版本。源码编辑及准备下一版本不改变已运行版本；显式重启后才采用新版本。每次 Worker 就绪检查仍核对固定版本的路径身份、Node 主版本和全部编译文件指纹，损坏文件拒绝执行。

`assertPreparedRuntime` 继续供编译／开发检查源码与当前产物的一致性；执行入口检查已绑定运行版本，不再把工作目录源码变化当作运行产物损坏。恢复 CLI 使用同一发布版本解析与校验机制。

不修改数据库、任务租约、Provider 授权或未知提交恢复规则。不引入第二套任务调度器，不自动清理可能仍被进程使用的旧版本。前端开发热更新和外部 SDK／Node 依赖仍沿用原部署方式；更新这些依赖需要正常重启。

## 验证

- 固定版本可在开发源码变化、下一版本准备和准备失败后继续运行。
- 新服务显式选择新版本；旧服务及其子进程使用旧版本。
- 编译文件损坏、目录别名、清单篡改或 Node 版本不符时仍拒绝执行。
- 通过真实隔离 PostgreSQL、正式常驻 Worker 与受控供应商验证调度／结果，零付费调用。
