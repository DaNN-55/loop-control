# ADR-0036：脚本保存与启动的分步恢复

状态：Accepted。日期：2026-11-10。Owner 批准状态机第 4 项；不提交、不推送。

## 决定

脚本确认仍按原命令顺序保存材料或修订，再启动生产。面板显式区分保存中、保存结果未确认、启动中、核对中、已保存但启动未确认、已启动。只有启动成功或权威读回证明同一脚本已进入制作，才确认草稿并触发后续准备。启动失败不能显示成保存失败，也不能重复创建已知成功的修订。

保存命令会刷新父页面版本，工作区重读也会暂时隐藏内容。脚本面板在重读期间保持实例并禁用；本次提交保留原草稿的 Owner／episode／版本范围，防止自身的保存刷新清空正文、原因及文件名。启动完成且父页面脚本已同步后，恢复普通版本跟随。切换生产单或卸载后的迟到结果不继续启动或通知新页面。

保存结果未确认时保留原草稿，用户可重试原确认，沿用现有客户端幂等键与服务端回执。已保存但启动未确认时提供「继续启动」；先通过现有生产单读取接口核对当前脚本 ID、只读及阶段。同一版本仍为 `waiting_input` 才重试原启动命令，已进入制作则直接继续；版本改变、归档、完成、历史只读、读取失败均保留草稿并停止。若继续修改正文，则仍需修订原因及二次确认，并携带最近已保存版本作为预期版本。

不增加自动恢复或跨版本草稿迁移协议。页面刷新后，已保存脚本按现有 `waiting_input` 确认入口继续；原草稿仍遵守现有 Owner／episode／服务端版本隔离。保存快照、文件校验、运行中任务限制、下游失效、历史媒体、Owner／CSRF／行锁、输入校验和幂等协议保持不变，不修改 SQL 或服务端命令。

## 验证

通过脚本面板与真实工作区父组件的公开输入、按钮、状态和回调验证，使用受控 HTTP 返回生产单状态。覆盖分步延迟、保存失败、保存成功而启动失败、已启动的未知响应、版本冲突、只读、读取失败、重复操作、编辑后的修订、切换生产单，以及草稿隔离。浏览器使用真实组件、客户端和隔离 HTTP，检查宽窄屏及失败恢复，不操作正式业务数据。
