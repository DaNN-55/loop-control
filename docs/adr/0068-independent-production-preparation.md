# ADR-0068：独立制作基准版本与稳定镜头

状态：Accepted，依据已批准的 ADR-0066／实施规范 B1，分步实施中。日期：2026-11-13。仅在源码和隔离环境实施，未应用日常。

当前准备基准通过 `review_packages` 表达，原生工程和口播又引用包内镜头。选择在同一 PostgreSQL／Owner 事务体系内增加 `production_preparation_revisions`、`production_shots` 与 `production_shot_versions`，随后迁移当前读写；不将新增表当成已经完成替换，不长期双写两套当前模型。

制作基准是不可变版本，冻结主脚本 ID、内容 SHA、文件引用和规范化镜头清单。镜头稳定身份采用「生产单 ID + 原镜头键」，保留既有 `shot-01` 等键及原生 clip ID，不为了新模型重建工程或音轨。每个基准保存相应镜头版本，局部新增镜头也必须有明确来源，不以当前可变草稿覆盖冻结正文。

排版修订可以沿用完全相同的工程字节，但会确认新的脚本与制作基准关系。工作版本的身份因此包含工作区、工程 SHA、脚本版本及制作基准版本，不能再只以工作区和工程 SHA 去重，否则会静默丢失新的确认关系。同一 SHA 的内容读取仍验证实际字节；读取元数据时选择最新记录，保留全部原记录。排版接续记录同单父基准，并复制其镜头版本与来源类型，不重新解释为旧分镜。

当前格式使用 `production-preparation/v1`，不接受旧 `shotType` 分类，也不要求静态镜头提供视频参数。旧 `storyboard/v1` 经版本化适配进入；原审核包、上下文、文件引用与旧分类另存来源证据，规范化快照移除旧分类。不得改写原表、原文件或已冻结任务。

可编辑字幕输入按工作区、制作基准与稳定镜头保存，和字幕校时／人工确认的证据分开。当前字幕保存不再建立或修改旧镜头草稿；已有工作区的原字幕合同确定性接入新存储，保留原记录。原生字幕轨仍表达实际编辑，输入存储用于初始化和显式修改，不能在重开时覆盖原生人工编辑。旧音轨状态只在尚未切换声音来源的显式适配中读取，不恢复旧字幕写入。

历史字幕导入记录原 package／draft，使用生产单、原包、镜头和草稿 ID 的复合外键锁定来源。排版子基准可以继承原父输入及其原来源，不将原草稿改说成来自子包。当前编辑改变的是独立输入；原草稿不变。有效原生字幕保存同步当前输入，输入与校时／人工确认仍分开；后续口播提交冻结当前字幕输入，不回写旧缓存。

新声学对齐任务使用 `workspace-caption/v2`，冻结工作区、制作基准和镜头；领取与回执继续使用原 attempt／lease 协议。采用前校验当前输入、实际音轨、证据文件、结果结构及冻结模型。旧任务仅经显式解码接入：原冻结 draft／package／shot、当前原草稿和 canonical `storyboard/v1` 来源必须一致；未知版本或换基准的旧结果不能写入当前字幕。原任务和结果保留，不改写快照或自动重新执行。

独立基准指针是当前读写的依据，不能被旧包字段静默覆盖。旧排版适配在同一事务内先登记并安装子基准，再由通用同步读取；其 Owner、主脚本、工程 SHA、活动任务、历史及冻结来源检查保持。

口播输入按工作区、制作基准和稳定镜头保存，正文／音色／语速／语言与人工音轨选择独立于旧审核草稿；原生工程中的已采用音轨继续决定实际成片，保存新草稿不自动替换它。旧输入确定性接入并保留原来源与原确认指纹，旧请求及音轨不改写。新 `workspace-narration/v2` 任务和新音轨显式引用制作基准，不再伪造旧包／草稿字段；原有效请求仍以原格式恢复和登记，未知请求不重发。

默认新单直接登记 `production-preparation/v1`，不再写旧审核包、旧审批或旧镜头分类。当前工作区必须持有同单同脚本的独立基准外键；旧包字段仅保留已有历史来源，可为空，不给新基准伪造旧包身份。原非空历史字段和原记录不清空。新的制作与排版确认处于「脚本已确认」，不通过旧「分镜审核」阶段表达当前工作区。

独立基准的排版接续在真实正文／文件比较之后，以新文件登记一个同内容子基准，显式确认新脚本，继承父镜头版本及可编辑输入；保留原工程字节、旧基准、文件及所有已采用音轨。新身份必须未被使用，不能借接续覆盖现有版本。原格式路径仍使用其历史适配，待后续统一接入时再退役；不能将保留适配说成当前新单仍需要旧包。

Pexels 检索和预览同样冻结独立制作基准、稳定镜头与真实请求身份。Worker 解析凭据前先核验有效租约、当前基准及冻结请求与记录相符，不能因零费用而绕过来源检查。新任务缺引用不能伪装旧任务；原 `workspace-pexels-v1` 请求仅按明确的原目标格式读取，未知协议版本拒绝。旧检索结果可以在验证原来源后明确建立新的当前预览请求，原检索和原任务字节不改写；导入与采用仍分开。

当前写入只通过受控 SECURITY DEFINER 操作，保持 Owner／当前主脚本／归档／历史／回收站栅栏和生产单行锁。普通应用只有按 Owner 隔离的只读权限；Worker 无注册能力。同 ID 同内容重放返回同一版本，内容改变明确冲突，不覆盖原版本。历史接入与当前作者注册分开，不能借导入绕过当前确认。

本机 `productionPreparationStore` 在 SQL 之前验证实际文件位置、SHA、大小及 JSON 内容；SQL 不读取宿主媒体。后续 HTTP 注册必须通过该文件边界。原永久删除协议在全部既有栅栏之后按镜头版本、基准、镜头身份的顺序精确清理，不通过级联删除跳过协议。同单脚本归属使用已有复合唯一键上的外键约束。

现有数据迁移先核对同单脚本、基准与原版本，歧义阻止迁移而不是挑第一条。完整恢复保留新表，逐项投影和永久删除协议在当前路由切换前同步承接。当前候选、音轨、字幕和回执尚未迁移的部分须明确标记未完成，最终以新单不再写旧审核／旧草稿及旧工程原样恢复为验收条件。

验证使用真实隔离 PostgreSQL：无旧包的独立注册、稳定身份、重复／冲突、Owner／Worker／直接写入拒绝；非空旧作品升级、回滚、原表／音轨／工程及任务快照对账；最终新旧制作、恢复与 schema 矩阵。不引入依赖，不修改历史 ledger，不提交、不推送。

逐项历史恢复采用明确的制作业务表清单，而非恢复整个私有schema。恢复独立基准、镜头、工作区版本、字幕／口播输入、候选及已发生请求／导出／交付事实；登录凭据、会话、付费调用确认和可消费的采用决定不装回当前执行表，原记录保留在历史版本。输入记录可以恢复用于识别生产单，但所有执行开关关闭；已恢复任务保留历史标记，不能重新领取。

逐项恢复只追加当前缺失记录，不替换已有编辑。行键须与当前主键一致，来源Owner、生产单和账号明确一致；父记录先后到达在同一事务内处理，跨单或跨Owner的依赖不接入当前业务图，而保留原始历史及原因。宿主目录授权不从历史SQL复制；已有已核验目录可以读取恢复后的工程，缺少目录授权时仍拒绝读取，须走既有存储恢复边界，不自动创建目录或改文件。

历史来源不能借用现存账号的身份：归档中的账号／生产单声明不替代当前Owner成员关系。需要使用历史归属时，必须有投影器证明原账号和单据曾实际装入的记录及历史标记，不能用current-preserved的冲突记录作授权。所选父记录来源Owner的核对也覆盖当前已存在的父记录，不因本轮未插入就跳过。

pre-188 私有备份由独立的历史转换模块处理：只接受已知旧工作版本双字段主键及缺少独立基准字段的旧协议，将当前主键与原历史键分别跟踪。调用既有严格188转换器建立数据关系，不冒充当前制作确认；未知格式、歧义和来源冲突留在history-only。失败清理只匹配本次新增的完整当前主键，不能按共用工程SHA误删已有其他脚本／基准版本。原历史键、payload与文件不改写。

历史注册的导入Owner不替代原始Owner。只有导入归属已获证明、原Owner确为同账号Owner且生产单已标记历史时，才保留原input记录的Owner，执行开关全部关闭；不恢复登录或消费授权。派生前核对审核包、脚本、文件、草稿、音轨、音频产物／任务、镜头输入和旧确认依据的所选来源Owner，包含当前已存在的依据。

旧排版接续原本不复制草稿；转换沿已核验父基准链逐镜头选择最近的原草稿，子包已有编辑优先，缺少时继承父输入。保留原draft/package及音轨身份，不将父来源说成子包；人工新增镜头与原工程字节保持。转换后的完整备份恢复仍核对全部表、序列、角色与ledger；此阶段不替代最终新旧矩阵。
