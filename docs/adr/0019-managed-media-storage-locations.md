# ADR-0019：统一媒体根与生产单物理收纳

- 状态：Accepted，按 #178 子票逐步实施。
- 日期：2026-10-31。
- 扩展：ADR-0018 的账号目录归属，以及 ADR-0008、ADR-0013 的位置映射、路径身份和恢复边界；保留其余约定。

## 决定

工作区拥有一个全局媒体根。账号、系列、未分系列收纳及生产单使用登记的稳定相对位置；可读名称只在创建目录时使用，改显示名称不搬文件。媒体根与账号根是存储配置，不属于创作蓝图。系列物理收纳与生产单创建时冻结的系列规则版本相互独立；位置变化不重写蓝图、执行快照、任务、来源及审核证据。

复用 `account_asset_directories`、`episode_asset_locations` 和 `account_directory_locations`，不建立第二套位置系统。`episode_asset_root` 继续解析该单的账号文件 I/O 根；已有产物路径相对此根，保留原字节及冻结引用。`episode_storage_location` 返回同一根下登记的生产单完整相对目录和身份，所有新路径消费者以此为准，禁止按当前标题或系列名重拼目录。历史记录没有相对目录时沿用 `episodes/<稳定 ID>`；T01 先建立兼容契约；制作、删除和恢复调用方逐批验收后，T12 才启用正式新单层级。

新的物理目录登记设备和 inode 身份，存量未纳管目录继续按旧授权与账号身份读取。定位及打开仅解析记录并检查现有目录，不创建缺失目录，不登记制作资格，不启动任务；Owner HTTP 只接受对象身份，服务端复用 Owner / CSRF、账号归属、部署映射及真实路径校验。禁止符号链接及越界目录，挂载或身份变化时停止相关写入，不回退至旧根或创建同名替代目录。

媒体根更换、旧层级纳管及同账号系列收纳调整均属于显式迁移。复用盘点、流式复制、指纹与引用校验、持久回执及原子切换。活动任务、打开的原生工程、未知付费提交和变化的盘点阻止切换；原目录保留，切换前读取可靠旧位置，重启依回执恢复。备份包含数据库中的配置、目录映射、身份和回执，以及实际生产文件；数据库、秘密、共享程序、模型缓存、独立历史库与备份保持各自职责。

## 后果与验收

只添加前向迁移，不修改已应用 SQL。目录维护与创作保存使用独立命令，已完成及归档单据的内容只读不妨碍其定位。全局根的正式设置、自动创建、迁移和恢复由后续子票实施，不能将本契约发布解释为日常数据已移动。

以正式页面 → Owner HTTP → 隔离真实数据库与文件 → 系统文件夹打开及适用原生工程为验收链路。检查旧产物字节及预览、新层级夹具、拒绝跨账号与任意客户端路径、缺失目录不重建，以及目录身份变化。UI 检查桌面和窄窗。不得使用日常数据或真实付费 Provider。

## T03：媒体根初始化与部署接管

`local_identity.media_root_binding` 登记工作区存储 Owner、实际根、设备 / inode 和挂载点。原 `media_deployment()` 的活动根优先读取该登记；恢复目标与 `import_record` 的来源位置保留，不改写冻结来源。有效现有根在正式服务启动时接管，不搬文件；Owner 设置读取不创建目录。存储 Owner 优先继承已登记身份；首次接管使用明确部署 Owner、唯一现有 Owner membership 或唯一凭据 Owner，多 Owner 歧义须由部署配置明确，不能由首个访问者抢占。

只有没有账号与生产单、源根没有生产文件或未知内容、目标实际目录为空时，才允许显式初始化。纯部署来源记录不代表业务资料。源空判定只排除可信服务配置中精确登记的模型缓存目录；缓存继续位于原处，并独立登记身份。字幕对齐保留原媒体根内的兼容授权；新根下只接受与缓存实际路径一致且身份有效的显式 `cacheBinding`，不接受浏览器传入缓存路径。已有账号或文件的根更换继续走后续受控迁移。

初始化在 Owner / session / CSRF 边界后协调数据库绑定、私有部署文件、初始化回执和待完成日志，再重载 HTTP 服务与 Worker。旧恢复回执仍证明原部署，新的初始化回执仅授权本次新根。下一进程按数据库提交位置恢复或完成待完成日志；无法确定一致位置时停止启动。数据库、Keychain、共享程序、模型缓存、独立历史库和备份位置及备份开关不随媒体根变更。已有 `create_account` 的首个 Owner membership 要求由后续账号创建票衔接本存储 Owner 契约，本票不放宽创作对象权限。

## T05：系列与未分系列收纳

`account_storage_containers` 登记账号内的物理收纳位置：`kind=series` 关联同账号的真实系列，`kind=unassigned` 每账号最多一条且 `series_id` 为空。位置以账号实际根下的稳定相对路径、设备和 inode 保存；读取与打开只验证登记位置，缺失或身份变化时停止，不补建。历史系列没有登记时明确为未纳管，不按显示名称推测路径。

系列显示名称可重复，身份仍为 `series.id`，创作版本身份仍为 `series_versions.id`。新目录使用创建时规范化名称和完整 UUID；同名、大小写或 Unicode 归一化相同的名称不会覆盖另一个对象。独立改名只更新系列元数据，不搬目录、不新增创作版本，也不重指已有生产单的冻结版本。当前收纳、系列创作版本与账号硬约束继续独立。

正式系列创建使用持久 intent 固定容器 ID、媒体根绑定及账号根的路径和设备 / inode，协调既有账号迁移锁；最终业务、目录登记与回执同事务提交。未分系列通过明确创建命令建立，不创建业务系列或规则版本；后续无系列新单可在取得生产单事务锁之前调用同一显式边界。完成的 intent 是创建历史，重放按当前登记位置验证；未完成的 intent 固定原位置，迁移与恢复必须盘点其保留目录并处理冲突。新生产单默认层级仍由 T12 启用。

迁移和备份恢复须保留这些表及回执，并在验证实际目标目录后重绑容器身份。仅恢复相对路径和旧 inode 不代表位置已可写；禁止按当前名称重建目录，禁止为迁移改写已完成 intent 的历史位置。

## T09：原生工程、导出与交付

Studio 工作副本、SQLite 与恢复文件、不可变工程版本、冻结工程、导出及交付文件由同一 `episode_storage_location` 定位。`episodeFiles.episodeFileIO` 只适配该持久位置与原始引用读取边界；会话不持有已结束的数据库事务，后续命令传入当前事务的位置检查。工程 / 任务 / 审核中的原始来源引用和 SHA 保留，实际读取位置单独传给原生复制、渲染与包校验。Worker 的隔离 staging 按原始冻结坐标放置已核验输入，不改写工程或渲染指纹。SQLite 优先、缺库回执拒绝旧 JSON、工程双改冲突、Owner revision / SHA 比较及任务去重保持。

SQL120 以字面登记 prefix 比较路径，只对固定后缀使用正则；历史 legacy 冻结工程还须匹配本单已登记不可变产物的路径、SHA 和大小。Vite 依赖编译缓存属于可重建的程序临时文件，每个原生进程独享一个系统临时目录，按创建时 device / inode 身份清理；不承载工程、SQLite、生产媒体或冻结证据。原始来源及其实际读取位置不因此变化。进程回执保留缓存身份；无法确认归属的异常残留不按猜测路径递归删除。T09 阶段保持 legacy 创建默认，正式新单层级由 T12 启用；生产单 prefix 迁移 / 恢复 lineage 仍由 T13 / T14 实施。

## T10：归档、删除与存储占用

归档不改变位置。已有永久删除统一解析 SQL110 的实际生产单目录，并复用 ADR-0001 的 Owner 确认、精确文件授权、共享引用和恢复协议。新旧布局使用同一边界，不按当前名称重拼路径，也不把部署 aliases 或迁移 / 恢复保留源纳入默认永久删除。在线旧源完整保留，离线旧卷不阻断当前位置删除。空账号收尾同样仅使用当前登记根（legacy 仅映射当前蓝图指针），历史蓝图和 aliases 只用于引用保护。原生工程与交付文件按具体登记或可核验的协议成员识别；未知文件及原生存储中的额外项目保留。

SQL115 增加 `episode_deletion_intents`。备份、迁移及恢复必须将 `prepared` / `committed` 视为活动存储操作，避免复制半暂存状态。`completed` / `rolled_back` 的原始清单是历史，不是当前位置或当前文件引用，后续位置切换不重写它。未完成的账号和容器创建 intent 同样保留占用语义。删除前捕获当前位置登记用于身份相符的空目录收尾；已完成创建 intent 和 command receipt 保持原值。

## T11：完整备份与异地恢复

沿用 `scripts/storage` 的导出快照、全表 COPY 指纹、sequence、ACL、外键与文件校验。新归档保留真实目录清单，包含空账号、系列和未分系列目录；文件以固定块计算指纹并独占复制。可信运行配置中精确登记的程序、缓存、独立历史库和运行目录保留原职责，不递归收入生产媒体，媒体根与备份根禁止重叠。无 `import_record` 的新工作区保持真实零来源记录；SQL121 仅为既有 `restore_record` 增加恢复来源别名，并由同一 `media_deployment()` 解释。

恢复先审计归档原样业务行和引用，再更新全局媒体绑定、账号实际根、系列／未分系列容器及已登记生产单的目标设备和 inode。相对位置、业务身份、冻结规则、任务、工程原文、旧迁移 manifest 和已完成创建 intent 不重写。恢复回执绑定归档 SHA，并记录各级原根、原身份和经过实际文件验证的目标身份，供后续受控迁移解析使用；回执不单独授予任意旧 prefix 的重定向权限。已完成账号创建按当前登记根验证后返回原结果，不再访问旧创建根或清理旧标记。未完成创建、活动删除、未完成迁移、活动任务、未知提交及原生 writer 阻止完整备份和恢复发布。

恢复部署复用既有 `media-root.mjs` 的私有配置、授权回执和待完成日志，操作明确为 `restore`。目标 DB、Worker DB、存储 Owner、全局绑定、恢复回执和独立缓存身份须一致；关闭的自动备份保持关闭。恢复先独占预留最终目录并排他复制，数据库保持 `pending`；文件、历史业务行、目录身份和配置准备完成后才提交 `ready`，随后发布 `passed:true`。发布失败保留源归档、不完整目标及明确的失败／准备回执。既有 journal 保存目标配置和授权回执，pending 强停保留现场；显式恢复重验后完成提交，ready 强停仅在实际目标身份及配置授权一致后完成尾部，不覆盖期间改动的未知配置。原 initialize v1 的事务顺序和恢复分支保留。

媒体复制使用 256 KiB 固定块。当前受支持归档上限为 20,000 个媒体文件及目录、64 MiB 压缩数据库归档和 64 MiB manifest；SQL 解码沿现有 128 MiB 子进程输出上限，超限须失败并保留现场。媒体流式处理不代表任意规模的 SQL 解码已实现流式处理。生产单 prefix 迁移及旧失败任务中冻结目录身份的解释仍由后续迁移契约完成，不能修改旧任务使其看似已恢复。

## T12：正式创建生产单

正式 Owner 新建生产单在已登记的系列或未分系列容器下创建独占目录。请求仍选择可选的系列规则版本，服务端校验同账号并解析真实系列身份；未选系列不创建业务系列。账号及系列未纳管时明确拒绝，不按当前显示名称猜测旧路径。可读名称只用于首次创建，完整 UUID 保持身份；改账号名、系列名或本期标题不搬目录。旧记录、直接历史种子和文件 helper 的 legacy 默认保持原样，不批量改写位置或来源。

SQL122 的 `episode_creation_intents` 在首次文件变更前固定请求及哈希、生产单 UUID、账号和蓝图／系列版本、实际父容器、媒体根绑定以及父子目录和标记身份。创建过程沿用账号迁移锁、Owner 幂等锁、既有命名与私有标记协议。`create_episode_from_intent` 只允许可信本机角色根据固定 intent 登记；业务单、输入资格、layout2 位置、intent 结果及命令回执同事务提交，最终登记前后均重新核验实际父子目录与标记。生产单根目录先独占建立，`input` 与 `materials` 由后续明确的输入写入建立。

待完成 intent 同样冻结创作版本。修改当前蓝图时，SQL108 的版本分支将待完成创建计为引用；原蓝图内容及 ID 保留，新规则成为新的当前版本。系列沿用始终新增版本的既有规则。重试按原引用完成，不强制原蓝图仍为当前或激活状态，不悄悄换用当前规则。已完成重放只验证当前登记位置，不重建缺失目录，也不要求创建时的旧源在线。

补偿只处理本次拥有、身份及标记一致且没有未知内容的空目录。未知文件、替换身份和无法证明归属的内容保留。待完成生产单 intent 接入既有账号迁移占用、账号删除及备份／恢复占用检查；完成 intent 保留为历史，后续迁移不得把它当作当前位置或删除授权。所有生产文件继续经 SQL110 与 `EpisodeFileIO` 解析；活动原生会话中的候选源注册同样传递该 I/O 上下文，保留原生采用、版本及身份检查。

真实恢复保持完成单只读。交付前的完整快照可验收原生编辑、关闭、新进程重开及导出；交付后的完整快照保留全部交付文件和历史状态，恢复后验证 Owner 文件指纹与既有只读限制，不为验证而重置业务阶段。

## T13：旧资料纳管与完成位置证明

旧账号通过正式目录维护入口显式盘点纳管。计划固定账号、容器及生产单身份、原实际来源与目录设备 / inode、目标稳定名称、文件指纹和冻结引用；读取、登录、升级与改名均不搬文件、不补目录。共享全局旧根只提供该生产单已确认 prefix 的来源范围，与独占账号写入根区分；禁止递归复制整个全局根，也不放宽一般根目录重叠保护。多个旧根的同后缀文件只有指纹一致才可合并，未知及共享内容和所有旧源保留。

`layout_version=2` 只代表位置曾登记，不能据此跳过纳管。`episode_storage_collection` 及其 TypeScript 适配器仅在当前位置确实直属同账号已登记系列／未分系列容器、且 `storage_series_id` 一致时返回已纳管。只有真实未分系列容器下的 NULL 才表示明确未分系列；未形成该层级的 legacy NULL 仍按冻结创作系列兼容盘点。T14 沿用同一判定，不按当前系列名或标题猜历史路径。

SQL123 在唯一当前位置之外增加 append-only 完成操作证明与生产单位置边。边完整记录稳定账号／生产单及 source root、prefix、设备、inode 到 target 对应坐标；操作原 manifest 与规范化指纹共同验证边，不能由客户端路径 JSON 授权。`episode_completed_storage_lineage` 只返回完成且原证据一致的边；`EpisodeFileIO` 统一解释唯一完整链，并验证当前父链与目录身份。原 relative refs、SHA、大小、冻结 input_snapshot、native 目录身份、attempt、fence、publication、费用及创作版本保持原文。原生 sourcePath、Worker staging 和最终发布只改变实际文件位置，不 mkdir 旧 prefix 或修改冻结输入。

恢复仍先通过 T11 私有部署授权、归档 SHA、DB restore_record 及实际文件审计，再追加旧到新物理坐标证明。备份捕获真实生产单目录身份，包括 legacy；恢复先读取旧 sourceBinding，再重绑目标。已有位置可能经过106映射，因此当次物理来源不与原冻结逻辑根盲等。已完成 adoption → restore → 后续受控 move 共享同一链，不让各读取、probe、SDK、Worker 或交付消费者另建 resolver。旧106整根回执缺少子目录身份，不能据此伪造 inode 桥；其旧源在线时可显式补证，缺证明明确拒绝。原高级整根迁移对 layout2 在文件动作前拒绝，直到同一协调器支持逐子目录证明。

纳管复用106持久计划、256 KiB流式复制与账号迁移锁。先取得账号 session 锁，再进入全局事务锁；未来全局协调器不能持有全局锁后阻塞等待账号锁。未完成113／114／122创建、115 prepared／committed删除、实际任务／租约／未知付费请求及原生 Studio 共用占用屏障；未登记 legacy 根也不能跳过 copying 期间的归档和删除阻塞。completed／rolled_back仅是历史。

复制前持久记录本次临时文件句柄身份，中断恢复只清身份相符的本次 partial；完整副本、替代身份与未知文件保留。新旧文件、引用及冻结业务证据复验后，在同一事务登记当前位置和完成边；最终 SQL 执行之后、COMMIT之前再次核父链、子目录、目标指纹、旧源快照及所有引用，失败回滚整个位置切换。重复盘点中的已纳管旧引用同样经 I/O 和实际指纹核验，不能按 managed 标签或当前 prefix 豁免。完成重放检查当前位置及完整原坐标证明，不要求旧源在线；显式回滚继续使用旧位置并保留目标副本。

SQL124 的可信完成函数核对 Owner、同账号生产单、当前完整来源坐标、源容器及目标容器、目标直属路径和实际登记身份，再追加 `kind=move` 完成证明并更新唯一当前位置。沿用 SQL123 的完成证明查询和 `EpisodeFileIO`，不修改旧边、任务、费用、来源或审核证据。最终 SQL 后、COMMIT 前继续复核源、目标、父容器和字节，变化时回滚全部位置切换。活动任务、真实 Studio、未知供应商提交、创建／删除和迁移占用继续阻止移动。

## T15：全局媒体根迁移计划

所有者设置中的本机存储可以选择旧根之外、不同授权父位置的实际目标，先保存全局盘点。SQL125 的 `media_root_migrations` 固定 Owner、幂等请求、完整 manifest 与服务端 SQL canonical SHA；相同请求重放同一计划，不同请求不能共用 key。计划只包含 `planned`，不复制、不切换位置、不写部署配置、不激活实例、不启动制作；后续 T16 在同一 planId / 原 manifest 上增加执行和发布状态，不能另造计划或以客户端 JSON 授权路径。

盘点由 SQL110 的唯一当前位置、SQL123 / 124 的完成证明、`EpisodeFileIO` 和实际文件身份共同确定范围。记录账号、空系列／未分系列及生产单的真实目录，按生产单范围计算文件 SHA / 大小、原始引用与冻结目录身份。旧 shared global root 仅提供精确生产单范围，不递归复制整个旧根。缺少完整冻结身份桥的历史回执形成冲突，不伪造 child inode，不改写原任务或来源。原始文件和历史完成清单保留。

账号迁移和全局盘点共用 `storageInventory` 的异步 walker、目录身份、stream hash、引用提取与证据指纹。单文件读取为 256 KiB 固定块；拒绝 symlink、hardlink 和 FIFO 等特殊条目，深度上限 128，单次目录扫描的文件及目录上限 100000，引用上限 100000，业务证据上限 32 MiB，最终 manifest 上限 64 MiB。文件、空目录、数据库证据、源和目标身份在持久化前复验，晚期文件插入／改写形成冲突。容量区分完整复制、目标已有内容、未完成副本和可信运行配置要求的预留空间；有冲突的计划仍可读，不能被当作执行许可。

生产目录与平台资源分开登记。程序、运行状态、模型缓存、独立历史库、备份和秘密保持原职责，秘密只记录职责，不读取值。已经授权的媒体根可以位于 program / runtime / state 父目录之下；只将当前媒体子树从该宽泛父范围中划出，不放宽新目标的平台目录保护。源根的未知、手动及旧保留内容明确列出，不自动复制或删除。历史库使用正式服务原有 `runtimeRoot/history/content` 配置来源。

全局盘点先按稳定顺序取得既有账号 session locks，再进入 global / ownership 事务锁；不能持 global 阻塞等待账号。首次账号预留与初始化共享 global 准入，空工作区判定包含未完成 account / container / episode 创建和活动删除、账号迁移。实际任务、lease、未知提交、Studio、待恢复复制、正式服务的活动备份及配置 publication 均进入阻塞清单；已完成历史与普通 `planned` 全局计划不永久阻止正常创建，之后的执行必须重新验证范围。

保留平台状态位于旧媒体卷内时，卸载也不能在 host 同名路径重建状态树。Worker scheduler 与 native automation 在启动时绑定实际 state 目录身份，后续共用的 `recordOperation` 验证原 dev / inode，不递归重建缺失父目录，不在失败时重新绑定替代位置。后台继续运行并保留数据库中的状态；恢复原挂载及身份后才恢复该位置的写入。该保护针对平台状态记录，不扩大为新的媒体目录管理器。

## T16：全局根执行与恢复

全局迁移在 SQL125 原 `media_root_migrations` 行上执行，不接受新的 manifest 或客户端路径证明。SQL126 仅前向增加 `copying/failed/committed/completed/rolled_back`、实际字节进度、暂存文件身份和 publication 证明；原 manifest、Owner、请求和 SQL canonical SHA 保持不可变。`GET /api/local/media-root` 优先返回仍有持久屏障的计划，已失效的旧 `planned` 不能遮盖执行或完成回执；存在活动全局计划时不能另起竞争计划。普通计划不长期冻结创作。

执行先暂停本机新写入并排空已经准入的请求，再按原账号锁与 global / ownership 锁重验范围、身份、引用、任务、Studio 和其他未完成操作。`copying/failed/committed` 共用数据库持久写屏障，覆盖任务、账号、生产单及 intent；空工作区的普通初始化也不能绕开该屏障。客户端断开不取消服务端复制，进度按实际 256 KiB 流读取累计并持久化。SIGKILL 后可由新进程继续同一计划，或将尚未提交计划标为回滚；原源与复制现场保留，不按目录名猜测清理权限。

账号迁移、旧资料纳管、收纳移动和全局迁移共用 `copyStorageFile`。调用方传入原冻结目标 dev / inode，创建父目录、打开暂存文件、首次写入及发布前继续验证；句柄设备与实际路径须一致。目标卷脱挂后出现的 host 同名完整目录不获得授权，不写入该树。源使用 `NOFOLLOW | NONBLOCK` 打开后再核对普通独立文件，FIFO 替换不能挂住读取。暂存采用排他创建、身份回执、同步、SHA 校验及不覆盖的 link 发布。未知空目录也不能被全局迁移认作本次创建。

完整复制后，在同一事务内更新全局根、账号、容器和生产单登记，并追加现有 `storage_location_operations` / `episode_storage_lineage` 的 `root_migration` 完成证明；最终 SQL 后、COMMIT 前再次核对源、目标和业务证据。部署配置沿用私有 `media-root-pending.json` journal，绑定原 planId / manifest SHA。COMMIT 回应丢失时保留 journal 与屏障，由新连接读取可信 SQL proof 决定恢复，不能盲目撤销配置。接管前失败保留旧实例；接管后关闭旧实例失败保留新实例与提交证明。协调器先释放旧 pool client，再激活 replacement，避免旧实例关闭等待自身连接。只有新实例建立、配置确认后才完成 ledger。

直接 application 启动和 environment 的 secret hydration 前段共用同一 publication proof 验证。`committed` 要求当次全对象及文件仍完整一致；`completed` 保留不可变历史 authority，同时验证当前可达位置的合法 lineage，允许之后正常收纳移动、编辑或删除。历史完成不能永久固定生产单的 CURRENT 坐标。

正式 Worker guard、Owner Studio 与 system status 从真实 `media_deployment().binding` 核验 dev / inode / mount；允许已授权的 host 深层媒体目录位于 `/` 文件系统，但系统根、未授权路径和身份错误继续拒绝。备份和恢复只在 SQL110 的精确生产单作用域支持 `asset_root === global root`，通用账号根映射仍要求严格子目录。平台缓存、运行状态、备份、历史库、秘密和未知资料保持原职责，旧源不自动删除。

本机存储 dialog 提供真实进度、明确错误和同计划继续／回滚；正在执行的请求刷新后仍禁用重复动作。正式页面验收包含窄窗、键盘、真实 Finder、旧源离线后的原生保存重开、可见播放及导出。多账号混合布局通过不同父目录和不同设备的实际全局迁移、原任务 compiled CLI 重试及备份恢复；证据存于仓库外 T16 交接目录，日常数据与服务未迁移。
