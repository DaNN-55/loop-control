# ADR-0019：统一媒体根与生产单物理收纳

- 状态：Accepted，按 #178 子票逐步实施。
- 日期：2026-10-31。
- 扩展：ADR-0018 的账号目录归属，以及 ADR-0008、ADR-0013 的位置映射、路径身份和恢复边界；保留其余约定。

## 决定

工作区拥有一个全局媒体根。账号、系列、未分系列收纳及生产单使用登记的稳定相对位置；可读名称只在创建目录时使用，改显示名称不搬文件。媒体根与账号根是存储配置，不属于创作蓝图。系列物理收纳与生产单创建时冻结的系列规则版本相互独立；位置变化不重写蓝图、执行快照、任务、来源及审核证据。

复用 `account_asset_directories`、`episode_asset_locations` 和 `account_directory_locations`，不建立第二套位置系统。`episode_asset_root` 继续解析该单的账号文件 I/O 根；已有产物路径相对此根，保留原字节及冻结引用。`episode_storage_location` 返回同一根下登记的生产单完整相对目录和身份，所有新路径消费者以此为准，禁止按当前标题或系列名重拼目录。历史记录没有相对目录时沿用 `episodes/<稳定 ID>`；T01 只建立兼容契约，默认创建仍使用旧层级，直到制作、删除和恢复调用方逐批验收后才启用新层级。

新的物理目录登记设备和 inode 身份，存量未纳管目录继续按旧授权与账号身份读取。定位及打开仅解析记录并检查现有目录，不创建缺失目录，不登记制作资格，不启动任务；Owner HTTP 只接受对象身份，服务端复用 Owner / CSRF、账号归属、部署映射及真实路径校验。禁止符号链接及越界目录，挂载或身份变化时停止相关写入，不回退至旧根或创建同名替代目录。

媒体根更换、旧层级纳管及同账号系列收纳调整均属于显式迁移。复用盘点、流式复制、指纹与引用校验、持久回执及原子切换。活动任务、打开的原生工程、未知付费提交和变化的盘点阻止切换；原目录保留，切换前读取可靠旧位置，重启依回执恢复。备份包含数据库中的配置、目录映射、身份和回执，以及实际生产文件；数据库、秘密、共享程序、模型缓存、独立历史库与备份保持各自职责。

## 后果与验收

只添加前向迁移，不修改已应用 SQL。目录维护与创作保存使用独立命令，已完成及归档单据的内容只读不妨碍其定位。全局根的正式设置、自动创建、迁移和恢复由后续子票实施，不能将本契约发布解释为日常数据已移动。

以正式页面 → Owner HTTP → 隔离真实数据库与文件 → 系统文件夹打开及适用原生工程为验收链路。检查旧产物字节及预览、新层级夹具、拒绝跨账号与任意客户端路径、缺失目录不重建，以及目录身份变化。UI 检查桌面和窄窗。不得使用日常数据或真实付费 Provider。

## T03：媒体根初始化与部署接管

`local_identity.media_root_binding` 登记工作区存储 Owner、实际根、设备 / inode 和挂载点。原 `media_deployment()` 的活动根优先读取该登记；恢复目标与 `import_record` 的来源位置保留，不改写冻结来源。有效现有根在正式服务启动时接管，不搬文件；Owner 设置读取不创建目录。存储 Owner 优先继承已登记身份；首次接管使用明确部署 Owner、唯一现有 Owner membership 或唯一凭据 Owner，多 Owner 歧义须由部署配置明确，不能由首个访问者抢占。

只有没有账号与生产单、源根没有生产文件或未知内容、目标实际目录为空时，才允许显式初始化。纯部署来源记录不代表业务资料。源空判定只排除可信服务配置中精确登记的模型缓存目录；缓存继续位于原处，并独立登记身份。字幕对齐保留原媒体根内的兼容授权；新根下只接受与缓存实际路径一致且身份有效的显式 `cacheBinding`，不接受浏览器传入缓存路径。已有账号或文件的根更换继续走后续受控迁移。

初始化在 Owner / session / CSRF 边界后协调数据库绑定、私有部署文件、初始化回执和待完成日志，再重载 HTTP 服务与 Worker。旧恢复回执仍证明原部署，新的初始化回执仅授权本次新根。下一进程按数据库提交位置恢复或完成待完成日志；无法确定一致位置时停止启动。数据库、Keychain、共享程序、模型缓存、独立历史库和备份位置及备份开关不随媒体根变更。已有 `create_account` 的首个 Owner membership 要求由后续账号创建票衔接本存储 Owner 契约，本票不放宽创作对象权限。

## T09：原生工程、导出与交付

Studio 工作副本、SQLite 与恢复文件、不可变工程版本、冻结工程、导出及交付文件由同一 `episode_storage_location` 定位。`episodeFiles.episodeFileIO` 只适配该持久位置与原始引用读取边界；会话不持有已结束的数据库事务，后续命令传入当前事务的位置检查。工程 / 任务 / 审核中的原始来源引用和 SHA 保留，实际读取位置单独传给原生复制、渲染与包校验。Worker 的隔离 staging 按原始冻结坐标放置已核验输入，不改写工程或渲染指纹。SQLite 优先、缺库回执拒绝旧 JSON、工程双改冲突、Owner revision / SHA 比较及任务去重保持。

SQL120 以字面登记 prefix 比较路径，只对固定后缀使用正则；历史 legacy 冻结工程还须匹配本单已登记不可变产物的路径、SHA 和大小。原生宿主对其 Vite 缓存的真实文件路径按 path component 序列化 URL，只改模块 lexer 识别的该缓存 import，不改磁盘位置、普通 JavaScript 文本或业务来源。默认 legacy 创建不提前启用新层级；生产单 prefix 迁移 / 恢复 lineage 仍由 T13 / T14 实施。
