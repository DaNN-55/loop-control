# ADR-0008：统一任务执行与逐段本地化契约

## 状态与范围

2026-10-23，T03 / [#109](https://github.com/DaNN-55/loop-control/issues/109)。Accepted。Owner 于 2026-10-23 明确确认 A 阶段通过并批准本 ADR；这是设计决策批准，尚未部署或切换生产。B/C/D 后续票实施这些契约；A 不重写系统、不切换生产。现行 ADR-0001、0004、0005、0006、0007 的生命周期、Prompt、运行前置条件、连接版本和审核语义继续生效。

依据为隔离库的 230 条历史迁移、当前函数定义和 [A 阶段真实演练](../verification/stage-a/README.md)。演练确认现有 `HTTP派发→Worker CLI→原子领取→真实FFmpeg→回写` 路径，以及现有渲染模块生成的真实 OpenChatCut 产物；没有验证并发上限、故障恢复或完整 Owner 审批链。

## 驱动与选项

目标是单机单 Owner、多内容账号，在保留冻结输入、审批和历史证据的前提下提高可恢复性和派发效率，并能断网操作业务数据。

选择本地 PostgreSQL、一个 Node 应用服务和其常驻调度器。继续使用现有事务与 PL/pgSQL 语义。SQLite 需要重新实现行锁、领取事务和大量函数，当前收益不足以承担这一重写成本。完整自托管 Supabase 用作 A/B/C 的兼容测试设施，不作为 D 的最终运行架构；否则 Auth、REST 网关和平台秘密存储仍是运行前提。A 没有引入新 npm 依赖。

## 服务与权限边界

- 浏览器只通过应用服务查询和提交命令，应用服务拥有业务事务；Worker 只消费冻结任务包、解析凭据引用、验证文件、执行并回写结果。执行器不能代替 Owner 审批或任意改变蓝图、Episode 阶段。
- B/C 保留现有 Supabase RPC 和 Owner 会话边界，统一按钮与定时入口的持久任务语义。D 按路径接管查询和命令，保持一个领域内一致的数据访问方式，不为内部队列、密钥或单元测试增加第二套公开 API。
- 同一命令只有一个权威写入端。迁移中的前端路径要么已接管，要么明确不可用，不能回落到生产 URL，也不隐式双写本地与云端。
- 服务仅绑定 loopback；仍验证 Owner 会话、精确 Origin、变更请求的 CSRF、账号成员关系和规范文件路径。`account_id`、`asset_root`、凭据引用均不能仅凭请求参数信任。原有 RLS 在过渡期间保留；服务端内部角色不交给浏览器。
- 当前本机控制面不拥有业务数据；D 新增的应用服务才是查询与命令的权威。通过明确迁移完成状态改变职责，不暗改 CONTEXT 中现行定义。

## 任务领取、容量与结果事务

现行证据：外层领取只遍历 ready 任务，在资源组 advisory lock 下计算 running 数，然后调用 legacy 领取函数；租约回收位于内层。仅有过期 running 任务或过期任务占满资源组时存在无法进入回收路径的结构性风险，T05 必须先实际复现。当前运行约束的 worker capacity 被用于单组上限，不能据此认定已有全机容量控制。A 未修复或宣称这些行为通过。

目标事务顺序：

1. 在独立恢复步骤回收已过期的尝试；不能以存在 ready 候选为触发条件。回收与容量计算在可串行化的临界区内完成，活跃续租不被回收。
2. 领取事务先锁定全机容量，再按稳定顺序锁资源组，选取满足依赖、退避时间和尝试预算的候选；保持 `FOR UPDATE SKIP LOCKED` 或经真实竞争测试证明等价的语义。锁顺序固定，执行期间不持有数据库事务。
3. 全机执行槽位与 CPU、渲染、下载、Provider/Adapter/连接资源组分别约束。有效上限取可信连接/Provider、Adapter 安全上限、整机配置的保守最小值；缺失可信 Provider 限额时沿用 Adapter 保守默认。单组上限不能代替全机计数。
4. 在同一事务写入 task running、唯一 task_run、冻结输入、租约持有者及到期时间，之后释放锁才启动执行器。按 Episode 轮转，避免单条长生产单持续占据前沿；没有空位时保留排队，不能重复生成任务代替排队。
5. 回写在同一事务验证 task、attempt、租约 token 和有效租约，写入结果/产物索引并释放容量，再触发后续满足依赖的业务步骤。失败/重试的尝试历史保留；旧尝试迟到的结果被拒绝，不能覆盖新尝试、审核和产物引用。

现有尝试语义必须保持：`tasks.attempt` 是已领取计数；首次领取返回的 Worker attempt 和 task_run attempt 为 0，而 tasks.attempt 为 1。不得在迁移中把这两个值直接当成相同编号。新增 lease token 是防串代凭证，不能取代业务尝试记录。任务提交/重复点击的幂等键引用同一冻结输入，输入变更产生新版本；进程内 Map 仅减少重复唤醒，不能作为唯一防重机制。

Worker 当前每 5 分钟调用租约刷新，租约窗口为 30 分钟。B 保留兼容窗口并验证刷新和回收竞态；C 将参数与调度状态显式配置。常驻调度器在用户动作后被立即唤醒，并以 5 秒扫描兜底，防止扫描重入；空槽且所有前置满足时，以提交成功/ready 到原子领取成功衡量 5 秒目标。不能把轮询周期当成响应时间证明。

| 常驻调度 | 与应用服务同一部署，短数据库事务领取，受控子进程执行；不引入 Redis、消息中间件或第二套定时服务 | T06–T09 持久排队、防重、公平、退避、容量及租约真实竞争测试 |

## 恢复与迁移顺序

B 先建立可恢复的完整备份，再修租约。业务备份应覆盖实际实体与引用，不能继续把旧 14 表 best-effort JSON 当作完整备份；健康检查、备份和提醒各自记录结果。备份须在空白测试库真实恢复，核对实体数量、外键、冻结快照、审核和选定媒体指纹。数据库备份不包含 Keychain 明文；恢复应校验引用可解析，无法解析的连接明确不可用并由 Owner 重新录入，不能自动替换旧版本。

C 依次统一持久执行入口、全机/资源容量与公平消费、预构建与唤醒、通知去重/健康/备份触发、读取优化和已审核成片复用。复用键必须包含冻结工程、素材及音轨字幕、导出参数和输出完整性；来源变化或产物损坏不能复用。

D 按 T12–T25 已发布依赖推进：只读目录与 PostgreSQL 导入 → 本地身份 → 配置 → 连接秘密 → Episode 输入和 Worker → 分镜 → 旁白/媒体 → 对齐与同步预览 → Studio → QC/发布包与生命周期 → 自动化 → 新环境恢复 → 移除 Supabase/n8n 运行依赖。每段完成同一路径的 HTTP/DB/产物验证后再交接权威源。

Auth 用户外键、`auth.uid()`/`auth.role()`、角色授权和 Vault 依赖必须逐一登记并前向适配。先明确 Owner ID 映射和事务身份，再迁移调用方；不能在纯 PostgreSQL 中盲跑旧迁移或制造无权限检查的空壳 Auth/Vault 来伪装兼容。旧迁移保留。所有试验继续使用隔离数据库，不导入生产秘密。E/F 搁置，生产切换、合并和删除旧环境需 Owner 后续批准。

## T07 实施细节（2026-10-23）

本节细化既有容量/轮转契约，不改变B/C兼容环境与D接管顺序。DB中的单例整机capacity（默认2）为跨进程权威；调用者只能降低本轮上限。领取在全机锁后回收租约，按持久Episode轮转序号及任务创建顺序选候选，在稳定资源键顺序下同时约束Provider、Adapter、连接及CPU、渲染、下载资源。受信服务可在worker_resource_ceilings为任一资源（包括独立连接）设置更低上限，不能借此提高平台默认值。未知Provider限额沿用Adapter保守值；不从蓝图任意扩大限额。轮转序号在领取时持久更新，执行期间不持有事务。

统一dispatcher先原子领取再启动子进程，已领取包及围栏token只经stdin传递；Worker先验证/续租该尝试，继续原预检与结果事务。普通HTTP唤醒消费同一全局持久队列，任务ID仅标识已提交命令；Episode参数保留planner范围，执行消费仍公平共享。操作员直接Worker单任务入口保留定向排障语义，但同样受到DB全机与重叠资源限额。进程内并发只限制当前dispatcher，不能代替全机计数。每个已启动消费者完成后立即补位，持续发现执行期间新加入的任务；没有可领取任务时不启动空跑执行器。

失败或租约回收而重新ready的任务写入available_at，指数延迟1秒起、最大30秒，尝试预算不变；进程重启不清除退避；服务专用的剩余退避读取使用数据库时钟，避免宿主/VM时钟偏差造成提前退出，不增加浏览器命令。T08再负责启动预构建与常驻五秒兜底；T07不把默认测试预算或轮询间隔冒称产品五秒性能保证。
