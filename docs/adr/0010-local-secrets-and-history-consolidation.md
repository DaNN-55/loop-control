# ADR-0010：秘密统一存储与历史差异整合

状态：Accepted。日期：2026-10-26。Owner已授权清理Supabase、把秘密迁入本地Keychain，并整合全部备份差异，允许核验后清理来源。不新增备份，不调用付费Provider，不提交或推送。

## 决定

- 当前主目录的PostgreSQL、媒体库与专用Keychain为权威源。停止应用及Worker后整合；每个来源按内容摘要登记，可重复执行且不重复插入。
- 业务记录按主键追加缺失项；当前已有记录保持原值。相同主键的旧版本及不适合进入当前运行表的旧运行状态存入`local_identity.history_*`，在Owner界面可查询来源和原值。该历史是当前项目的版本数据，不再依赖原备份或n8n。
- 导入的历史任务在数据库领取边界永久排除；原始状态保留。旧会话、密码摘要、连接在线资格、网络授权和自动化计划不作为当前授权重放。只有当前Owner正常发起的后续操作可创建新任务。
- 媒体与独有文件按摘要合并到本地内容库；可匹配的现行媒体补齐到正常路径，同路径不同内容保留独立版本。元数据声称的摘要和实际文件不符、缺失媒体及负向夹具如实登记，不能伪造恢复成功。
- Provider凭据与本地数据库口令进入现有专用Keychain。运行配置只保存不透明引用。专用Keychain的解锁钥匙存入本机登录Keychain，通过限定服务/账号的本机helper和stdin读取，解决自解锁循环；不在环境、参数、日志或文件保存明文。
- 过时密码、失效令牌与旧部署秘密作为历史秘密保留在专用Keychain，仅保留来源及引用；不将旧值覆盖当前凭据。云端Vault在停用前转入专用库，连接资格仍须日常环境验证。
- 移除Supabase SDK/CLI依赖及可执行云端入口。旧迁移、领域类型和回归协议记录保留为历史，不得成为云端回退路径。云端只处理已确认的`loop-control`项目，其他项目保留。

## 2026-10-27 分类、归档与清理预览

历史资料按来源元数据计算业务资料、配置与模板、测试与诊断分类；显示名与原始路径、来源 ID、内容摘要分开，原件身份和 JSON 文本不重写。来源分组、文件、原始来源信息和技术记录默认折叠，文件与记录分别分页。

归档按当前 Owner 的来源批次操作，仅写独立的 `history_source_preferences` 标记，可恢复；不移除来源关联或文件，不改变下载和还原能力。操作沿用有效会话、精确 Origin 与 CSRF，其他 Owner 不可操作。

永久清理本轮仅预览，没有执行接口。受控服务端函数核查来源关联、跨来源共用内容、保护映射和普通历史值依赖；跨 Owner 的分享检查只返回计数，不返回其他 Owner 的来源或路径。未发现上述依赖的独占内容仍标为待核查，不承诺可删除或实际可释放空间；正文中的间接引用、运行引用及磁盘状态还需进一步核验。预览不修改历史表、索引、文件或 Keychain。

## 验证

逐来源记录覆盖、冲突及文件摘要核验；检查全部外键、Owner可见性、历史任务不可领取、重复导入无新增；真实Keychain读回/锁定拒绝、无明文扫描、正常停止启动和HTTP/UI；类型、默认回归及原生构建。来源数据全部接入并核验前不得删除来源。无法取得的内容明确记录，不把缺失当作完成。

## 退役阶段兼容

源快照包含一条`publishing_review`生产单；当前领域已退役该阶段。导入不伪造`production_completed`或改写成其他状态：仅对管理员登记的历史生产单放宽阶段约束，并在本地界面以只读方式显示原阶段、任务与产物。正常新建流程仍受原阶段约束。原脚本/系列记录在全部来源中缺失时，当前只读投影留空，原始引用仍在历史版本；不制造替代素材。

## JSON 数值精度

PostgreSQL JSON 的小数和大整数可能超过 JavaScript Number 的精度。历史 COPY 解析采用 Node 24 原生 `JSON.rawJSON` 保留数值原文；之前解析造成舍入的版本保留并标记为“旧导入精度版本”，追加完整精度版本，不覆盖当前业务。详情以 PostgreSQL JSON 文本返回与显示，避免 HTTP/浏览器再次解析舍入。当前原有 289 条任务与原恢复数据库直接文本对账一致，348 个原产物也未改变。

## 2026-10-27 原件退役

6 份旧 Keychain、两份旧工作树及指定迁移/诊断原件在逐文件和秘密覆盖核验后删除；当前专用 Keychain、历史内容、活动媒体、Python 与 Studio 保留。生成依赖/缓存无需再复制进历史库，源码、锁文件及独有诊断内容按摘要保留；重复 Buffer JSON 保存原内容引用和已实测的编码参数，避免保留膨胀的重复载体。删除只针对精确清单中的不变文件和链接，目录仅在为空时移除，不递归删除顶层运行目录。

历史文件遇到多层转义时复用已有秘密，`metadata.replacements` 可使用 `encoding: existing-secret-transform/v1`：从 `reference` 读取秘密，按可选 `valuePath` 选择其 JSON 字段，再重复 `encodingDepth` 次 `JSON.stringify(value).slice(1,-1)`，最后替换 `marker`。逆序处理所有替换后，原始 SHA 必须一致。该方式不新增转义派生秘密；普通原始值和单层 JSON 引用继续兼容。文件下载仍只返回受保护内容。

## 2026-10-27 同值历史秘密去重

294 个历史逻辑引用对应 56 种完全相同字节值。其中 3 种复用现有业务引用，其余保留 53 个历史条目；删除 241 个重复 Keychain UUID。当前运行/连接的实际 UUID 与范围外条目保留，比较值时不做大小写、空白或 JSON 格式归一化。

既有 `secret-index.json` 增加两项无秘密值的元数据：`referenceAliases` 将旧 UUID 指向保留 UUID，`nameAliases` 将旧名称指向保留条目。运行读取先解析 UUID 映射，再调用原有固定路径/服务的 native helper；非法目标和环引用明确失败。`secrets:list` 仅列 61 个保留名称，旧名称的复制和同值再次导入仍复用保留值。真正改变旧名称的秘密值时创建新 UUID，不覆盖任何既有值。

为保持原证据的字节身份，历史文件正文、记录 payload、来源成员与原始 SHA 均不重写。177 行文件 metadata 的 `replacements[].reference` 和 5 行保护映射指向保留 UUID；`marker` 字符串仍与原文一致。不可变正文或历史 payload 内的旧 UUID 通过 `referenceAliases` 继续解析。该映射是当前历史还原的一部分，不能当作备份或过时文件清理；它不保存任何秘密值。

删除前后须验证所有 294 个逻辑引用值相同、187 份文件及 12 份保护映射精确还原，并核对历史身份和现行业务摘要。无明文落盘/无新增备份；错误恢复材料只存在执行进程内存。

61 个保留名称使用「功能·条目」的显示标签，命名与物理路径解耦。新增的 61 个重命名别名与原有 241 个去重别名合计 302 个；所有映射只指向同一保留 UUID。功能分组写入索引元数据，历史/现用状态继续单独展示，模板资料不标为可用业务密钥。`keychain-db`、索引、native helper 和历史内容仍在原固定根目录，不迁移或复制实体文件。

## 2026-10-27 非秘密模板归档

逐值及来源核验后，32 个模板项全部确认为非秘密：22 个公开模型名、4 个空配置、2 个明确占位符，以及公开地址、公开资源型号、示例费用、注释各 1 个。旧环境变量匹配的空白表达式会跨行，把空 API Key 的下一行误收进 Keychain；改为只匹配行内空白，并跳过两种已确认的文档占位符。真实非空秘密仍沿用原保护流程。

这些值以 `template-literals` 普通 JSON 文件登记到既有 `history/content` 和 `history_sources/history_files`，Owner 可在历史资料搜索「模板配置」下载。索引新增 `historicalLiterals`：canonical UUID 对应固定内容库文件的摘要/字节数及单值摘要/字节数，不含明文。兼容读取先解析原 UUID 别名；仅已登记的普通值从该文件读取，并校验文件与单值摘要，其余仍调用原 native Keychain helper。原 payload、文件正文、marker、原 SHA 与来源身份均不重写。

32 个名称及相关旧名称移到 `historicalNameAliases`（140 项），不再进入秘密列举/复制和管理员秘密列表；同值历史再次导入仍复用该普通值引用。原 UUID 别名继续保留。现有秘密名称剩余 29 项（运行 2、业务 6、历史 21），专用 Keychain 实际剩余 45 项，包括命令外连接 7 项及范围外 9 项。本轮只删除这 32 个确定的非秘密条目。

删除前后 309 个逻辑引用值相同，187 份历史文件及 12 份保护映射均精确还原，当前业务/认证摘要不变。仅新增普通历史资料的来源和文件登记，不新增备份、不改变当前凭据及连接授权。

## 2026-10-27 剩余历史秘密复核

剩余 21 项逐值和来源核验后，将 13 项转为普通历史资料：旧隔离端口的默认口令测试地址 4 项、公开固定签名且来源为隔离配置的 demo 令牌 2 项、`UI_LOCALE=zh` 1 项、自然语言历史授权说明 5 项、明确非真实的离线 UI 录入夹具 1 项。demo 令牌的 HMAC、issuer、role 与来源同时验证；不单凭名称或 JWT 声明认定为示例。授权说明仅是历史数据，不是当前执行指令。

普通值读取明确兼容 `template-literals` 和 `history-literals` 两种目录格式，继续核验目录文件及单值摘要。前轮 32 项映射不变，本轮独立文件登记为 `普通历史资料/非秘密验收与配置原文.json`；累计 45 个普通值、328 个普通名称映射，秘密旧名称映射剩余 19 个。原 UUID、正文、payload、marker 与历史原始 SHA 不重写。

8 项真实认证材料继续加密：实际历史口令 3 项、Cookie/Bearer 2 项、真实旧项目访问材料 2 项、自动化用户 bcrypt 摘要 1 项。未发现它们是源码中的公开常量或明确占位值；不能因环境曾用于验收就将实际认证材料转为普通文本。保留不表示旧值仍有效，也不恢复旧身份/会话。

本轮精确删除 13 个 Keychain 项，当前命名秘密 16 项（运行 2、业务 6、历史 8），实际 Keychain 32 项，包含命令外连接 7 项与范围外 9 项。全部 309 个既有逻辑引用值及 199 份原文还原一致，原业务、认证和历史身份摘要不变；不新增备份，不修改运行凭据或连接授权。
