# ADR-0043：发送阶段与原操作回执恢复

状态：Accepted。日期：2026-11-11。用户批准实施48类中的4/5/17/24，并确认未知请求可经风险确认另发新请求、明确未外发的临时准备故障最多自动恢复2次。

## 决定

保留任务、供应商提交、原生产内容、原生发布和UI访问各自的权威，不将它们压成一个成功／失败标记。为新图片／口播尝试增加Worker私有的准备／进入发送事实，绑定task、attempt、lease与冻结请求指纹。仅当持久事实证明尚未进入transport时，才允许同一输入的临时本机准备恢复；次数跨attempt按同一task累计，最多2次。参数、权限、过期输入和原未知请求阻止继续；进入发送标记的提交结果不明也按未知处理。旧submission／reservation没有新事实时不推断为未发送，不重写历史。

完整供应商响应仍不等于可恢复产物。沿用ADR-0039与现有NativeAttemptOutput：实际解码、校验文件并fsync私有publication receipt后，才在同一发布事务登记received与任务完成。付费图片／口播的完整凭据形成后，登记、文件发布或COMMIT失败保留publication hold；NativePublicationUnknownError向上传递，不转换为通用失败重试。显式恢复只验证并登记原文件，不调用供应商、不重新读取秘密；没有完整有效凭据时不承诺恢复。

本机写入未知后，客户端先通过Owner范围的只读查询核对同一幂等意图，命中则恢复原成功回执；未命中仍未知，绝不自动POST。返回沿用原公开结果投影，禁止暴露私有清理清单、lease或发布凭据。成功写入后的目录读取失败只重读目录。

图片和口播共享这套阶段语义。旧请求仍未知时先提供原请求核对；新的付费生成必须重新确认、带retryOf原任务、保留原记录和费用预留，当前工程／目标／连接／确认资格仍须通过。新结果只进入候选区，不自动启用或采用。停用内容与后台待核对提醒继续遵守ADR-0041；回收站保护继续遵守ADR-0042。

## 取舍与验证

不新增供应商网络重放层或原始HTTP响应缓存。复用既有发布凭据和精确恢复，减少两套产物登记并存。无法消除网络／进程中断，也无法凭新日志还原旧503唯一原因；不将找不到回执当作没有执行。

通过实际executor故障注入、真实隔离Owner HTTP／PostgreSQL／文件／Worker验证：未发出原因、跨attempt最多2次、进入transport后0自动重发、旧未知保留、完整文件后登记失败与COMMIT丢失的原恢复、明确拒绝、风险确认新生成、迟到结果不自动采用、Owner和旧版本拒绝。每批独立审查，并更新48类逐项证据；合成Provider响应不等于真实供应商质量／扣费验证。

已识别的准备恢复只处理数据库序列化/断连及本地临时IO的明确错误码，共用持久预算；Keychain权限/不可用不假定为临时故障，不反复弹系统授权。同步HTTP 4xx（408除外）与首音频前的语音45000000/45000001明确拒绝归rejected；部分音频、未知代码、5xx、畸形响应保留unknown。错误码依据：[供应商语音合成官方错误码](https://docs.volcengine.com/docs/doubao-voice/error-code-query-1?lang=zh)。

本机只读回执适用于实际持久command_receipt的命令；无回执的清理预览、原清理恢复及必须重建运行会话的打开类命令沿用各自显式恢复协议，绝不因回读失败自动重放其他写入。无完整有效publication receipt时保留hold并拒绝假恢复。

历史兼容：旧executor会在文件校验前提前登记received，因此163允许stopped legacy received且无任何provider_dispatch_facts、无publication hold、无已有child（图片还须无provider_task_id）的请求，经新的风险确认与retryOf建立唯一替代。原记录不改，绝不改判not_sent；任一新事实或hold都禁止借用这个例外。服务端重新计算unknownRetryAllowed，UI不自行猜测旧协议资格。
