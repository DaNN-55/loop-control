48 类规则已经认可，适用部分已实施或验证保留。下方「修复前实现」保留最初只读审计，「本次验收」说明本轮结果。回执规则已确认，分类实现仍待完成；回收站已按认可方案迁入正式产品，启动不清理现有作品。查看逐项验收矩阵 · 验收报告 · 回收站迁移报告

已经认可的总规则

不再使用的内容，不应继续阻塞当前作品。关闭口播、字幕、配乐或音效，应解除当前制作依赖。旧任务、可能的费用和供应商结果仍保留记录，作为独立提醒；不能因此自动重发、自动重新启用或自动采用。

「关闭提示/窗口」只收起界面；「停用/不使用」改变当前作品的需求；「取消任务」只在任务/供应商明确支持并确认后才算取消。这三种操作需要不同的名称和结果。

修复前发现的问题（审计基线）

  • 口播开关只改变原生工程并静音保留音轨，未处理旧口播任务关联；目录汇总又不看这个关闭标记，所以仍显示阻塞。
  • 待准备计数只判断 mode 与采用音轨，没有判断 enabled，因此关闭后仍可能计入。
  • 真正导出检查主要看已用文件、连续画面和启用字幕，与列表历史任务汇总不是同一套判断；可能出现「列表需处理但实际可导出」。
  • 只静音仍保留原生媒体节点时，文件引用也仍存在。若「关闭」含义是舍弃，需要明确从导出依赖中排除，不能只调整音量。
  • 口播发送前拦截与发送后断网目前都可能归为 unknown；不能据此推断本次已经发给供应商。

已认可的异步规则（回执分类部分暂缓）

事实是否阻塞允许操作停用当前内容后
尚未发送/本机校验失败只挡本次动作与必需依赖修正后重新提交；不应提示已扣费解除制作依赖，保留失败记录
明确拒绝/明确执行失败当前必需内容仍缺失才阻塞修正后重试原输入；新参数属新请求保留历史，可继续制作其他内容
已排队/执行中等待当前必需结果；其他无冲突操作可做等待/读取状态；支持取消才可取消从当前作品摘下；在途事实仍可见
已发送，结果未知阻止自动重复付费；不自动阻塞不用它的导出查原任务/供应商；必要时独立确认新付费请求保留费用/结果核对提醒，不自动采用迟到结果
已有产物，登记未完成尚不可当作已可用恢复同一次产物登记，不重新生成作为待恢复记录，不成为无关交付门槛
候选完成，未采用只有当前必需内容还空缺才阻塞预览/采用/舍弃；无需重试保留候选/历史，当前作品不再等待它
已采用且当前文件有效可继续编辑/导出/撤回；内容变化需重新确认解除当前引用/可执行依赖，文件历史保留
已确认交付，但后来文件损坏/缺失不可假装可下载或已验证读回校验或恢复该交付文件不是「关提示就解决」，需要真实文件证据

实施边界

  1. 关闭口播/字幕/配乐/音效 = 不使用这部分，不再列为当前作品阻塞；保留文件与任务历史。
  2. 旧任务可能扣费但本片已不用，放在「待核对请求」提醒中，不把整张生产单标成「需处理」。
  3. 列表「需处理」只来自当前实际必需内容、当前已用文件和未解决成片问题。后台历史失败不直接升级为整期阻塞。
  4. 失败重试、查询原任务、恢复产物登记、重新付费生成，分成不同动作。
  5. 回收站默认 5 GB，超限按最早安全项目清到上限内；刚入站和单项超限保留，活动/未知任务禁止入站，共享/离线/变化项不强制清理；正式实现与隔离验收见回收站报告。
