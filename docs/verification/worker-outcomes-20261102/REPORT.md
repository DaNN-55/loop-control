# Worker 异常收尾与原生产物发布恢复

日期：2026-11-02。范围：本地 Worker 异常分类、最后一次失败的重试边界、发布未知结果的持久保护及显式恢复。未提交或推送。

## 改动与影响

- 准备或执行异常按已领取尝试和最大次数回报；最后一次失败正常落为 `failed`，不再因错误请求重试而滞留 `running`。尚有次数时保持原重试规则。
- 产物发布前持久登记同一任务、尝试和租约；成功登记结果时在同一事务移除保护。可以确认安全回滚时解除保护；提交或还原结果未知时保留现场。
- 专用异常和只包含任务 ID、尝试序号的消息贯穿发布器、实际 Worker CLI、常驻服务和消费者；普通异常仍走原失败路径。
- SQL133 阻止发布未知任务被普通失败回报或租约回收重排。状态触发器在任务行锁内检查保护，覆盖失败回报先开始、等待发布事务提交的并发窗口；沿用原交付函数的锁顺序。
- 默认只读查询待核对登记；显式恢复只接收任务 ID 和尝试，从数据库解析租约和真实位置。保留目录身份、冻结输入、凭据、候选和旧文件指纹验证，不执行 Provider、不自动采用候选。

设计依据：[ADR-0023](../../adr/0023-native-output-publication-reconciliation.md)。操作说明：[恢复命令与拒绝条件](../../agents/native-output-recovery.md)。

## 复现和验证

最初的真实 PostgreSQL 复现中，最后一次准备／执行失败后任务仍为 `running`，租约未释放；修复后同一路径落为 `failed`，任务运行记录与重试字段一致。另一个真实并发用例复现了失败回报等待锁后绕过新保护的窗口；补齐行状态触发器后拒绝迟到回报，保留 `running` 与当前发布保护。

新用例使用真实 Owner 命令入队、`loop_worker` 数据库角色、实际租约／任务结果、文件发布与恢复；供应商响应在外部边界受控。分别执行真实 `COMMIT` 和 `ROLLBACK` 后注入确认丢失，未用单纯 mock 代替提交边界。实际编译后的 Worker CLI 和正式常驻服务均参与测试。

## 使用与验证边界

本轮没有迁移日常数据库、重新编译日常运行目录、重启日常服务或调用真实付费 Provider。数据库测试使用新建的隔离数据库；真实进程测试使用独立源码和编译目录。现有并行改动及暂存内容保留。

新能力部署前仍需在已授权的服务更新流程中应用 SQL133 并准备对应运行产物。恢复 CLI 的日常部署配置入口未对日常数据执行；实际查询、权限和恢复实现已通过隔离数据库验证。页面仍显示现有任务状态，待核对查询通过命令提供。
