## 实现与行为

复用图片／视频已有的 `useWorkspaceReading`。读取结果同时检查工作版本身份、版本号、请求先后顺序及当前入口生命周期；镜头切换或卸载后，即使传输层忽略取消、JSON 解析较慢或命令已经在服务端执行，旧回复也不会再更新当前界面。过时请求的错误同样不覆盖新操作结果。客户端取消不会撤销已开始的服务端操作。

- 口播候选保留 2 秒刷新间隔，显式刷新和操作前读取共用读取保护；后续候选操作仍按原顺序执行。
- 音效准备保留 3 秒间隔及原 `refreshWorkspaceAudio` 命令；原生保存后的读取也纳入镜头生命周期保护，准备／采用／混音结果可以阻止更早的回复回写。
- 分镜台保留立即检查、3 秒刷新及原 `refreshWorkspaceNarration` 命令。父级接收操作结果时立即登记新状态，保护不依赖 React 下一次渲染；暂停刷新和进入编辑器时使旧读取失效。
- `refreshWorkspaceNarration` 仍执行原有首次装配逻辑。首次装配条件、人工编辑保护、显式采用、服务端版本冲突、真实媒体和工程校验保持原实现。
- 草稿的 Map、`sessionStorage` 键、镜头隔离及输入指纹失效条件保持。刷新不会额外保存、生成或采用。

实际生产改动仅为 `src/local-app/useWorkspaceReading.ts`、`WorkspaceCandidatesPanel.tsx`、`WorkspaceAudioPanel.tsx` 和 `ProductionWorkspacePanel.tsx`。未引入依赖或数据库迁移。
