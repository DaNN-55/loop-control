# #144 首次任务隔离补修最终验收

最终 Spec 复核确认，重开的首次任务缺口已闭环，可重新关闭 #144。原自然租约、真实旧执行器晚写、三组提交/断连恢复和已接纳文件身份的验收继续保留。旧的阶段报告及此前关票、重开说明仍为历史记录。

同单实证发现，首次 TTS 及它自动创建的对齐任务可能在能力领取开关启用前插入，040 因此漏加输出命名空间。补修将 TTS 启用更新移到创建 RPC 前；必要的 042 前向迁移进一步让新任务的输出归属依据「全局已启用的原生生产单、12 类支持任务、ready/attempt 0」冻结。具体能力开关继续控制规划与领取，租约、预算、原 RPC 围栏和已领取输出不可变约束保持。已应用的 039–041 文件未改，042 已登记在初始化与恢复入口。

042 仅应用本轮新隔离库。重复应用通过；旧业务行、旧迁移记录、领取/租约函数及两个调用账本逐项保持。真实 PostgreSQL 回归覆盖：所有能力开关关闭时，自动对齐与首次 TTS 仍取得独立输出；同类型两任务路径不同；未托管/未启用及旧任务不被改写；真实 Worker 领取在未开能力时返回空，显式开能力后可领取；已领取输出变更被 `22023` 拒绝。创建事务更新和身份保护保留。

主区 042 环境的真实 Owner HTTP + PG 两项首次 TTS 回归通过，默认 5000ms。测试以外层事务/SAVEPOINT 回滚，实际验证创建触发器和失败回滚；readiness/wake 替身仅用于阻止额外 Provider 执行，不能将其冒称普通持久提交或额外真实 TTS 调用。最终同单新本地片段、审核渲染、final 和发布包已正常完成并重启读回，21 个产物的数据库摘要、正常 HTTP 字节和磁盘相符。

此前已接纳的 TTS 与早先自动创建的对齐任务保持原格式，没有补写命名空间或重发请求。042 的保证作用于之后新插入的受控任务。文件系统与数据库仍不是共同原子事务；原显式恢复合同、同 UID 与升级前旧进程的限制保留。
