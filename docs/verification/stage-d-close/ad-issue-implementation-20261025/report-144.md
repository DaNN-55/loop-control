最初实现遗漏了普通规划器直接 `writeFileSync(..., {flag: 'wx'})` 所需的输出父目录。新增真实 Node 子进程先复现 `ENOENT`，再用既有 `safeAssetOutputPath` 仅预建冻结父目录；不提前创建目标文件，独占写入随后通过。该失败和更早的输入复制、输入覆盖保护及辅助文件红测均保留私有原文。

发布仅保证逐文件原子替换，文件系统与数据库不组成一个原子事务；原实现的登记失败，以及下文仍未闭环的提交结果未知场景，可能留下未登记文件。失败或提交结果未知的临时文件保留诊断，不在释放租约锁后恢复旧字节，以免覆盖后续新尝试。输入使用 `COPYFILE_FICLONE`，不支持克隆的文件系统会实际复制；本票未完成通用容量或性能验收。

## 最终审查后的确定失败补修

Standards 审查指出原实现先替换 canonical 文件，登记失败只回滚数据库，可能使旧索引仍指向已被覆盖的文件。新增两个真实文件系统红测分别复现「已有文件被替换后登记失败」和「多文件发布的后续目标失败」。原自然租约成功结果与此失败分支不同，不能用前者覆盖后者。

补修取得原 task 行锁后建立 SAVEPOINT；备份所有已有目标并准备全部新临时文件后，再替换目标与登记结果。确定失败时，先成功恢复 SAVEPOINT，以确认原事务及行锁仍可使用，然后在锁内恢复旧字节、删除本次新文件，最后回滚并释放锁。备份和失败暂存保留诊断。相关定向检查为 **5 文件、22/22，默认 5000ms**，其中本模块 14 项；应用及 Worker 类型检查通过。数据库传输仍为边界替身，新增失败分支尚待整合者真实 PostgreSQL 验证。[补修摘要](144/publication-consistency-144.json)、[定向日志](144/publication-focused-144.log)

COMMIT 已发出却抛错，或连接丢失使原锁无法确认时，系统不盲目恢复旧字节，不自动重复登记或自动回报新 failed 结果；保留两代文件及私有 `publication-outcome.json`，明确记录 unknown。**这仍不是完整的文件系统/数据库一致性闭环，#144 保持开放。** 崩溃或提交结果未知仍需后续明确的核对/恢复协议；自然租约的原始成功证据对应补修前源码，不冒称已经重跑了新源码全链。

不能将剩余风险一概写成「只有未索引文件残留」。部分原生输出按 task UUID 命名，但视觉清单和 `storyboard-v1.json` 等路径没有该保证；现有 Studio 结构修订可再次创建分镜任务，旧 completed 产物索引仍在，新任务可能复用同一路径。TS 与多个数据库触发器又要求主产物严格等于冻结输出路径，不能只在本 helper 改成 attempt 后缀而绕过合同。因此本次只补确定失败恢复，不前向改写 SQL 或冻结输入，也不关闭 unknown 对既有索引文件的潜在影响。

## 审查补修的本轮真实 PostgreSQL 复验

使用独立新合成任务的真实 running fence，实际 helper 调用真实 refresh_worker_task_lease；在报告处以同连接真实 SELECT 1/0 触发 22012。SAVEPOINT 恢复后，以及文件恢复完成、完整 ROLLBACK 前，第二 PG 会话的 NOWAIT 均得到 55P03，证明恢复期间原行锁仍持有。旧字节恢复，恢复 Worker 前无新 artifact，输入、预算和 attempt 不变；随后专属 Worker 正常完成。原自然租约控制材料原样恢复，新材料单独封存。

此补验使用受控私有 canonical，未发送真实 report_worker_result payload，也不假称具有真实旧数据库索引。COMMIT/连接未知、跨任务历史索引恢复继续未验收，#144 保持开放。最终 Standards 复核确认确定失败 P1 已修复。
