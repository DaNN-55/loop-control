# P2：注销失败后的恢复与请求围栏

2026-10-25，Asia/Shanghai。仅修复本轮只读复查发现的注销失败问题，沿用优化 worktree、`codex/local-first-stage-a` 和未变的 HEAD `49e2538`；不提交、不新增在线请求、不进入 E/F。SQL 合同一致性建议暂不处理。

## 修复行为

原实现会在注销请求前清除客户端登录标记和 CSRF，但失败分支只显示错误，留下目录页面：刷新被登录围栏直接跳过，后续写请求因空 CSRF 被拒绝。

现在仍在请求开始时失效会话/请求代次并关闭目录读取；无论注销成功还是失败，都在 `finally` 清除本地工作区、详情选择及 CSRF 状态。失败时显示「未能确认退出，请重新登录。」并转入登录表单。重新登录走原有真实登录接口，重新取得 CSRF。没有恢复未经核实的旧会话，也没有改客户端代次逻辑或服务端鉴权。

网络失败时不能确认服务端是否撤销旧会话，因此提示没有声称「已成功退出」。本次选择显式重新登录，代价是失败后需要再次输入密码；无需整页重载。

业务源码只改 `LocalCatalogApp.tsx` 的 `logout`，测试只改同名组件测试。`client.ts`、SQL、依赖、迁移及其他 D 实现保持本次修复前字节。

HTTP 503 在实际组件/客户端边界用受控响应覆盖；真实 Chrome 覆盖的是浏览器传输中断，不能把它称为真实服务端 503。退出 pending 与迟到响应竞态由可控异步组件测试覆盖，不将快速浏览器故障冒称所有竞态的运行证明。

浏览器驱动保留两次失败：选中账号后的 `wait --fn` 超时，随后实际控件读取确认账号已选中；另一次在保存请求发出后立即检查弹窗消失过早，实际响应未完成。没有延长超时、重复写请求或改产品断言。之后独立读取 UI、唯一 POST 200 和数据库回执完成核对，两份原始失败日志继续纳入索引。
