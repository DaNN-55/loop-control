# 设置三页紧凑布局 Demo（第三轮）

日期：2026-11-11。范围仅为隔离原型；未迁入正式连接、密钥或文件清理界面。

## 方案与入口

三个方案共用现有 Owner 设置外壳、语义主题和 Button。底部「布局方案」可直接切换 A/B/C；左侧三页切换保留当前方案。English 与明暗主题均可切换。旧 `variant=compact/balanced/spacious` URL 兼容进入 A。

| 方案 | 结构 | 适用场景 | 入口 |
| --- | --- | --- | --- |
| A · 对齐列表（推荐） | 名称、信息、行尾动作三列；详情紧贴当前行 | 最接近现有表格直觉，浏览和修改都紧凑 | [打开 A](http://127.0.0.1:5210/src/local-app/settings-review-v2.prototype.html?page=connections&variant=rows) |
| B · 主从分栏 | 紧凑主列表 + 单个详情区；窄窗变为可滚动列表和下方详情 | 反复检查同一连接、密钥，减少详情撑开列表 | [打开 B](http://127.0.0.1:5210/src/local-app/settings-review-v2.prototype.html?page=connections&variant=split) |
| C · 用途分组 | 按图片/视频/语音/声音分组；回收站按最早/最近/共享分组 | 连接增多后，优先按用途寻找 | [打开 C](http://127.0.0.1:5210/src/local-app/settings-review-v2.prototype.html?page=connections&variant=groups) |

每个 URL 的 `page` 可切为 `secrets` 或 `recycle`。`lang=en` 可查看英文，`theme=dark` 为深色；`stress=1` 加入长连接名称和模型标识，仅作用于合成数据。

## 针对注释的变化

- 连接展开区移除重复名称（主从详情仍保留当前对象标题），字段改为紧凑的标签—值对齐；模型、账务、版本和编辑/测试/密钥操作统一在详情底部的一个操作栏，不再一部分位于右上、一部分位于左下。
- 密钥的当前版本和用途保持单行对齐，「查看/复制」固定行尾；历史折叠与「前往连接更换密钥」共用同一底部操作栏，取消独占整行的空白按钮区。A 中默认 gpt-image2 的展开区实测 101px。
- 回收站容量、上限、策略合并为紧凑设置区，恢复/永久删除固定行尾。默认 5GB 可修改、恢复、超限按最早安全项目释放的模拟语义保持。
- 三页统一 32px 桌面控件、34px 窄窗输入、同一页边距和行尾动作；分组靠分隔线、标题和间距表达，不嵌套卡片。
- 连接名称最多两行，悬停标题和可访问名称保留全文；模型标识在摘要截断，展开显示完整值。用户输入和模型 ID 不翻译。
- A 的浅色详情底色、B 的主从边界、C 的用途小节是结构差异，并非同一个布局的三档 padding。

## 验证

- `npm run check`：通过，见 `typecheck.log`。
- `browser-layout-results.json`：81 个布局场景，页面、对话框和主体无横向溢出。覆盖三页×三结构×1348/768/375深浅色，以及英文和320px长名称。
- `final-boundaries-and-contrast.json`：最后长名称两行处理后，9个320px英文深色场景再次通过边界检查；axe 的局部叠层背景不确定项按实际 computed 前景/最近不透明背景补算，20个样本最低对比度4.58:1。
- `a11y-results.json`：18个桌面/320px场景，WCAG A/AA violations 为0；窄窗部分文本因覆盖层的背景判断为 incomplete，已单独核对并保留原始结果，没有当作自动通过。

- `browser-errors.json`：浏览器 JavaScript 错误0。
- 截图：`rows-*.png` / `split-*.png` / `groups-*.png`。截图为合成数据，不包含真实凭据。
