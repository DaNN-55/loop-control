## 原因与处理

上轮两条失败回执和 214 字原文已保留。旧实现没有保存被拒绝的模型 JSON，因此不能还原当时的具体开关值和时长值。代码和最小失败回归确认了以下合同问题：

- 模型同时填写顶层开关摘要、通用 settings 内的开关和逐镜覆盖，存在多个来源；本地 helper 还把“默认”误判成关闭。
- 模型同时填写顶层总秒数及各镜头秒数，要求自行保持算术一致；原文和目标总长本应由请求确定。

新增模型设计合同，与既有内部拍法分开。模型每镜只填明确口播/字幕布尔值和 1–1000 的整数相对节奏，不再重复填顶层开关或秒数，也不能在 settings 重复开关。本地编译后计算摘要和准确秒数，再执行既有正文、设置、逐镜开关、时长及朗读速度校验。

普通原文先预留每镜至少 0.1 秒、口播每秒最多 7 字的最低朗读时间，再按相对节奏用最大余数法分配剩余厘秒，合计严格等于请求目标或页面估算值。既有 v3 明确逐镜时长时，默认优化保留原镜头边界和既定时长，不由权重覆盖；仅部分明确时长时保留已填秒数，只把剩余总长分配给未填镜头。全局继承及逐镜明确开关也逐来源保护。没有改写原文、延长总长或删除校验以接收不合格结果。

继承用的“默认”不再等同关闭。失败结果保留有界模型 JSON、供应商响应身份和 usage，仍是 failed、没有可采用 plan，不能确认或启动；沿用现有 Owner 隔离和 512 KiB 响应读取上限。没有新增数据库迁移或依赖。
