# 图片直接采用：待用户核对

专用隔离预览：http://127.0.0.1:5183/__image_adoption 。复用与当前产品相同的候选采用组件和正式 Owner HTTP，在独立临时数据库／测试素材中执行；不修改产品代码、不额外迁移本项、不提交／推送。

本项原改动：把图片“采用到当前镜头”从“更多操作”菜单移到候选预览下方，作为直接可见的主操作；“用作视频首帧”保持独立次级操作。点击采用仍需核对并明确“确认采用”，没有自动采用。当前镜头已有视频时，主操作为“保留为备用图片”；真正用静态图替换视频仍需走“更多操作→替换当前视频”的明确流程。

样例有两个 2 秒镜头和各自同一张绿色图片候选：镜头 01 初始为空，镜头 02 已匹配本地合成视频。没有上传用户私有素材或执行供应商任务。

验证：

- 两项相关组件回归通过，10 项未选中。
- 真实浏览器点击外部采用按钮→确认采用；正式 API 读取的实际原生工程中，镜头 01 从占位 text 变成 image，2 秒时长保留，镜头 02 完全不变。
- 镜头 02 点击“保留为备用图片”→确认采用；selectedImages 增加记录，原生工程 SHA 和全部片段完全相同，原视频未替换。
- 点击“用作视频首帧”后切至视频并带入图片；API 读取的工程 SHA、片段和修订均不变，没有生成调用。
- 核对操作完成后经产品自身取消备用／取消采用，恢复空镜头和原视频，候选文件保留；最终状态见 restored.json，供用户重新从头操作。

调用记录 review-calls.json 仅含本地采用／备用／取消操作，paidCalls=0。采用结果以确认结束后的 UI 和正式 API／工程值为准，避免把异步操作中途读取当作完成。

用户操作：打开预览→镜头 01→画面→图片，直接可见“采用到当前镜头”，点击后确认，预期“已采用”、左表已匹配、时长 2.0 秒。镜头 02→图片，预期“保留为备用图片”；确认后显示备用标记，切到视频可见原视频仍在。用作首帧只选择生成输入，不直接改变当前画面或发起生成。

上一项模型默认参数已获用户批准：initialDraft 和 chooseVideoSource 与已核对快照完全相同，日常源模块包含同一实现，HTTP 200、固定后端完整，故批准生效，无需重复覆盖／重启。
