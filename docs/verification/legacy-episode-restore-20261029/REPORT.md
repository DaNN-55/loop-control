# 豆包推广生产单归档与恢复修复

2026-10-29，时间均为 Asia/Shanghai。本地服务已更新；未提交、未推送，未对真实生产单执行恢复或归档。

## 原因与影响

五张生产单均仍存在，账号未归档。默认列表只显示未归档生产单，因此豆包推广列表为空。原审计记录与归档时间为：

| 生产单 | 原归档时间 |
| --- | --- |
| 操作电脑 / 操作电脑-v2 | 2026-09-08 13:56 |
| 操作电脑-v3 | 2026-09-12 22:26 |
| 操作电脑-v4 / 电脑体检打假 | 2026-10-24 15:39 |

这五张是现存旧生产单，没有 `local_identity.input_episodes` 新版执行管理标记，也没有历史只读标记。恢复接口却先调用 `lock_owned_input_episode`，把“允许归档管理”和“已启用本机执行”混为一个条件，因此在目录可见的单据上返回 404“本地生产单不可见”。原审计可证实归档时间，无法仅凭这些记录还原当时归档操作的全部意图。

已通过 `LOOP_EPISODE_ARCHIVE_ACCEPTANCE=1 npx vitest run src/local-app/episodeArchive.integration.test.ts` 在临时库用真实 HTTP 重现相同 404，再验证修复成功。测试最初出现套接字 ref/unref 和缺失 timezone 的夹具错误，已按既有验收接口补齐，残留临时库已清理。

## 修复

- 生命周期的 archive/restore 改为 Owner 归属及明确历史只读校验；同一事务调用既有归档函数并保存幂等回执。归档管理不再依赖媒体盘目录读写或新版执行标记。不插入执行标记，不重排旧任务。
- 新增 `083-legacy-episode-archive.sql` 更新数据库归档包装函数。并行服务更新已于 11:14:55 应用该迁移；本任务检测后未重复执行，逐一核对文件 SHA、实际函数体一致。
- 恢复框的标题区和按钮区原本各有一条边线，且没有中间表单字段，所以出现双线。现在只保留按钮区的一条线。失败在框内显示，保持重试入口，提交期间禁止重复提交和关闭。
- 菜单编号、蓝图、产物改为纵向三行；菜单宽度 260px，编号可换行，仍完整可读。
- 全局错误反馈改为随内容宽度收缩的紧凑提示，保留错误图标、重试、关闭和可访问状态；移除 `Error:` 技术前缀。恢复操作不再重复弹全局错误。
- 工作台“继续处理”的阶段轨迹“输入”改为“脚本”，未改阶段状态映射。
