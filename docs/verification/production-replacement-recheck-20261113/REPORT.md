# 当前制作链与旧流程替换：隔离复核及建议

日期：2026-11-13。结论：保留现有制作内核，分批替换旧业务模型、兼容执行层和当前命名，不建议整仓重写。本轮在当前源码的隔离副本中新建生产单并完成实际导出／交付，同时复核埋点；只新增评估文档与证据，没有修改产品代码、删除对象、应用日常迁移、启用日常采集、重启、提交或推送。

本报告是对[首次完整制作评估](../isolated-production-and-legacy-review-20261113/REPORT.md)与[全面替换方案](../../plans/production-workflow-replacement-20261113.md)的当前状态补充。首次报告中的缺陷属于当时源码状态；当前工作区已含部分修复，不能将旧报告中的「未修复」直接当成当前源码结论，也不能将隔离源码通过当成日常已更新。已有实施规范和 ADR-0066 的整体范围未在本次复核中完成。

## 隔离测试及结果

已实际读取用户引用的「埋店」对话 `01a1d24f-d6ab-7a20-ad89-8436bdc9b6df`。其采集代码已在当前工作区，直接随源码复制到同一专属 PostgreSQL／媒体测试环境，无须合并分支，也没有接入日常身份或供应商秘密。

- 当前源码通过隔离 Worker／backend 构建和产物完整性检查。
- 新建纯静态 v3 生产单：导入脚本、明确匹配图片、字幕设置、真实导出、精确 SHA 确认、实际交付 Worker 完成。无需视频生成字段，仅产生交付任务，费用预留为 0。
- 新建共用人工音频文件的多镜头生产单：不同音轨身份与不同文案，经过原生工程保存／重开、导出及交付下载，逐镜头对账通过。错误身份、错误 SHA、缺失身份的多义来源均被明确拒绝，唯一旧路径可读取。
- 同一隔离环境联验 13 个埋点集成：采集合同 6、工作流 3、重试 1、删除镜头 2、质量命令 1。包括受控口播请求、采用／撤回／再采用、保存重开不重复计数、统计回执失败不重发、交付质量冻结，以及停用／权限／历史覆盖边界。
- 单次运行共 7 个测试文件、17 项通过、0 失败；25 项未选中或夹具跳过，不计为通过。其中 24 项来自 runner 默认附带的其他制作测试，1 项是只用于挂起等待浏览器的质量夹具。[原始结果](vitest.json)、[运行与清理回执](run.json)。
- 视频 API、实际图片／口播模型、外部付费请求均为 0。图片使用本地测试图，口播请求使用受控响应；本轮验证业务与统计链，不能据此判断模型画质、真人语音或供应商实付。

当前交付证据：[测试成片](artifacts/confirmed-video.mp4)、[确认工程](artifacts/confirmed-project.json)、[交付说明](artifacts/metadata.json)、[逐镜头预期来源](artifacts/expected-sources.json)。首次约 9 秒三镜头样例及当时浏览器检查仍保留在原报告，本轮没有重新进行浏览器交互，也没有运行全项目默认套件或重做完整恢复矩阵。

## 前八类的承接与删除条件

原第 1 类旧生成脚本链已完成退役，不重复安排。其余类别都纳入上述方案，具体去向如下。

| 原类别 | 还需做什么 | 何时可删旧入口／名称 |
| --- | --- | --- |
| 分镜批准后的草稿初始化与历史复用 | 将隐式触发动作集中到同事务的旧工程接入操作，保留原音轨和绑定 | 当前模型独立、旧单接入验证完成、依赖旧审批的执行包已明确停止支持后 |
| 视觉／分镜回执校验与审核包登记 | 分离租约／冻结输入／文件验证与旧格式证据登记 | 旧登记入口可退役；校验职责必须由当前回执或历史适配器承接，不能消失 |
| 7 个旧拒绝 SQL 合同 | 明确最低运行版本和启动拒绝语义，迁移调用者 | 旧包不能再启动执行且无当前调用后；不能以「函数只报错」直接判断无用 |
| 空扫描器与旧预检 | 去掉当前对旧自动发现模型的依赖，明确旧版本支持清单 | 退出旧扫描器／迁移预检消费者后，分别删除；不得恢复自动发现或自动重发 |
| 旧 v2 手动命令组 | 迁移仍有用的手动能力、旧计划只读、原工程可接入 | 旧单可通过当前工作区继续必要操作，历史与未知请求保持后 |
| 旧 Studio／共享 Worker | 当前执行改用职责名，旧工程转接集中到适配器 | 当前调用与打包清单全部更新后，删除旧别名或包装；共享能力继续保留 |
| 历史数据、冻结证据、版本化 SQL | 保留原记录，通过版本化恢复器解码；改进当前对象清单 | 这些证据不作为清理对象。可退出当前接口的旧名字，不等于抹去历史资料中的旧名字 |

23 个原运行包的机器清单已存在于 `docs/runtime/runtime-support.json`，但清单本身不是最低版本拦截。若继续要求这些包原样执行，其旧签名就必须有人承接；若希望当前执行链彻底去掉这些名字，须先完成版本门槛和旧工程适配。历史可恢复与旧程序可继续执行要分别验收。

## 埋点能否一起验收

可以，当前环境已完成联验。已测范围内，任务／请求标记、冻结估算、主要候选采用与撤回、显式重试、质量快照、Owner 隔离和幂等保护通过。不过还不能宣称「全流程埋点完整」：

| 缺口 | 大白话说明 | 应如何补齐 | 不改的影响 |
| --- | --- | --- | --- |
| 四步制作耗时 | 数据库阶段不等于正文、准备、剪辑、导出四步；几步都可能停留在同一 stage | 在权威业务命令成功处记录里程碑、版本及开始／完成，不把点击标签当生产进度 | 能看数据库阶段，不能准确按四步拆耗时或返工 |
| 配乐／音效／原声使用 | 当前采用流水主要认图片／视频候选和主口播，上传配乐不一定计入 | 统一素材使用与撤回身份、声音类型、工程版本和可听窗口，保存重开不得重复 | 不能把现有「采用次数」称为全部素材采用率；不代表配乐没进入成片 |
| 同步本机导出与资源 | 导出可在 HTTP／本机同步路径完成，没有 ready／running Worker 任务 | 记录明确的导出活动及耗时，纳入资源活动窗口；继续区分主机资源与单任务资源 | 本机导出工作可能漏采，Worker 排队统计不能替代 |
| 交付完成的业务含义 | 技术通过事件不天然证明文案和来源都正确；原样例曾证明这一点 | 将业务内容一致性校验纳入组包，注明验证合同版本，事件按实际通过范围解释 | 容易把技术交付误读为内容也全部通过 |

统计不记录口播正文／文件路径／秘密，供应商实付无证据仍为未知，GPU 无可信观测仍为未知；关闭期间不采集、重新开启不补造历史，统计故障不能授权重发。真实视频请求与供应商账单不属于本轮验收。

## 推荐执行顺序及最终验收

1. 完成当前已有缺陷修复和 186 候选的最终回归，分清源码、隔离和日常状态。
2. 局部重构当前制作基准／镜头模型，迁移读写；同时完成 v3 当前输入、显示语义和里程碑合同。
3. 验证真实旧单、旧原生／HTML 工程、草稿、音轨及未知请求接入，旧计划改只读；落实最低版本门槛。
4. 删除失去消费者的旧命令、拒绝 RPC、扫描器和预检；将仍需要的历史回执验证留在版本化适配器。
5. 收敛当前 SQL 包装与共享执行器命名，生成当前类型及 clean 基线。历史迁移、ledger 和冻结证据原样保留。

每批要求当前新单、旧单接入、完整／逐项恢复、重复操作、Owner／租约／费用／冻结／精确导出和未知请求矩阵通过；模型迁移须对账稳定镜头 ID、原生人工编辑、原文件路径／SHA、采用关系和原音轨，不得默认重新生成。最终再运行完整默认套件、schema 新建／升级矩阵和实际浏览器检查。日常更新与采集启用按既有独立授权边界处理。

本轮 1,335 个原源码／SQL／脚本文件 SHA、HEAD、暂存保持；日常整库、冻结旧库元数据、app／deployment 哈希前后完全相同，采集关闭、事件 0。[保持检查](unchanged-check.json)。隔离数据库已按身份校验后清理，产物与运行证据保留。
