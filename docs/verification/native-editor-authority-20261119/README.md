## 交付行为

- 删除所有补充工具、导入重定向、媒体/字幕宿主改写桥接、专属组件与样式。分镜台仍可准备初稿；剪辑页使用原生素材池、时间线、字幕和 Agent。
- 首次进入剪辑后，以当前工程决定成片。新增片段无须分镜绑定，可以删除所有原画面、只使用新导入画面；旧声音和字幕准备状态不阻止保存与最终文件确认。
- 原生上传后台按实际字节归档并登记；重复保存复用归档，临时上传丢失可恢复。保留文件归属、SHA、版本冲突和最终文件确认。
- 改脚本不会自动重建已剪辑工程。迁移 213 只分离原生编辑/交付和编辑观察记录的基准限制；初稿生成的旧基准和授权锁保留。原生历史/工具省略宿主标记时，服务端保留已经确立的原生权威。

## 真实模型与完整用户流程

使用独立 PostgreSQL、临时 Owner 和测试生产单。仅复制已有连接引用与已建立的验证资格到测试库；未复制密钥或修改日常连接。模型调用不是 mock，也未创建图片、视频、语音生成请求。

1. 从分镜台进入原生剪辑，宿主没有补充工具和左侧镜头导航。
2. 通过 SDK 原生文件输入上传 PNG，在素材池双击加入时间线；删除后按撤销恢复。
3. 原生字幕界面把正文改为自己的文字，并将时间改为 0.2–1.8 秒。
4. 原生 Agent 使用 `gpt-5.6-luna` 将第一段视频透明度改为 80%；`gpt-5.6-terra` 修改第二段至 90%；`deepseek-flash` 实际将第一段改为 86%。读取 SDK 项目接口确认 `transform.opacity` 分别为 0.86 / 0.9；原片段起点和时长保留。
5. 重复保存、返回准备页、刷新、再次进入。新增自由片段、Agent 修改、字幕正文和起止时间全部保留。
6. 最终版另走一遍真实 `gpt-5.6-luna` 修改、原生导入/字幕、保存重开、导出与交付。得到 **1080×1920、9.045333 秒 MP4**，浏览器解码 readyState=4，实际播放；六项检查通过，Owner 确认实际文件。
7. 选择封面、输入发布文案，真实独立 Worker 完成交付核验。通过页面下载接口完整读取 ZIP，HTTP 200，2,759,030 字节，包含封面、文案、检查、manifest、最终视频和可编辑工程。

最终浏览器验收中的视频 SHA-256：`deb00d514c7567f6851791893f604299a21f38a71c664d6d9030b1e396e519b6`。读取实际文件核验 SHA，并核对保存工程中的 Agent 透明度、无分镜身份的新图片、手动字幕及 200–1800 ms 时序。

布局在 1600×1050 和 900×768 实际打开。900px 专注模式 iframe 底部 759px、保存按钮底部 49.75px、页面 scrollWidth=900；原生属性栏 260px，时间轴可见。未做手机触摸设备验收。

## Web 实现取舍

- `move-dom-element-without-losing-state`：我保留原生 iframe 的同一个节点和父级，仅用 CSS 改专注布局，避免指南指出的 “causing `<iframe>` elements to reload”。
- `validate-origins`：我保留 URL 解析后的精确来源、窗口、通道和工程身份核验，沿用兼容浏览器的严格比对（“candidateUrl.origin !== 'null' && candidateUrl.origin === trustedUrl.origin”），不以来源字符串前缀授予权限。
