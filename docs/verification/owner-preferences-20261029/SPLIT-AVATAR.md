# 独立偏好弹窗与头像

2026-10-29。在原偏好功能上完成本轮调整：个人偏好、通知分别从账户菜单打开，没有 Tab 或重复标题；两页保留各自保存、恢复默认及错误处理。

## 布局与上传

- 弹窗宽度由 880px 收至 560px，显示名称最多 320px，语言和外观保持同一行，桌面下各 248px。
- 将该弹窗接入公共 `scroll-layout.css` 的自动上下边距与背景滚动规则。正式页面 1543×953 下，弹窗 top=241、bottom=712，上下留白均为 241px；通知弹窗 1280×720 下上下留白均为 190.5px。
- 390px 下两个下拉框仍并排，弹窗在视口内居中；内容超过可用高度时沿用公共背景滚动。
- 支持 PNG/JPEG/WebP，原文件不超过 5 MB；本地居中裁切为 256×256 缩略图，最大 64 KB，随 Owner 偏好保存。保存后账户菜单入口同步显示头像，支持移除。没有外部上传服务或新依赖。
- 旧 JSON 偏好缺少 avatar 时读取为 null；无需新增数据库迁移。API 校验允许的图片类型、数据头与大小，输入不合法不覆盖已保存头像。

## 验证

- 60 项相关回归通过（11 个测试文件），覆盖独立页面、字段独立保存、头像移除和上传错误、旧偏好兼容、格式/大小限制、原安全/导航/通知路径。
- 真实 PostgreSQL + HTTP 事务回滚验收通过，新增头像保存、重读、移除及 SVG 拒绝检查；所有合成数据回滚。
- `npm run check`、`npm run backend:build`、`npm run build` 通过；保留已有前端大包告警。
- Impeccable layout 扫描无发现。
- 浏览器使用真实品牌 PNG 完成解码、裁切、保存、账户入口同步、刷新保留与移除后再刷新检查；输出实测为 256×256 WebP、5239 字符。上传试验只在拦截 fetch 的 localhost 隔离页进行，未修改真实账户偏好。
- 浅色、深色、390px 布局已查看。验收页补齐了正式入口的公共滚动样式，避免误以基础样式作为正式弹窗行为。
