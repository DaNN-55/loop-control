## 实现

- `LocalHistory.tsx` / `history.css`：两张摘要表的操作标题与按钮统一左对齐；读取错误保留重试；技术记录与版本快照放在详情顶部。
- `HistoryDeleteAction.tsx`：读取服务端计划后，使用同一弹窗进入单独确认步骤，避免预览与确认摘要重复；显示真实生产单目录、独占历史文件与保留数。必须勾选不可恢复说明并输入完整名称，最终请求绑定服务端版本和路径。步骤变化管理键盘焦点，提交期间不允许重复操作或关闭。
- `episodeLifecycle.ts` / `historyEpisodeDeletion.ts`：复用目录暂存、回滚恢复、提交后清理和旧回执重试。计划绑定数据库业务/历史版本、全部选中目录条目与文件身份；新文件或版本变化拒绝旧计划。
- 运行任务、资产锁、并发写入、跨生产单对象和路径引用均受保护。引用检查覆盖数据库及当前项目文件；历史内容库只用于留存，不当作执行输入。纯栅格图和常见独立音视频不做无意义的文本引用扫描，其数据库引用和实际删除前的 SHA/设备/节点校验继续保留。
- 历史 blob 只按内容库根下的合法 SHA 文件清理，检查间接 SHA 引用链闭包；提交后新引用优先保留，并登记为业务依赖。异常保留文件与待清理回执，不把数据库提交误报为全部清理完成。
- `077-history-episode-deletion.sql` 新增 Owner 删除计划、事务删除和保护机制；`078-history-deletion-child-ownership.sql` 识别同一生产单素材审核等内部子记录，显式属于其他生产单的记录仍按外部依赖处理。已有迁移未改写。
- 旧部署路径是映射别名，不把已不存在的别名作为实体存储扫描。实际当前媒体和确认存在的本生产单副本继续核查；已登记外部盘可用性和目录身份校验不放宽。
