## 本轮发现与现状修正

### 1. 正式输出带编辑辅助网格

实际抽帧可见 contain 留白区带棋盘格。隔离 SDK `src/editor/TimelineComposition.tsx` 的第 28 行定义 `GRID`，第 298 行将它用于非透明根背景。文件、SHA 和交付检查通过，不能证明画面背景正确。

建议由 SDK 渲染边界区分编辑预览辅助背景与正式输出底色／透明策略，覆盖 contain、旋转、分屏空位、图片与视频。不得用裁满全部素材或放宽文件检查掩盖问题。本轮没有修改 SDK。

### 2. 待确认原声的角色与身份未完整承接

另建真实 Owner／PG／文件场景：原镜头为 `audio_mode=source`、有准确音轨 ID、状态 pending；显式接入后，历史来源仍保留原轨、区间和 source 意图，当前口播输入却为 `mode=none`、`audioTrackId=null`。再明确采用视频，原生工程出现 `volume=1` 的关联视频声音节点，而主声音概览仍是 `mode=none`。

这证明目前「原主声音意图」和「视频携带的关联声音」没有统一为当前可编辑语义；没有证明原声文件丢失或成片必然静音。原草稿逐字段保持，未伪造原确认。见 [专项回执](evidence/pending-source-intent.json)。

后续应明确主声音与环境声的角色，携带可核验来源身份及区间作为未确认输入，再由 Owner 明确采用；不把导入变成采用，不继承旧授权，不重置当前人工混音。需要补听感／导出、双槽与 TTS 替换等验收。

### 3. 封面已有正向实现，仍需收尾验收

保存计划接入已提供 `workspace-cover-source/v1` 引用；交付可按准确 material／artifact ID 与 SHA 选择，并在交付时重核验原文件。本轮实际保存计划→当前准备→导出→封面引用交付通过，相关组件选择测试通过。不能再把「历史封面完全无法使用」作为当前事实。

仍需补齐错 Owner／SHA、文件变化、混合输入、迟到文件读取、当前人工封面优先和不同历史来源恢复矩阵。本轮没有验证全部这些边界，也没有把正向通过当作完整封面验收。

组件检查还检出交付封面选择按钮内包裹 `ImagePreview` 的放大按钮，形成嵌套 `<button>`；源代码与 React 警告一致。建议将选择与放大作为并列控件，局部修复。尚未在本轮实际浏览器复现由它造成的操作失败，不将警告夸大为已证实的线上故障。另有 jsdom 未实现 `HTMLMediaElement.pause` 的环境提示，与此结构问题分开记录。

### 4. 旧计划模块仍被当前能力借用

`workspaceImageGeneration.ts`、`workspacePexels.ts`、`workspaceCallConfirmation.ts` 仍从 `scriptProductionStore.ts` 导入 `productionHash`；实际算法来自已有 `configurationCommands.ts` 的 `canonicalFingerprint`。所以旧 Store 看起来属于退役业务，实际却被当前图片、检索和付费确认借用为工具出口。

退役 Store 前应让当前调用直达已有规范哈希工具，保持字节算法和授权哈希不变，再分离旧计划只读适配。无需新增另一套哈希库或重写费用校验。

### 5. 已解决项与尚未覆盖项

当前快照通过保存计划明确选择的实际窄屏／重开页面、普通新单确认页面、原 HTML／JSON 登记阻止计划重建、错误 Owner／过期来源／当前编辑拒绝，以及混合确认与双槽构图。此前「确认脚本直接准备」与「原工程未阻止计划重建」不再作为未修问题重复安排。

旧原生接入做了真实数据库＋文件备份，迁往新数据库及根目录，原位置离线后新应用仍能编辑 SQLite 并导出；主脚本晚于生产单装入的逐项恢复检查也通过。它们不等于保存计划、HTML、混合草稿、封面和不同来源 Owner 的全部恢复矩阵已完成。
