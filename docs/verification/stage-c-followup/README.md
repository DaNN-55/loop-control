## 范围与实现

起点 `5384429`，分支 `codex/local-first-stage-a`，工作目录为优化 worktree。使用既有 `loop-control-stage-b-verified`：console55176/API55461/DB55462。仅增加前向迁移 `20261024004749_episode_catalog_paging.sql`，未改写已提交的历史迁移。控制台为只读观察模式，未启动 Worker、调度器或 n8n，也未调用在线 Provider/桌面提醒运输。

- 页面骨架不读取全量 episodes、tasks、artifacts。统一 `read_episode_catalog` 在服务端执行账号、系列、归档/进行中和审核筛选；每页20条，按 `updated_at DESC, id ASC` 稳定排序，越界页收敛到有效尾页。
- 账号数量、审核徽标、阶段分布和 Worker 状态由服务端汇总。运营明细、待审包、阻塞项分别分页，保留全局数量、原有字段和修复入口；Owner 条件叠加现有 RLS，匿名无函数执行权。
- 请求绑定捕获的会话令牌和筛选/请求代次。快速切回相同筛选会重新读取，旧结果不能回填；退出/换 Owner 清理列表、详情和修复上下文。
- 详情继续使用原聚合/增量服务。仅业务状态、产物或审核相关变化刷新当前目录页；不因无变化的 task-run 数组或租约 `claimed_at` 心跳反复刷新目录。隐藏时暂停，恢复可见立即读取。所选详情与列表页独立保存，并按需保留 OpenChatCut/交付依赖；不把未加载的 tasks 当作“阻塞已解除”。
