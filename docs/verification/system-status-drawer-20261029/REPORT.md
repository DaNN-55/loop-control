# 系统状态抽屉正式接入验收

2026-10-29。Owner 已确认原型布局。沿用侧栏“系统状态”入口，正式显示本机 Worker、任务队列、资源状态和日常维护；不新增页面或工作台卡片。

## 实现与数据来源

- Worker：读取应用内真实调度器的 4 秒心跳、最近扫描、活动子进程数和本机并发配置。心跳超过 15 秒或服务停止为离线，扫描超过 30 秒未更新或出现错误为需处理。没有配置或观测时显示待确认，不用“最近任务成功”推断在线；原始进程错误不进入响应。
- 队列：沿用认证的 `/api/local/system-status`，在 Owner/RLS 只读事务中读取持久任务。排除归档、历史、失效及已恢复的旧任务；先按操作确定最新任务，再筛选运行、排队、阻塞和失败，防止旧失败覆盖已完成或被替代的任务。总数与当前页来自同一快照，每页最多 20 项，界面默认两项，按需展开及分页。“查看”打开已有生产单，保留原有未保存草稿保护。
- 资源：CPU 为两次 OS CPU 时间累计值之差；首次无有效差值时不虚构百分比。内存明确显示 OS 空闲值与总量，不能将该数值等同于 macOS 内存压力。磁盘读取 `statfs` 的可用空间；素材盘复用已有真实挂载点、目录归属及读写权限校验，并按部署的最低可用空间要求判断不足。
- 维护：保留现有持久运维尝试与调度证据。关闭的完整备份、未启用的部分快照不作为故障；真实失败继续显示并可展开查看时间和原因。
- 刷新：页面初次读取一次；抽屉打开且页面可见时每 5 秒刷新，关闭或隐藏后停止定时读取。资源快照缓存 2.5 秒，无额外常驻采样进程；请求防重入、取消及代际检查避免旧响应覆盖当前状态。读取失败不沿用正常指标，各子区域可独立显示未读取。
- 界面：520px 右侧抽屉，窄窗占满可用宽度。头尾固定、正文独立滚动，复用语义主题与焦点管理，支持 Esc、遮罩关闭和原入口重开。演示参数、场景选择和全部示例任务均已移除。

## 验证

- 48 项相关检查通过：状态组件与生命周期、状态判定、调度器、运行装配、工作台及账户导航保护、既有共享状态面板、HTTP 来源边界，以及真实 PostgreSQL/HTTP/OS 集成验收。
- 真实集成测试使用单个未提交事务：包含跨 Owner、非 Owner 成员、历史/归档/失效任务、恢复、完成/替代旧失败和 23 项当前任务的分页。结束后回滚，原账号、生产单、任务指纹一致。验证真实 OS 内存、磁盘、有效素材挂载、未挂载目录和数据库读取失败的独立降级；没有生成、领取或执行任务。
- TypeScript、生产前端构建、Worker/后端构建及 `runtime:prepare` 完整性检查通过。保留已有大 chunk 提示。构建初次曾遇到并行生产页变更的类型错误，后续当前来源已修复并重新构建通过。
- 测试夹具初次失败分别来自会话凭据父记录、部署媒体路径绑定和事务内相同创建时间；按真实约束修正后集成通过。装配测试显式 mock 新增观测工厂端口，避免依赖并行前端构建期间临时清空的 dist 文件。
- 确认无真实 ready/running 任务后，执行本地服务标准停止/启动，实际页面确认：Worker 在线空闲、执行位 0/1、队列为空；CPU、16 GB 总内存、本机磁盘与素材盘空间均来自当前机器，心跳及读取时间持续更新。
- 实际桌面与 390px 窄窗核验展开、正文滚动和固定页尾。未通过真实断盘、停止 Worker 或制造业务失败来测试；相关故障采用隔离读边界和状态测试验证。
