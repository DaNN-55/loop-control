## 实际变化

- 保留现有页面外壳与四步导航，脚本区使用原文、可空的目标时长、继续制作与优化拍法；移除右侧基准栏、重复字数、必填修订原因和双重确认。历史、备注、帮助及已确认拍法按需查看。
- 普通文本或非模板 Markdown 作为完整片段继续，不按空行拆镜，不自动调用模型。有效 v3 保留明确镜头与设置。原文、可执行制作输入及已审批拍法分开保存，刷新不把内部模板替换成用户原文。
- 优化、提出修改与大胆改编使用真实连接及新合同。默认保留内容、口播/字幕顺序、有效总时长和非拍法设置；改编单独选并列出内容变化。首次有多个可用模型且无 Owner 选择时先展示选择，不提前派发；之后沿用已选偏好。
- 一次采用只提交原文、基准、时长和请求身份，后端读取绑定的可信回执。源输入变化使旧方案失效，迟到响应不覆盖新稿；未知请求只核对，不自动重发。
- 方案中逐镜口播、字幕正文与实际开关一致，包括字幕跟随口播和显式字幕-only。保存/启动分步恢复、归档/完成只读、已有工程与素材保护继续有效。

## 关键问题与修复证据

- 保留真实父组件保存刷新回归后，发现启动失败后再次改稿且保存失败会退回初始基准；已将最近保存的来源身份与浏览器草稿基准分开，重试保持正确版本。
- 旧 native-edit guard 会跳过重规划新工程的字幕装配；加入真实图片采用前序才复现。新工程显式标为 fresh，原工程读取/恢复仍保留人工编辑保护。
- 口播/字幕关闭镜头、空字幕跟随口播和空启用口播曾导致审批展示与实际内容不同；共享逐镜开关/字幕正文计算，并拒绝每个启用镜头的空正文后闭环。
- 日常 Vite 直接监听源码。发现后将全部任务文件逐一 SHA 校验复制到独立 worktree，并恢复日常根干净 `main`；HTTP 核验日常仍提供旧组件。后续测试在隔离 worktree 完成，正式切换前不会再修改日常源码。
- 独立 worktree 缺少 OpenChatCut 读取工具依赖时，通过显式只读工具路径修正测试环境；未修改日常运行配置。一次浏览器等待错误使用 aria 名称当可见文本超时，实际 DOM、单镜头状态和模型请求数 0 已独立核实。

`209-script-studio.sql` 已正式提交事务，135 张原有表在启动前摘要全部一致，新确认表没有回填。启动后 134 张摘要一致；唯一变化是 `local_identity.media_root_binding.updated_at`，已与恢复备份逐列比对确认其他列一致。既有脚本、分镜、任务、素材、费用和交付记录未变，新确认记录仍为 0。运行包为 `3d40c4c3cc549a50fd3ae8a64427e1cf7abdbd109971383371740bbbde6b39cb`，App 在 5174 正常运行。

## 限制

新建/修订与模型输入统一最多 20000 Unicode 字符，已有更大脚本可查看。逻辑镜头 0.1–3600 秒与视频供应商单次生成时长分别校验。没有新增依赖、轮询或常驻生成任务；模型请求上下文限 128 KB、响应限 512 KB、镜头数限 100。本轮没有真实供应商推理、付费素材生成、最终成片导出、Safari/Firefox 或完整 Docker clean-schema E2E 验证。

## Modern Web Guidance

- `forms`：保留可见标签，按提交校验并聚焦错误字段（“DO move focus to the first invalid field”）；辅助按钮不提交，原文与模型结果保持安全文本渲染。
- `css-layout`：用容器查询和可收缩网格适配左右/上下布局，实测排除溢出（“Do NOT use overflow: hidden to mask layout issues”）；提高时长控件选择器精度，避免旧抽屉全宽规则破坏已确认的紧凑布局。
