# 批准范围与验收接口

来源：本会话「剩余 36 个状态机族专项复查」建议及 Owner 对第 3、4、5 项的实施批准。按顺序完成，每项验证通过后才开始下一项；保留业务规则与恢复限制，不提交推送。

1. M09：仅传 `sourceOutSeconds` 时，校验默认起点为 0，准备与采用必须应用该区间。保留仅起点、双端点、省略、非法范围、时长选择、Owner、工程版本与文件指纹校验。通过隔离 Owner HTTP 的准备结果及最终工程验证，最小修改区间写入条件。
2. M02／M04／M07／M08：真实隔离 PostgreSQL 验证旧 attempt 拒绝、未知提交不重发、原任务／原远端 ID 恢复、publication hold 与 COMMIT 两种结果核对，以及授权消费事务回滚。使用受控 Provider，保留图片未知提交的既有显式确认、关联原任务和单次例外重试。先验证，不重写恢复协议。
3. M36：在目标目录 mkdir 成功、创建目录进度尚未持久化的窗口终止迁移进程。重启必须安全停止，保留原位置和未知目录／内容；验证现有提示及可行的人工接续步骤。不得自动认领、删除或覆盖未知目录，不增加恢复权限。

验证使用已有公开 Owner HTTP／Worker RPC、真实临时数据库、真实文件与独立进程。只在外部 Provider、文件系统中断和数据库断连边界注入故障，不 mock 新增私有逻辑。没有界面改动，不需要为本批新增 UI 结构。

测试集运行时使用无网络、无持久卷、无宿主端口的独立 PostgreSQL 容器，从冻结本机基础 schema 和当前全部前向迁移构建。日常数据库存在的历史迁移 139 SHA 差异保持不动，不用伪造账本绕过校验。编译后 Worker 在独立运行副本中准备，不改变日常固定运行版本。
