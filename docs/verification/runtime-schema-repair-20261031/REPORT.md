# 本机服务错误修复

日期：2026-10-31。目标页面：生产单 `3bf59fde-cf0b-47e1-990e-d7034cfbcfb3`，操作电脑-v2。

## 原因

用户页面显示“本机服务暂不可用，请检查本机状态”。当前服务 PID 71478 已于 14:19 启动新代码，运行包摘要有效，数据库可读；日常数据库却缺少 100–109 共 10 份迁移。`episode_asset_root(uuid)`、账号目录、生产单位置、规划选择和 Pexels 关系均不存在。工作区 GET 依赖这些新结构，因此进入通用 503 错误分支。

私有日志中的旧 Worker 过期提示不作为当前故障结论：本轮 `assertPreparedRuntime` 实际通过。未登录 curl 的 401 也不作为这次页面错误的依据。

## 修复

1. 核对已执行迁移 SHA，零改动；当前 ready / running 任务为空，无活动原生编辑。
2. 记录 40 张既有业务表的原字段与记录指纹，以及 1719 个媒体 / 工程文件的 SHA-256，共 3,932,457,120 字节。
3. 通过现有 `npm run runtime:migrate` 补齐 100–109。每份迁移按既有事务与账本执行，旧迁移文件未改写。Owner 已关闭自动备份，本次遵循该设置，没有额外创建整库备份。
4. 重跑结构探针和保留性比较；登录后在后台复核原页面及系统状态，关闭本次创建的验证标签，保留用户原标签。

未重建运行包或重启服务，PID 71478 保持。没有搬动账号目录、修改历史脚本 / 任务输入、调用 Provider、创建生成任务或替 Owner 选择账号目录。新增位置 / 规划映射属于前向迁移初始化，不改写原历史内容。
