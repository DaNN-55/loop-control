# 脚本确认常驻聊天验收

2026-11-18。按已确认的线框落实正文／分镜／聊天三栏，仅调整脚本确认及支持它的拍法接口；其他产品页面不变。

## 结果

- 上传、时长、历史与帮助收进顶部工具栏，采用／继续统一放在底部。右侧为可收起的拍法助手，模型选择与发送位于输入框内。
- “仅讨论”产生结构化文字回复，不替换已有分镜；“调整拍法”根据当前方案和历史交流生成待采用的新版本。手动镜头修订、双示例、草稿、导入、保存／启动恢复和直接制作保留。
- 大胆改编通过“更多选项”显式选择，发送前再次确认。过去允许改编不代表当前轮获得改编权限。
- 对话复用持久请求回执，通过父请求身份恢复完整上下文，无新增数据库迁移。刷新只读取记录，不调用模型；未发送文字沿用 Owner／生产单／脚本版本隔离的本机草稿。
- 历史用户要求同时进入模型输入和不可变的本地校验依据，避免上一轮明确的口播要求在下一轮被误拒。每轮实际输入另存为 `turnInstruction`，页面不会把累计要求重复展示为本轮输入。
- 未完成／结果未知只核对，不重新派发；讨论后手动编辑仍保留完整回执链。采用仍只接受同 Owner、生产单、原文、时长和脚本基准的有效计划回执。
- 起点的历史／帮助移位修改已整合至顶部，入口与 Escape 关闭、修订备注等行为保留。搜索页只更新测试夹具，将新对话查询 POST 正确视作只读请求，未修改搜索页面代码。

## 上下文边界

对话绑定 Owner、生产单、脚本版本、原文和目标时长。修改这些输入时使用对应上下文，防止旧方案混入新脚本；采用生成新脚本版本后开启新上下文，旧回执保留。当前没有跨版本合并聊天或自动总结长期对话。

发送快照仍限制为 128 KiB，父链最多读取 256 个回执；超过边界明确拒绝，不静默截掉早期用户要求。仅讨论同样使用所选模型并产生正常调用费用，但不生成素材。真实 Provider 本轮未调用，供应商实测仍是盲区。

## 验证

- 先运行新增上下文与 Provider 失败测试，再实现并通过；聊天恢复与交互测试同样先失败后实现。
- 脚本回归 **88 项**通过；后续跨轮校验覆盖的上下文／Provider **20 项**通过；搜索草稿导航 **16 项**通过。以上与全量有重叠，不相加。
- 独立原生 PostgreSQL、SDK 副本和本地 Provider stub 的 **20 项真实 HTTP／数据库集成**通过；另一个浏览器驻留夹具按需运行，正常集成中跳过。
- 最终全量 **332 文件／2,422 项**通过，类型、前端构建、后端构建及 Worker／运行包完整性检查通过。保留现有主 bundle 大于 500 kB 的构建提示，没有新增依赖。
- 完整应用浏览器实际完成：生成 → 仅讨论 → 刷新恢复 → 后续调整 → 手改镜头 → 改编确认后取消 → 采用进入分镜台。分镜台显示实际手改画面，未调用真实模型、图片、视频或语音服务。
- 1481／900／390px 无横向溢出；桌面正文、分镜和聊天均高 653px，底部操作在同一外卡底部。聊天收起后仅保留 42px 栏，模式和发送按钮保持同一行。窄屏上下重排，保留页面滚动；截图仅记录当时滚动位置。
- 日常应用单独重启，PostgreSQL 保持运行。正式页重新打开后读取正常，DeepSeek 选择及原有本机草稿恢复；没有点击正式生产单的优化、保存、采用或制作。
- 重启前后及正式页只读回看后，七张相关业务表的数量和内容指纹完全一致，运行中任务均为 0。见 [比较](daily-comparison.json)。不将运行时日志／会话／采样数据算作业务表不变证据。
- 临时浏览器、HTTP 服务、私有 PostgreSQL 集群及 SDK 副本已关闭和移除；正式 5174 服务保留。Safari／Firefox、真实触屏设备与真实模型尚未验证。

## 验证中修正

- 搜索测试将所有 POST 都当作写入，误把新对话只读查询记为写操作。夹具现在仅允许确切的 `conversation` 查询，保存、启动及模型请求仍受原禁止写入断言保护。
- 历史用户口播要求已传给模型，但原本只用当前输入做本地验证，导致跨轮要求可能误拒。现在模型生成与采用校验使用同一固定用户要求上下文，并单独测试历史改编许可不能扩大当前权限。
- 本机应用重启时旧标签保留了此前请求错误，草稿保护阻止重新加载；未放弃用户草稿，另开正式页只读复核，工作区状态正常且草稿完整恢复。
