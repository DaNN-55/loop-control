## 本次发现并修复的问题：SQLite 与 JSON 权威分叉

OpenChatCut 0.2.17 的 `server/storage/sqlite-store.ts` 已明确将 `project-store-v1.sqlite3` 作为唯一持久化后端，旧 JSON 仅保留为备份。Loop Control 的 `readStoredProject` / `writeStoredProject` 原先仍只处理旧 JSON，存在以下结果：

1. 编辑器关闭后，读取「最近保存的旧工程」可能拿到旧 JSON，遗漏新版 SQLite 中的修改。
2. Loop Control 采用新工作版本并重开时，只写 JSON 不会触发 SDK 的第二次导入；宿主快照与原生界面可能显示不同版本。
3. 直接修改 JSON 的旧集成测试未经过新版真实存储，因此既会漏报，也会产生无效失败。

复现：在真实 SDK 中保存原生改动，关闭编辑器，再读取旧工程。修复前有 `expected 37, received 0`；证据见 `sqlite-before.log`，完整最终回归见 `integration.log`。

修复：优先读取 SQLite，读取失败不静默降级到过时 JSON；不存在 SQLite 才保留旧格式兼容。替换工作版本时，先确认旧子进程真正关闭，再以 SQLite 事务更新本期工程；关闭超时则阻止替换。数据库文件及 WAL / SHM 沿用普通文件、符号链接和硬链接限制。测试经真实 SDK 注册、修订检查和工程写入接口修改工程，覆盖离线读取、保存重开以及采用新版本后原生接口的实际内容。

这是第三方编辑器存储边界的兼容修复，不是主项目 PostgreSQL 向 SQLite 的迁移。SQLite 的后续替换评估另记研究文档，不把建议视为已批准的架构决定。
