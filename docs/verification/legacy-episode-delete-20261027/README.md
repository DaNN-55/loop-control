# 测试账号旧生产单删除无反馈修复

2026-10-27。本轮只实现并验证功能，不对现有账号、生产单、当前运行目录、外部盘旧副本或原始素材执行删除。所有真正删除仅在临时数据库与临时媒体目录执行。

## 原因与复现

测试账号中的「测试」（da8677ae-3c4d-4815-92d5-e1fef8bc7164）已归档，无运行任务或有效资产锁，也不属于只读历史；但没有 `local_identity.input_episodes` 管理标记。原删除预览依赖生产执行的管理标记，所以返回 404「本地生产单不可见」。客户端在全局错误处理以外获取计划，确认框也不捕获提交异常，因而点击后只有 Promise rejection，没有可见反馈。

- `npx vitest run src/local-app/LocalCatalogApp.workspace.test.tsx -t 'shows a deletion-plan failure'` 修复前失败：找不到确认框内错误提示，出现未处理 rejection。原始输出 ui-before.log。
- 独立数据库以 managed=true/false 两种形态运行相同 Owner HTTP 生命周期；修复前新单通过、旧单计划返回 404。原始输出 legacy-before.log。
- 真实浏览器在旧后端上仅打开检查即可得到同一错误，见 before-plan-error.png。没有提交删除。

## 修改

- 前向迁移 069：增加专用 Owner 清理归属锁，支持缺少生产管理标记的旧生产单，仍排除只读历史；删除守卫继续要求归档并拒绝运行任务、有效资产锁和并发任务锁。不补生产管理标记，不启用旧单生产执行。原生产功能的管理要求不变。
- 打开确认框立即获取服务端删除计划；显示部署映射后的实际路径，而非蓝图里的历史目录文字。确认提交使用同一份计划的路径、版本和确认文本。
- 计划失败在框内显示并提供重新检查；提交异常在框内显示，不产生未处理 rejection；检查和提交期间禁用重复操作。确认文案明确给出标题。
- 数据库记录删除但文件清理尚未完成时，页面明确提示到所有者设置 → 系统维护重试文件清理。

## 清理边界

成功永久删除清理该生产单的关联业务记录（任务、审核、产物索引等），并递归移除当前部署映射后的 `episodes/<id>` 目录及其中所有文件。先暂存目录，数据库事务失败则恢复；数据库提交后再清理，未完成时保留重试记录。

本例实际清理目标为：

`/Users/dan/Programs/loop-control/.loop-control/local/volume/media/test-account/episodes/da8677ae-3c4d-4815-92d5-e1fef8bc7164`

外部盘 `/Volumes/Ebuget 1T/Media/accounts/test-account/episodes/<id>` 的旧副本也存在，但不属于本次映射目标，不会自动删除。账号根目录、其他生产单、原始素材和历史备份保留；不扫描其他位置的副本。数据库命令回执和不可变历史资料不等同于被清理的业务记录。
