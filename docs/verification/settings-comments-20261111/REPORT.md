## 流程审阅

[完整交互清单](../../reviews/workflow-rules-20261111/index.html)包含 48 类场景。64 个现代工作区命令与 50 个通用/兼容入口已按源码核对；所有证据路径存在。每项只有「当前实现」陈述现状，通过、阻塞、停用后和恢复栏目是待确认的建议。清单包括自动退避、尝试耗尽、旧输入失效，以及兼容自动续作和受控审核修订。

当前已确认的脱节：原生工程的第二镜头已保存 `loopControlNarrationEnabled=false`，后台仍保留 TTS 任务关联；目录汇总没有检查该开关。待准备数也只判断 mode/采用状态。导出则主要核对实际已用内容与必要字幕，因此列表任务汇总和真正的交付门槛并不一致。不能再仅用「任务历史需要保留」解释关闭后继续整期阻塞。

建议主线是「不再使用的内容不阻塞当前作品」，同时保留可能费用/未知请求的独立核对提醒。关闭提示、停用内容、取消任务需要分开；不把退出窗口当作取消外部请求。

## 回执调查

[底层报告](receipt-logs/REPORT.md)区分两类问题：通用本机 503 是已收到的错误响应，不能据此判断事务是否提交；口播 `provider_result_unknown` 也不能证明本次已经外发。

实际口播执行函数的隔离故障注入证明：预留失败和缺少 route 在 0 次外发时也得到 unknown；网络断开在 1 次外发时得到同名异常；已收到响应但登记失败又得到普通生成错误。咖啡任务约 6ms 即被阻塞，没有对应 submission/费用预留记录，不能唯一还原旧事件的触发分支，不能断言供应商已扣费。

本轮只增强可观测性，未提前实施新的请求分类或重试语义。网络/进程中断、外部执行与本地登记之间的间隙仍可能造成真正未知；后续应按发送阶段回执、原请求恢复和幂等证据处理。
