## 实际行为

- 保存停留剪辑台；返回分镜台和前往交付分别保存后离开，重新进入同一工程并恢复选择。素材不齐可进入，真实缺失文件仍阻止编辑。
- 补充工具默认收起，提供配乐/音效准备、画面候选和字幕校时。原生音量、淡入淡出、闪避、字幕整轨样式和裁切拆分继续直接使用。分镜台声音面板只准备镜头音效。
- 导入、检索、生成和试听只准备候选，明确采用才进入原生工程。采用通过当前原生连接修改，保存后登记，指纹或归属变化拒绝覆盖。
- 默认只替换选中片段；明确选择整条分镜才将其全部画面实例合成一个新素材。保留口播、字幕、独立声音和其他分镜位置，不自动拉伸、循环或移动后续内容。整条替换前写入原生“替换整条分镜前”历史版本。
- 绑定的视频原声跟随新来源；无原声会清晰提示并移除旧绑定声音，口播/无主声/解除关联的声音保留。新原声通过 212 迁移中的受控登记函数取得真实来源身份，不伪造 Worker 任务。
- 新口播按跟随/独立正文模式更新并重校时；后台只应用同一输入且未被人工修改的结果，保留原生样式和位置。

## 零基础用户实际路径

1. 从空白生产单导入两镜 v3 脚本，5 秒与 3 秒；先进入仍有占位的剪辑台，保存返回。
2. 在分镜台导入并明确采用两张图片，第一镜上传中文口播，第二镜关闭主声音和字幕。真实离线 WhisperX 自动校时成功，保留两句 20–785ms、905–3379ms；不是替换结果的 mock。
3. 再进入剪辑台，在补充工具上传配乐；核对上传后声音轨不变，明确采用后才出现 8 秒整期配乐。进行中切工具、返回、保存和时间线操作禁用，完成后恢复。
4. 采用带原声视频，原生在 2 秒切开第一镜，保存。上传另一视频，默认仅替换第一段：保存文件中第一段 SHA 改变，第二段、第二镜、口播、配乐及字幕保持。
5. 明确选择整条分镜，采用无声视频；确认前显示两个片段合并、5 秒不变和不播放旧原声。保存后只有一个 5 秒画面，口播/字幕/配乐保留，旧绑定原声消失。
6. 打开原生历史，看到“替换整条分镜前”，点击恢复并保存；画面/声音实例与替换前逐项一致。
7. 保存返回分镜台，将第二镜换成另一张图，再进入原工程；仍有第一镜两个片段，并定位到刚修改的第二镜。
8. 使用原生字幕整轨“故事黄高亮”和配乐闪避 -12 dB，保存。保存工程确认整轨模板已更新，局部样式按原生规则清除，文字、句子时间及布局保留。
9. 保存前往交付，实际导出、浏览器播放到结束并解码检查代表帧，确认成片与字幕。选封面、填写标题/简介/标签，生成并验证交付包，实际下载视频、ZIP 和可编辑 JSON。

输出为 H.264 1080×1920、视频 8.000 秒、AAC 音频；封装总时长 8.042667 秒，395680 字节。下载视频 SHA-256：`2b4f71381d851386bff3debc22605d87e8d9a7d1e4bcd9fa044fe1c5a5bed6fc`，与导出登记及 ZIP 内文件一致。ZIP CRC 检查通过，内含封面、元数据、检查、清单、视频和可编辑工程；单独可编辑下载为有效 v3 JSON。精简回执见 [acceptance.json](acceptance.json)。

## 验收发现并修复

- 声音采用期间可切走工具、旧上传成功文案误导：贯通完整操作忙碌状态和明确进度，阻止操作途中离开。
- 原生来源 URL 与登记来源不同，导致已采用状态识别失败：按素材身份/SHA 回查当前候选。
- 编辑器错误继承分镜台素材面板上下文，隐藏直接文件入口：编辑器工具独立渲染，回归验证实际文件选择器。
- 原生拆分后第二次保存误报版本变化：区分原生文件指纹与归一化业务工程指纹，继续分别校验原生旧回执及业务版本，不放宽并发保护。
- 独立检查发现非选中片段锁轨和历史配乐恢复边界：补齐整个受影响范围的锁定检查、精确已采用来源恢复验证。
