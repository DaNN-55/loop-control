## 改动

`workspaceVisualRequest.ts` 集中图片与视频的制作选择、创作上下文、素材身份、最终 prompt、实际主声窗口和供应商时长解释。调用确认、图片入队、候选视频与首次填充视频分别调用，仍在各阶段读取当前状态；不缓存准备确认的结果。

确认阶段沿用原参数接受语义并测量参考图尺寸。入队阶段执行原有严格参数、模型时长和最终 prompt 校验，保留运行就绪检查、事务授权、SQL 入队及未知提交保护。首次口播装配仍在 `workspaceImages.ts`，解释不修改工程。费用算法、确认摘要、contextHash 输入结构与任务快照格式保持兼容。

新增真实 Owner HTTP／PostgreSQL 回归：确认消费后候选写入权限失败，验证确认消费、任务、候选和命令回执一起回滚；恢复权限后同一确认仍可正常使用。

## 既有隔离用例失败

本轮没有将这些失败记为通过，也没有修改无关旧用例：

- `workspaceVideoSelection.integration.test.ts` 的未知提交用例：故障注入依赖旧 `return Response.json({id:'controlled-t05-video'});` 字符串，当前夹具响应已包含多个供应商字段，替换未生效。改前源码同样无法得到预期的未知提交拒绝。现行 `workspaceGenerationState.integration.test.ts` 的真实受控视频查询恢复、防止第二次 POST 等 5 项检查通过。
