# 原稿直接识别为分镜的验收

2026-11-17。用户纠正：模型直接识别镜头／字幕，确认结果后即可确认脚本并进入分镜台；连续场景允许一镜到底，不强行按字数或段落拆分。本记录取代此前修改建议流程的当前行为说明，决策见 [ADR-0071](../../adr/0071-confirmed-script-recognition.md)。

## 行为与边界

- 本地成功路径保留；失败时通过右侧已验证的 GPT／DeepSeek 连接识别。连续内容优先单镜头，明确切镜保留顺序。原文不被模型改写，已有设置提取后由本地制作合同校验。
- 模型结构进入“镜头与字幕预览”，先确认识别，再确认脚本；编辑原文使旧确认失效。没有“格式建议”或“采用改稿”。
- 后台只接收原文、基准及请求 ID，从同 Owner／同单／同原稿的完成回执读取结构，拒绝客户端伪造 JSON；确定性转换为内部制作输入，复用分镜台、口播、字幕和工程流程。原文保留在回执，并与主脚本版本的确认关系绑定。
- 新合同和旧格式建议回执分开；旧写入口返回 410。网络未知和回执写入失败仍不自动重发，不自动换供应商。

## 日常真实 OpenAI 验证

沿用用户明确批准的 OpenAI 测试授权，实际调用 `gpt-5.6-luna` 1 次。合成原稿含错误章节名与两段连续口播；模型返回 1 个镜头，字幕完整包含两段文本，直接进入预览。点击“确认识别结果”后仍保留错误格式的原文，未保存脚本或启动生产。

完成回执：输入 597／输出 125 tokens，不推算金额。测试前后生产单、脚本版本、任务、任务运行摘要一致，日常确认保存记录为 0。当前用户换入的 214 字口播草稿已先备份、测试后逐字恢复；没有把该业务草稿发往模型。日常后端运行包与 Schema 校验通过。

私有证据位于 `.scratch/script-format-fallback-20261117/`：`recognition-live-result.json`、`recognition-live-openai.jpg`、`recognition-live-draft-backup.json`、`recognition-browser.log`、`recognition-ui.json.result.json`、`recognition-storyboard.png`、`recognition-preview-narrow.png`、`recognition-mutation.log`、`recognition-rehearsal.json`、`recognition-daily-applied.json`、测试及构建日志。恢复备份为 `recognition-daily-before.dump`（0600），不进入 Git。

## 限制

DeepSeek 新合同已通过受控 HTTP／真实 PostgreSQL 测试，未做真实 DeepSeek 推理。OpenAI 实测是短合成文本，不代表任意复杂原稿都能可靠识别；歧义仍须在预览核对，不能可靠识别时要求补充信息。没有做 Safari／Firefox 或完整 Docker clean-schema E2E；当前基线、非空恢复与迁移、真实文件、日常 API 和浏览器路径已覆盖。日常当前生产单未执行最终确认保存，该部分在隔离真实环境验证。
