# 回收站迁移独立审查

审查范围仅限本轮回收站迁移：`160-episode-recycle-bin.sql`、回收站服务与界面，以及其直接相连的生产单生命周期、目录迁移和目录查询边界。

## Critical issues

无未解决项。

审查中发现的两项阻断问题均已修复并复核：回收站记录的应用角色行锁权限，以及旧 `plan_input_tasks` 会为已回收的旧式生产单继续创建任务。现实现复用已有 Episode 清理锁读取成员记录，并在最终 planner 入口按未归档、非回收状态筛选且持有 Episode 行锁。

## Important improvements

无未解决项。

- 回收仅写成员记录和临时归档状态，保留原 ID、关系、脚本、工程、任务与文件；恢复还原原归档状态。
- 公共输入锁、任务资格、目录/工作区读取、目录查询和旧 planner 都排除了回收项；入站拒绝在途、未知回执、发布 hold、资产锁、删除 intent 与目录迁移。
- 自动清理复用精确 `stage → commit → cleanup`；已提交但待清理的回执继续占用容量，旧文件清理恢复入口保留。
- 容量按 `dev:inode` 跨项目去重；共享、未知、离线或已变化内容保守计入且不自动清理；GET 不递归哈希文件。

## Optional notes

- 先前把 `input_task_allowed` 的权限失败视为实现问题，现撤回该判断：隔离库基线 ACL 仅给函数所有者执行，Owner 直调不是既有合同。不要为测试扩大该权限，应通过 worker 入口验证。
