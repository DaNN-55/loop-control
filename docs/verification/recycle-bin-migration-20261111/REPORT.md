## 容量与自动清理

默认 5 GB，支持显式保存 0.1–1000 GB。容量取真实普通文件字节，按设备／inode 跨回收条目去重；包括受保护文件的保守占用，不等于可释放容量。硬链接、共享引用、手放／未知文件不会自动清理；不跟随符号链接。入站保存相对路径、SHA256、字节与物理身份；恢复／清理重新核验，GET 只查 DB、依赖和登记目录身份，不重新哈希全部视频或递归扫描磁盘。

只有新入站或明确保存上限触发 FIFO；迁移、启动、GET 不触发。刚入站项目和单项超限项目保留。超出上限时按最早的安全项目清理，离线、变化和共享项目跳过并显示原因；没有安全项时保留超限状态。文件提交后尚待清理的回执仍计为占用，完成原清理后才释放计数。

## 曾发现并修正

1. 初版把回收表当作普通可 UPDATE 表加 `FOR UPDATE`，但应用角色只有 SELECT，导致恢复／计划返回 404、FIFO不清理。已改用既有窄 definer 锁 Episode，再读成员；不扩大应用 UPDATE 权限。实际恢复和真实 FIFO 已红绿复验。
2. 仅禁止任务资格不足以禁止旧 planner 先创建 ready 任务。160 同时限制 planner 并锁 Episode 行，避免回收与规划竞态。
3. 永久删除成功、外层回收站回执尚未写入时，用稳定派生的原永久删除 key 续接，避免成员已消失后重试 404。
4. 普通入站已保存、目录刷新失败时沿用已保存／刷新失败提示，不误报写失败；未保存容量不能被其他操作刷新覆盖。

## 部署与限制

执行子 Agent 没有重载日常服务、修改日常 DB、删除／恢复用户生产单或调用付费生成。主 Agent 部署前应确认无活动编辑器，正常应用新160并使用最终前后台构建；上线后的只读回收站应为空、默认5 GB，旧清理任务继续可见。回滚前端可回到 Git 检查点；已应用的数据库迁移和已入站真实成员不能用直接删除表或改账本回滚，应先按受控恢复与状态证据处理。

入站／恢复需要流式读核验相关文件，文件多或体积大时会消耗本机磁盘 I/O。容量不包含整块磁盘剩余空间，也不承诺共享／未知文件可自动释放。若清理停在提交后阶段，保守保留占用，使用旧持久清理任务继续处理。
