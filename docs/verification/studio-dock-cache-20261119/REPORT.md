# 剪辑右侧工具与程序缓存验收（2026-11-19）

## 本轮结果

- A 布局已进入正式组件：补充工具默认关闭，打开后停靠右侧，独立滚动；900px 以下覆盖显示。切换、关闭与 Esc 返回按钮焦点均不重建原生 iframe。
- 删除 `WorkspaceShotRail`、折叠状态及旧左栏/字幕栏布局残留。下方原生时间线承担片段选择、拆分、拖动、删除、复制和撤销；返回分镜台保留当前镜头。
- 整条业务分镜仍由现有分镜台新增、删除或调整。原生时间线删的是选中片段，不会替用户推断是否连口播、字幕一起删除；新增原生片段也不自动生成一条正式业务分镜。
- 缓存导出程序包，工作台启动后延迟 2 秒后台准备。缓存基于 SDK 源码/资源/锁文件、已安装关键依赖、宿主适配及 Node 内容指纹，校验生成文件内容；不提前创建业务编辑会话。
- Vite 依赖缓存跨次复用，按版本独占写入；同时打开其他编辑器时使用其私有缓存。缓存不可用时退回原准备路径，等待占用最多 5 秒；清理遇忙跳过。
- 空闲缓存只保留最近两版、合计最多 512 MiB；活跃版本保留。缓存与业务工程、SQLite、素材分离；文件真实性、权限和 SHA 核验保持。

## 速度证据

同一机器、同一实际 SDK/Node 24、相同微型音频工程顺序测试，每组 3 次。导出程序已在后台准备后，服务就绪中位数 **1644 ms → 1139 ms，缩短 30.7%**。首次后台构建 1038 ms，再次校验复用 174 ms。

这是服务启动耗时，不是点击到整页可编辑的总耗时，也不代表大型工程。缓存前后入口脚本请求没有确认的独立改善；本轮主要收益来自跳过导出程序重复构建。真实 SDK 集成测试确认导出程序和 Vite `deps/_metadata.json` 的内容及 mtime 均跨次保持。

完整样本和验收摘要见 [results.json](results.json)。现有媒体复制测试仍核对真实内容相同才保留 mtime，不使用 size/mtime 猜测文件相同。

## 真实用户路径

使用独立 PostgreSQL、临时挂载卷、测试 Owner、真实浏览器/SDK/原生工程和本机交付 Worker；无正式数据、真实 Provider 或付费调用。

1. 分镜台选镜头 02，进入剪辑台；默认没有左栏，工具默认关闭。
2. 打开右侧画面工具，上传图片并采用到所选片段；打开声音工具，上传 12 秒本地 MP3 并采用为整期配乐。
3. 切换字幕工具、关闭重开、Esc 恢复焦点；iframe 保持同一节点。1440/390/320px 检查；320px 工具内容宽 210px、滚动宽 210px，无横向溢出。
4. 直接在真实时间线上点击、拆分、拖动（镜头 02 起点 90→121 帧）、删除、复制，并逐次撤销，恢复原来的两个片段。
5. 保存并返回分镜台，仍选镜头 02；修改提示词、切换镜头后仍保留；重新进入剪辑台，采用结果、原片段身份和所选镜头保持。
6. 保存前往交付、真实导出、确认成片与字幕、上传封面、填写文字、生成交付包，刷新后读取已完成结果。
7. 成片 H.264 1080×1920、AAC 音轨，6.058667 秒；播放器实际 readyState≥2，交付六项文件全部验证完成。

## 发现并修复

- 旧 `production-compact.css` 残留两列宽度会挤窄编辑器：删除旧导航及旧字幕栏规则。
- 320px 长配乐文件名撑宽工具区：限定内部网格可收缩，保留完整文件名并换行。
- Vite 内部退出先于外层异步清理，遗留缓存占用标记：通过 Vite `closeBundle` 等待幂等清理；真实 SDK 回归先失败、修复后通过。
- 旧雨伞测试脚本仍为模板 2：更新为当前模板 3。旧集成测试的导航点击改为等待原生写连接；模块图断言补齐既有音频采用模块。
- 验收环境中前端 build 会清空 dist，覆盖预备运行文件：最终按前端 build→runtime:prepare 的顺序，完整流程重新通过。未改产品业务逻辑处理这个测试顺序问题。
