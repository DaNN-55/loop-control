# 脚本保存与启动分步恢复验证

日期：2026-11-10。基线 HEAD：`951a368e`。用户批准第 4 项：明确脚本确认的保存成功、启动成功和失败恢复，保留草稿及现有业务规则；不提交、不推送。

## 改动

- `WorkspaceScriptPanel` 使用局部分步状态：保存中、保存未确认、启动中、核对中、已保存但启动未确认、已启动。状态与按钮分别表达保存和启动结果；只有启动成功，或读回证实同一脚本已进入制作，才确认草稿和进入后续准备。
- 已保存但启动失败时提供「继续启动」，先读取当前生产单。同一版本仍待输入时只重试 `start`，已启动则直接继续。版本变化、归档、完成、历史只读或读取失败时停止，保留正文和原因；恢复读取错误不会被父页面原启动错误遮住。
- 保存刷新父页面时固定本次草稿范围；工作区重读期间隐藏并禁用脚本面板，保留实例，其他区域沿用原加载规则。防止自身的版本更新清空正文、修订原因、文件名或分步状态。切换生产单、卸载后的迟到保存不再启动旧生产单。
- 保留修改后的再次修订、原因必填和二次确认。后续修改以最近已保存版本为预期版本；未知保存重试继续沿用原客户端幂等协议。启动回执若属于旧脚本，不能确认新版启动成功。

原命令、服务端 Owner／CSRF／行锁、运行中任务限制、文件校验、历史材料、下游失效和恢复限制保持。不引入依赖、SQL、通用状态机或新恢复存储。刷新后仍按原 Owner／episode／服务端版本隔离草稿；已保存的待输入脚本通过原确认入口继续，不自动启动，也不迁移旧版本草稿。
