# 永久删除自动清理空目录和标题链接

2026-10-27。按 Owner 要求修改永久删除功能，不直接删除现有生产单或历史资料。

## 最终行为

- 删除事务提交后，对每个已确认账号位置，只移除「按标题浏览」内精确指向该生产单 `episodes/<id>`、且目标已不存在的符号链接；支持相对和绝对目标，不按标题名称匹配，不跟随链接删除目标。
- 已登记旧副本仅剩该生产单标题链接时，也纳入删除计划和目录版本确认。未登记位置和其他失效链接保持。
- 非递归移除已经为空的「按标题浏览」、`.deletion-staging` 和 `episodes` 容器；容器仍有其他文件、链接或其他待删生产单时保留。账号根目录保留。
- 原生产单路径重新出现、导航目录被链接替换或链接位置发生变化时拒绝收尾，保留待清理回执。权限不足等错误也可从系统维护重试；暂存产物已移除后仍继续链接及空目录收尾。
- 事务回滚恢复生产单目录，标题链接仍保留。原始素材库、历史资料、其他生产单、无关链接和旧回执未确认的外部副本不动。

## 验证

新增文件系统回归先运行得到 4 失败/1 通过，证实旧实现残留标题链接、空容器且不重试标题清理；修复后通过。仅剩标题链接的旧副本发现回归也先失败再通过。

最终 11 项测试全部通过：9 项真实临时文件系统测试及 2 项一次性 PostgreSQL 数据库/真实 Owner HTTP 验收。覆盖双副本、标题链接、数据库回滚、权限故障和重试、旧回执范围、Owner/CSRF/归档/运行任务/资产锁/并发保护、其他生产单、素材和合成历史文件保留。见 tests.log。所有测试删除仅使用临时目录和一次性数据库。

`npm run check`、本地后端编译通过；正常 stop/start 完成运行时代码准备和重新编译。真实服务重载前运行任务为 0，重载后首页返回 200，编译产物包含自动收尾逻辑；现有账号和生产单 ID、历史来源/版本/文件关联数量前后一致。见 runtime-before.json、runtime-after.json。

本轮未调用现存生产单删除接口，未写历史资料，未执行数据库迁移，没有提交或推送。未修改 UI，未进行真实永久删除的浏览器验收；删除行为由隔离 HTTP 验收验证。
