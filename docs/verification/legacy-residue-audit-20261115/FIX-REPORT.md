## 修复结果

1. **关闭旧执行入口。** 30 个残留手工命令在认证、CSRF 和 Owner 归属检查后统一返回 410，不重放原执行回执、不读写旧草稿或唤醒 Worker。删除旧 WAN／Studio／交付的三个专属 TypeScript 模块。旧远端审核修订、冻结和最终渲染重试也在任何网络 I/O 前明确拒绝。
2. **关闭假排队。** `planMedia` 随旧命令退役，不再返回没有实际任务的 `queued: true`。
3. **目录与连接并行读取。** 连接慢或失败时目录先显示，错误单独提示并只重试连接；保留迟到结果、退出和 Owner 切换栅栏。补齐登录过程中连接 401 的竞态，失效会话不会被迟到目录改回 ready，登录按钮仍可用。

新增 `201-close-retired-manual-execution.sql`，对 41 个旧专属 SQL 写入口撤销普通应用、Owner、Worker、匿名和 PUBLIC 的执行权限。保留内部函数体及历史数据，不改已采用迁移、累计 clean-v3 或原 ledger。类型由应用 201 后的真实 PostgreSQL 目录重新生成，关闭的合同不再出现在当前可调用类型中。

Worker 从真实工作区请求、制作基准和镜头关系识别当前任务。候选选择、最后领取、CLI、凭据读取及视频费用预留均有来源／租约门槛，公共领取不能绕过；原在途任务在租约窗口内继续计入容量。没有按 `generate_a_roll`／`generate_b_roll` 等共用名称删除当前媒体能力。执行协议升为 `production-workspace/v3`，旧 v5/v2 包经完整性核验后明确退役，原包不改写。

历史工程查看、下载、显式接入、原生编辑、准确的既有租约终态结果及输出核对保持。既有命令回执仍可只读查询；拒绝旧执行不删除历史外发、任务、草稿、文件或审批。

## 审查闭环

独立 `code-reviewer` 只读复核后端／SQL／远端入口、前端会话和最终测试合同。发现并关闭：三个遗漏 SQL 入口（旧最终重试、旧阶段审批、旧发布完成）、旧远端写 helper、TypeScript 未使用导入，以及测试标题误称真实历史身份。主审另补登录 401 竞态及失败回归。最终无开放的行为 P1/P2；改动范围内 `git diff --check` 通过。

历史 184→185 专项测试继续保留原权限及 `0A000` 断言；201 不进入那些旧库，不能用当前撤权预期改写历史验收。两项当前口播／字幕的 Docker 专用旧迁移测试本轮未完整执行，其拒绝记录保留，201 的原生非空升级与完整恢复由独立测试覆盖。

首轮浏览器失败来自测试服务器在 finally 重复结束已完成响应；修正夹具后实际宽窄页面、恢复和刷新通过。部分早轮集成因未先准备 v3 包、缺少调度配置或历史夹具仍调用已撤销入口失败，均分别定位并保留结果，没有放宽产品保护。默认 jsdom 媒体方法、React act 和 pg 并发查询的既有警告未被掩盖。
