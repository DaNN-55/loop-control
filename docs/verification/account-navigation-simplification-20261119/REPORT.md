## 验收发现与修复

1. 预览异步请求曾把上一张生产单的“已有脚本”状态带入下一张：按生产单 ID 隔离结果，回归先失败后通过。
2. 从维护队列进入生产单后焦点留在背景：详情解除 `inert` 后把初始焦点交给详情，并保留详情内已有焦点。
3. `canInitialize` 实际表示空工作区允许初始化，并非是否已经绑定：读取增加明确的 `initialized` 事实；已绑定位置的更换继续走迁移流程。两个场景均有回归。
4. 创建账号后目录慢回读，紧接着新建生产单可能拿到空账号：立即合入真实创建回执；用挂起后续目录读取的用例验证。
5. 原生预览关闭时，在弹窗仍打开、背景不可交互时调用 focus 会被浏览器拒绝：先卸载弹窗，再恢复到选中行。单测模拟背景不可聚焦，最终真实浏览器复验通过。
6. 正式入口的 React StrictMode 会先清理再重建 effect，旧的原生 close 事件可能在重开后到达：仅响应当前确实关闭的 dialog，忽略旧事件。补上 StrictMode 和原生异步事件回归，先失败再通过；浏览器入口同步补齐正式入口的 StrictMode 及样式。

## 验证环境及失败轮次

浏览器使用独立 PostgreSQL、一次性媒体根、SDK 源码副本和专用浏览器会话；有明确身份检查及 finally 清理，不读取日常 deployment 或 Keychain 秘密，不调用付费生成接口。临时证据保存在本工作树忽略的 `.scratch/account-navigation-verification/runs/`。

早期 worktree 缺显式 vitest/typescript 入口，补共享依赖 symlink 并保留私有缓存，未改依赖清单。旧 UI 合同测试已随确认的入口和文案更新，未删除有效保护或降低检查门槛。一轮全量与构建并发，构建清空 dist 导致运行时导入失败；最终改为构建、runtime 准备、全量严格串行。
