## 当前有效结构

从原生 PostgreSQL 17.11 只读导出 schema，当前有 121 张表、162 条本地迁移 ledger。实际 schema 为 `extensions`、`local_identity`、`loop_internal`、`public`；没有 `supabase_migrations`。

实际有效定义中仍有 17 个函数、1 个连接约束包含旧供应商名称。`legacy-object-inventory.json` 记录函数签名、文本检出的代码引用、SQL 函数引用与触发器引用。文本引用只用于发现依赖，不能证明动态 SQL 可达性或证明无调用。

其中 `local_identity.generate_input_shot_tts` 仍被当前语音代码引用，`local_identity.input_task_connection` 仍被旁白 Worker 和 Worker 数据库边界引用。另有蓝图保护和任务运行约束触发器。因此下一步需要重写有效分支及保护逻辑，不能将这些函数直接整批删除。

## 隔离恢复预演

使用已存在的固定 PostgreSQL 17.6 镜像，在 Colima VM 内建立专属容器：无网络、无主机端口、无主机目录或数据卷挂载，仅使用容器临时文件系统。没有启动冻结的旧日常容器，没有复制日常登录密码或 Keychain 秘密。

候选 SQL 仅是未修改的有效结构汇总，仍含旧供应商分支，保留在私有目录，不放入正式基线目录、不启用。尚未覆盖业务数据升级、序列状态、角色成员关系及全部函数执行授权对账、旧业务导出恢复、应用主流程或失败恢复。这些仍属于下一轮正式 C 阶段验收。

## 已批准的 Google TTS 元数据清理

用户查看记录后明确授权「清理吧」。清理对象为名为 `google_tts` 的旧连接、第 1 版及其 `qualified=false` 的资格记录；连接创建于 2026-08-26，版本已于 2026-10-27 撤销。没有当前任务、蓝图、生产单、工作区、密钥绑定、用量/模型设置或验证记录引用它。

在日常原生数据库的单个串行化事务中锁定目标并重新检查条件，删除 1 条资格记录和 1 条连接；外键级联删除其唯一版本。没有禁用触发器、改写 schema 或操作 Keychain。

- 实际仅 3 行元数据被删除；其余 118 张表指纹一致。
- 这 3 张表的其他记录也经「现存行 + 私有恢复快照」补回计算，与删除前完整表指纹一致。
- 精确恢复快照仅保存在权限受限的私有目录，不把历史秘密引用写入 Git。初始 JS Date 序列化截断了微秒，已使用删除前 JSON 观测和既有迁移恢复包补齐完整时间精度，再完成原表指纹验证。恢复材料最终与删除前内容相符。
- 在隔离库实际恢复 3 行元数据，逐字段比较一致并回滚；没有把测试数据写回日常库。
- 当前 8 类供应商的其他连接保留，Google TTS 连接/版本/资格记录均为 0。
- 日常 App 清理前后 PID 均为 `64406`，根页面 HTTP 200；没有重启服务。部署配置及三份并行 CSS 指纹保持。
- 没有删除音频、成品、历史 SQL、旧回退库、密钥或其他历史资料。
