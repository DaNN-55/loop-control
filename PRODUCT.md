# Product

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
React 19 + TypeScript + Vite native local entry, existing accessible React Aria controls and real local API/command adapters. Styling is owned by src/ui/impeccable; the standalone approved prototype is visual evidence, not a runtime data source.

## Users
A single Owner operating multiple short-video content accounts on a PC. The current artifact is the real local operating application.

## Product Purpose
Coordinate versioned account rules, series, episode production, assets, human review, editing, QC, and verified delivery packages in one traceable workflow.

## Positioning
An episode freezes account and series rules; automated production and explicit human approvals advance it toward a verified delivery package. The product does not claim to generate the main script or publish externally.

## Operating Context
A desktop content-production workspace. The Owner moves between many episodes, responds to blockers, reviews creative work, configures production capabilities, and manages local resources.

## Capabilities and Constraints
Preserve current active product capabilities and terminology; navigation, hierarchy, layout and interaction design may be replaced. Include accounts and versioned blueprints, series, episode creation and lifecycle, main-script upload/confirmation, preflight and configuration repair, visual/storyboard review, shot preparation, narration/captions/composition, editing, QC, package delivery, connections, secrets, historical material and sources, recovery, local health, authentication and security.
Use existing real application APIs and data logic. Preserve Owner authentication and CSRF, request-generation guards, registered adapters/models, frozen configuration and review revision, business approvals, generation authorization and historical read-only behavior. Third-party OpenChatCut remains the actual editing engine. Retired interfaces are excluded. UI verification must use isolated synthetic fixtures for write operations, credentials, Provider generation and Studio workspace commands.
Every dropdown, form, action, overlay, feedback and significant state is design scope. Project-owned OpenChatCut entry, replacement conflicts and revision flows are included; its independent engine is preserved. The user delegated the visual direction and authorized implementation of every page, dropdown, form and control.

## Brand Commitments
Keep the product name Loop Control and Chinese interface copy. No inherited Dan UI, Untitled UI, purple palette, component, layout or multi-skill design constraint. Impeccable alone provides the design process.

## Evidence on Hand
Read-only current source: README.md, CONTEXT.md, src/local-app/main.tsx, src/local-app/LocalCatalogApp.tsx, src/workspace/WorkspaceViews.tsx, src/accounts/AccountWorkspace.tsx, src/episodes/EpisodeProduction.tsx, src/local-app/LocalDeliveryPanel.tsx, src/operations/OperationsWorkspace.tsx, src/local-app/LocalHistory.tsx, src/local-app/HistorySources.tsx and src/local-app/LocalSecretAdministration.tsx. These establish capabilities, never visual authority for this redesign.

## Product Principles
- Make the next useful action visible without forcing context loss.
- Connect list, detail, configuration, review and delivery through real entities while preserving return context.
- Prefer concise task vocabulary, coherent alignment and necessary inline feedback.
- Every primary affordance must retain its actual handler, authority and error semantics.
- Keep drafts, confirmation boundaries, precise counts, independent pagination and recoverable failures.

## Accessibility & Inclusion
Named semantic controls, keyboard navigation, visible focus, readable contrast, accessible overlays and tooltips, reduced motion. PC-first, with a usable constrained-width browser view.
